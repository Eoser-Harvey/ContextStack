## 一、硬件与算力（课程没讲透，面试必问"为什么这么选硬件"）

### Q1：你的项目用了 STM32N647，它有 Neural-ART NPU（600 GOPS），但你说最终用 CPU 跑——为什么花大价钱买 NPU 却不用？

**答**：
> 我的模型是 2403 参数的 MLP，MAC 总量极小。NPU 的并行优势要在大矩阵乘加上才体现，而小模型上 NPU 的**启动开销（DMA 搬运权重/激活到 NPU 内存、状态切换）可能比计算本身还大**，用 NPU 反而更慢。我实测单帧推理 CPU 的 Helium 已满足 40Hz 实时性（<5ms），所以最终走 CPU。这是基于数据的架构决策——**小模型 CPU 更快，大模型（>10 万参数、大量卷积）才是 NPU 主场**。选 STM32N647 而不是普通 M4，是因为它给未来上更大模型（如视觉/KWS）留了 NPU 余量。

### Q2：Cortex-M55 的 Helium 是什么？它和你熟悉的 M4 有什么区别？

**答**：
> Helium 是 Armv8.1-M 的 **SIMD 矢量扩展**（MVE），M4 的 DSP 指令一次算 2 个 16bit 数据，Helium 一次算 8 个 8bit 或 4 个 16bit 数据，对 INT8 推理是量级的提升。Cortex-M55 是第一个带 Helium 的 M 核。我的 INT8 模型在 M55 上比 M4 快数倍，就是因为 Helium 能用一条指令做多个乘加。

### Q3：CMSIS-NN 是什么？你项目里用了吗？为什么 2403 参数的小模型，CMSIS-NN 收益不明显？

**答**：
> CMSIS-NN 是 ARM 为 Cortex-M 定制的**神经网络内核加速库**（注意拼写是 `CMSIS-NN`，不是 CMNN）。它和 TFLM 是分层关系：**TFLM 是引擎（调度/内存/算子注册），CMSIS-NN 是内核（单个算子的 SIMD 优化实现）**。TFLM 编译时检测到 Cortex-M + CMSIS-NN，就把 FC/Conv 算子的实现替换成 CMSIS-NN 的优化版。
> 我的模型只有 FC + Softmax，CMSIS-NN 主要加速 FC 的矩阵乘加。但 2403 参数太小，SIMD 优化有启动开销（数据重排），省的几个周期被抵消，所以小模型上加速比不明显——**CMSIS-NN 的主场是大量卷积的大模型**。

## 二、量化深度（课程只讲了 scale/zero_point，面试会追问细节）

### Q4：你项目量化参数 input_zero_point=-13、output_zero_point=-128，为什么不是 0？这说明你用的是哪种量化？

**答**：
> zero_point 不为 0，说明我用的是**非对称量化**（对称量化 zero_point 恒为 0）。为什么激活用非对称：我的激活函数是 ReLU，输出全是 ≥0 的。如果硬用对称量化（zero_point=0），INT8 的负半段 [-128,-1] 就浪费了。非对称量化把浮点 0 映射到 -13，让 [-128,127] 整个范围都用来表示非负激活，精度更高。
> 口诀：**权重对称（分布对称、省计算），激活非对称（ReLU 后非负、充分利用范围）**。

### Q5：你的量化损失只有 0.27 个百分点，这么低的损失靠什么？per-channel 量化起了什么作用？

**答**：
> 关键靠 **per-channel 量化**。per-tensor 是整个张量共用一个 scale，但我三个 FC 层里不同输出神经元的权重分布差异很大——范围小的通道精度浪费、范围大的溢出。per-channel 让**每个输出通道单独一个 scale**，各自用最合适的范围，量化误差显著降低。
> TFLite 转换时权重默认 per-channel、激活默认 per-tensor。我 2403 参数的小模型，权重 per-channel 后损失只有 0.27 个百分点。如果强制 per-tensor，小模型误差会被放大到 2-5%。
> 为什么激活不 per-channel：激活是运行时动态值，per-channel 会让推理多一次逐通道反量化，开销大；权重是静态的，per-channel 的 scale 转换时就固化好了，推理零额外开销。

### Q6：你用的是 PTQ 还是 QAT？为什么？如果 PTQ 掉点超过 2% 你会怎么做？

**答**：
> 我用 **PTQ（后训练量化）**——训练完直接用校准集统计激活范围，一次转换完成，不用改训练代码。因为我的 PTQ 掉点只有 0.27%，远低于阈值，没必要上 QAT。策略是先 PTQ 快速验证，掉点 <2% 直接用；掉点 >2% 才升级 QAT（训练中模拟量化误差）。
> 如果掉点超过 2%，我按 5 步排查：①查校准集是否覆盖全部工况 ②查前后处理一致性（归一化参数）③PTQ→QAT ④混合精度（敏感层留 FP16）⑤调整模型结构。

## 三、模型选型（课程讲了，但面试会问"为什么"）

### Q7：你的动作识别为什么用 MLP，不用 CNN 或 LSTM？这是面试官最常问的题

**答**：
> 四个理由：
> ①**特征已经手工提取成 56 维向量**——MLP 直接读向量最自然；CNN 要吃原始波形才能发挥卷积核优势，LSTM 要长序列。
> ②**参数最少**——2403 参数；1D-CNN 起步 2-5 万，LSTM 还要存隐藏状态。MCU 上参数少 = Flash 省。
> ③**TFLM 算子极简**——只注册 FullyConnected + Softmax 两种，部署零摩擦；CNN/LSTM 算子多且 TFLM 支持受限。
> ④**数据量约束**——我只有几百个窗口，CNN/LSTM 极易过拟合。
> 核心是**手工特征 + 小模型**在数据量小、资源受限时的最优组合，这是"基于数据规模的架构决策"。

### Q8：为什么隐藏层是 56→32→16 递减结构，不是递增或等宽？

**答**：
> 递减是"信息瓶颈"设计——逐层压缩特征维度，强迫网络学习最本质的判别特征，同时控制参数量。32 和 16 是实验平衡精度和体量的结果。等宽或递增会导致参数量膨胀，对我 2403 参数的目标不友好。

### Q9：2403 参数具体怎么算的？为什么你简历上能精确到个位数？

**答**：
> 全连接层参数量 = 输入×输出 + 输出（权重+偏置）。三层加起来：
> 第一层 56×32+32 = 1824，第二层 32×16+16 = 528，第三层 16×3+3 = 51，合计 **2403**。能精确到个位数是因为 MLP 的参数量是确定性的算术，这本身就说明我对模型结构门清——面试官一听就知道不是背的。

## 四、数据与训练（课程讲了，但面试会挖"为什么这么做"）

### Q10：你采样率为什么是 40Hz，不是 100Hz 或更高？

**答**：
> 人体动作频率集中在 0.5-5Hz，奈奎斯特定理要求采样率 >2 倍，40Hz 覆盖到 20Hz 足够。更高采样率对 MCU 负载和功耗不友好，且不提升分类性能。40Hz 对应 25ms 固定调度，固件实现最方便。

### Q11：你训练集为什么用时间块隔离，不用随机划分？2× 硬样本权重又是什么？

**答**：
> **时间块隔离**：随机划分会让同一次采集的相邻窗口（只差 0.4s、几乎一样）分跨训练/测试集，等于开卷考试，评估虚高。我按时间顺序切 60/20/20 + 64 样本隔离带，用过去的数据训、预测未来的数据，才接近真实部署。
> **2× 硬样本权重**：Walk 尾段（紧挨上楼梯的那段）最易误判为 Stairs，我给这段 2× 损失权重强迫模型重点学。消融实验：1×→Walk 86%，2×→93.22%（甜点），4×→89%（过拟合）。这个 2× 是实验调出来的，不是拍脑袋。

## 五、部署与内存（课程讲了概念，面试会问分配细节）

### Q12：你的 tensor_arena 为什么不用 malloc？arena 大小怎么定的？

**答**：
> MCU 无 MMU，malloc 会导致**内存碎片**，长时间运行后分配失败崩溃；且 malloc 执行时间不可预测，违背实时性。tensor_arena 是一块静态数组，启动期一次性分配，推理全程零动态分配。
> arena 大小用 `RecordingMicroInterpreter` 精确测定：MicroAllocator 用**头尾对半分配**——头存长期张量（输入/输出/权重），尾存临时中间激活，复用"用完就丢"的中间结果。所以 arena = **同时存活的最大张量之和**（我的模型是第一层 56→32 的输入+输出，几 KB 就够），不是所有层张量之和。

### Q13：你的 OpResolver 写 `MicroMutableOpResolver<2>`，这个 2 是什么意思？为什么不是模型的 3 层？

**答**：
> 2 是**算子类型数**，不是层数。我的模型虽然 3 层，但只用了 FullyConnected + Softmax 两种算子类型，所以 <2> 就够。ReLU 融合在 FC 里不用单独注册。这是新手高频踩坑：<N> 填的是"算子类型去重后的数量"，模型有 100 层但只 3 种算子，<3> 就够。

## 六、工程化（你的差异化王牌，面试必须主动讲）

### Q14：你部署阶段最难查的 bug 是什么？

**答**：
> 一个 9.807 倍的传感器单位矛盾。源码注释说输出 m/s²，但实际训练数据是 g（静止时 acc_norm≈1.0 而非 9.807）。根因是固件版本漂移——采集时烧的是老固件，源码后来加了 ×9.807 但没重新采集。如果不发现，部署后所有输入大 9.807 倍，模型全乱，且两端代码各自都"对"，没法从代码查。我用物理常识（静止=1g）审计数据定位，然后写进部署契约 JSON + 上电自检（DAY16_SAMP 静止显示 1000 对、9807 错），让这类问题制度化杜绝。

### Q15：你怎么保证 Python 训练端和 C 部署端的一致性？

**答**：
> 三层机制：①**部署契约 JSON**——采样率/传感器单位/特征顺序/INT8 参数/输出策略全部写死，任何一方改 SHA256 就变，契约作废；②**Parity 自检**——上电用 3 组固定数据验证 C 端和 Python 端逐点一致；③**OOD 检测 + 两窗 EMA**——clip>10 判分布外，连续两窗稳定才切换标签，防抖动。
