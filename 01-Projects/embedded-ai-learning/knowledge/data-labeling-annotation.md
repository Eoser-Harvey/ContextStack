# 数据标注到底怎么做？（结合 Day16 动作识别项目）

> 触发原因：2026-09-02 千寻面试被问「数据如何标注的」答得模糊，复盘后补这个知识点。
> 结论先行：**你其实一直在做标注，只是没意识到「按文件夹分类」就是标注的一种。**

---

## 一、标注的本质

一句话：**给数据打上「标准答案」标签，让模型学会「看到 X → 输出 Y」**。

监督学习的前提是「有答案」。标注，就是人工把「正确答案」写进数据。没有标注，模型不知道「这段传感器数据对应的是走路还是上楼梯」，也就无从学习。

---

## 二、标注方式按任务类型分（建立全景）

| 任务类型          | 标注方式         | 工具                     | 你的项目 |
|:------------------|:-----------------|:-------------------------|:---------|
| 图像分类          | 按文件夹分类     | 手动分文件夹             | —        |
| 目标检测          | 画包围框         | LabelImg / CVAT          | —        |
| 语义分割          | 逐像素涂色       | Labelme / Label Studio   | —        |
| 语音/文本         | 逐段转写         | 专用工具                 | —        |
| **时序/传感器动作** | **录制时打标** | 手动 + 时间戳            | ✅ Day16 |

关键认知：**标注不是只有「画框」一种**。对传感器时序数据，最自然的标注方式是「录制时打标」——采集者边做动作边记录「现在做的是什么」，标签跟着数据一起录下来。

### 标注的 4 种方式（浓缩版）

| 方式 | 任务类型 | 具体动作 | 你的项目 |
|:-----|:---------|:---------|:---------|
| 按文件夹分类 | 图像/传感器分类 | 把同类数据放同一文件夹，文件夹名=标签 | ✅ Day16 |
| 画包围框 bbox | 目标检测 | 框出目标位置 | — |
| 逐像素涂色 | 语义分割 | 给每个像素标类别 | — |
| 录制时打标 | 时序/传感器 | 采集时指定动作，标签随数据录下 | ✅ Day16 |

## 二·五、标注的通用流程（5 步）

任何标注任务，都逃不出这 5 步：

| 步骤 | 做什么 | 你 Day16 的对应 |
|:-----|:-------|:----------------|
| 1. 定义任务 | 明确模型输出什么 | 三分类：idle / walk / stairs |
| 2. 设计标签体系 | 定有哪些类别、怎么编码 | `CLASS_NAMES` + `CLASS_TO_ID`（0/1/2）|
| 3. 采集 + 标注 | 给每条数据打标签 | 录制时指定动作 + 按文件夹存 + 写 label 列 |
| 4. 质量校验 | 检查标签对不对 | `load_clean_csv` 校验 label 列 + 数据审计 |
| 5. 格式导出 | 转成训练能读的格式 | clean CSV（含 label_id/label 列）|

**核心在 3、4 两步**——面试官问「标注怎么做的」，考的就是「标签怎么来（步3）+ 标签错了怎么办（步4）」。

## 三、你 Day16 项目实际怎么标注的（三步，源码核实）

### 第 1 步：录制时打标（文件夹分类 + 数据内嵌标签列）

采集时人工指定当前动作类型，数据按动作分到三个文件夹，**文件夹名 = 标签**：

| 文件夹 | 标签   | 连续录制行数 |
|:-------|:-------|:-------------|
| `idle/`  | 静止   | 8388         |
| `walk/`  | 走路   | 11307        |
| `stairs/`| 上楼梯 | 11430        |

**⭐ 关键：标签的物理存在形式（这是「没理解」的根子，源码铁证）**

标签**不只藏在文件夹名里，还直接嵌在 CSV 每一行里**。`pipeline_common.py` 定义的 clean CSV 列：

```python
CLASS_NAMES = ("idle", "walk", "stairs")          # 类别名
CLASS_TO_ID = {"idle": 0, "walk": 1, "stairs": 2} # 类别 → 数字 ID

CLEAN_COLUMNS = (
    "t_ms",        # 时间戳
    "label_id",    # 标签数字 ID（0/1/2）
    "label",       # 标签名字（"idle"/"walk"/"stairs"）
    ...            # 后面才是加速度/陀螺仪原始数据
)
```

也就是说：**采集设备录数据时，每一行传感器数据都自动带上了 `label` 和 `label_id` 两列**。这就是标注的「物理落地」——标注不是训练时做的，是采集时写进数据里的。

**代码「校验」证明标注是事前做好的**（`load_clean_csv`，`pipeline_common.py:191-196`）：

```python
if set(frame["label"].astype(str).str.lower().unique()) != {expected_class}:
    raise ValueError(f"{path} contains labels other than {expected_class}")
if set(frame["label_id"].astype(int).unique()) != {CLASS_TO_ID[expected_class]}:
    raise ValueError(f"{path} has an unexpected label_id")
```

翻译：如果 `walk` 文件夹里的 CSV，`label` 列出现了不是 "walk" 的值，**代码直接报错**。这证明标注早已完成，代码只是「读标签 + 验标签」，不做标注本身。

### 第 2 步：事后校正（时间戳重标）

数据审计时发现 `stairs` 记录的**尾部其实是走路**（采集者录楼梯录到最后，其实已经走起来了）。于是按时间戳切分重标：

```text
t_ms < 290768              → 保留为 stairs
290768 <= t_ms < 297168    → 动作切换区，直接删除
t_ms >= 297168             → 重新标记为 walk（只进训练集）
```

### 第 3 步：剔除过渡区

动作切换的中间段（290768~297168ms，约 6.4 秒）既不是纯 stairs 也不是纯 walk，**直接删除**，保证进入训练的每个窗口标签干净。

> 这就是「**文件夹级标注 + 时间戳事后校正**」，时序动作识别最朴素、也最常见的做法。

## 四、面试话术（千寻问倒你的点，现在能答了）

> 「我的动作识别数据标注用的是『录制时打标』：采集时人工指定当前动作类型，数据按动作分文件夹保存，文件夹名就是标签。采完做数据审计时，发现上楼梯记录的尾部其实已经是走路了，就按时间戳把尾部那段重新标记成 walk，把动作切换的过渡段直接剔除。这样保证进入训练的每个窗口，标签都是干净的。后来我又做了重训练，验证标签修正对精度的影响。」

## 五、为什么面试会问这个（你的盲区）

| 层面 | 你的盲区 | 现在补上 |
|:-----|:---------|:---------|
| 认知 | 以为「标注」只有画框，没意识到「按文件夹分类」也是标注 | 标注 = 打标签，方式按任务类型分 |
| 价值 | 没意识到「事后重标 + 剔除过渡段」这一步的含金量 | 这正是「真做过」的人才会讲的点 |
