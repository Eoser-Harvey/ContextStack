## 一、一句话说清本质

> **模型 = 数据假设 + 数字运算 + 反复对答案**

1. 你有一个问题（比如"照片里是猫还是狗"）
2. 你假设数学公式能描述这个问题（网络结构 = 公式模板）
3. 你给公式看大量例子（训练数据）
4. 公式错了你就调它的参数（反向传播 + 梯度下降）
5. 调到它基本不错了 → 模型训练完成
6. 你把公式刻进芯片（部署）→ 每次给它新照片，它输出答案（推理）

### 阶段①：定义问题 — "我要解决什么"

| 问题类型 | 任务 | 例子 | 输出形式 |
|---------|------|------|---------|
| 分类 | 这张照片是什么？ | 猫/狗/车 | 概率分布 `[0.8, 0.15, 0.05]` |
| 检测 | 照片里有什么、在哪？ | 人脸 + 位置框 | 类别 + 坐标 |
| 回归 | 这个值是多少？ | 温度 23.5°C | 连续数值 |
| 分割 | 照片每个像素是什么？ | 路/车/行人/天空 | 逐像素标签 |

**你的嵌入式场景**：异常检测（分类）、故障类型（多分类）、剩余寿命预测（回归）。

### 阶段②：数据准备 — "模型靠什么学"

```
原始数据            清洗后            模型吃进去
 传感器读数    →    去掉空值异常值   →   归一化到 [0,1] 或 [-1,1]
 图片         →    统一尺寸           →   (224, 224, 3) 的张量
 音频         →    MFCC 特征提取      →   频谱特征矩阵

划分：
  训练集 70%  → 模型学习用
  验证集 15%  → 训练时检验用（每轮训练后测一下）
  测试集 15%  → 最终最终评分用（一把梭哈，只用一次）
```

**关键经验**：测试集绝对不能碰，碰了就作弊。训练时验证集可以反复用，测试集是最后一把梭。

### 阶段④：训练 — "怎么学会"

这就是你刚学的损失函数发挥作用的阶段。

```python
# 训练循环的本质（伪代码）
for epoch in range(100):                    # 把数据集看 100 遍
    for batch in dataloader:                 # 每次吃一小口
        predictions = model(batch_images)    # ① 前向传播：猜答案
        loss = loss_fn(predictions, labels)  # ② 计算损失：猜得有多离谱 ← 损失函数
        loss.backward()                      # ③ 反向传播：算每个权重的梯度
        optimizer.step()                     # ④ 更新权重：朝"损失变小"的方向调
```

| 概念 | 一句话 | 你的知识库位置 |
|------|--------|:---:|
| **损失函数** | 量"猜得有多离谱"的尺子 | [[loss-function-embedded-ai]] |
| **优化器（Adam/SGD）** | 决定"往哪个方向调、迈多大步" | 训练代码里 `optimizer='adam'` |
| **学习率** | 每一步调整大小的步长 | 太大乱跳，太小太慢 |
| **Epoch** | 把全部数据完整看一遍算一轮 | 通常几十到几百轮 |
| **Batch** | 一次吃几口（一次算几个样本） | 太大显存放不下，太小训练不稳定 |

### 阶段⑤：评估 — "学会了没有"

```
训练完后，用测试集打分：

分类任务 → 准确率（Accuracy）= 答对了多少 / 总题数
检测任务 → mAP（平均精度）            = 找对了 + 找对了位置
回归任务 → MSE/MAE（平均误差）        = 偏差多少
```

> ⚠️ 高准确率 ≠ 可以部署。训练的时候可能作弊（过拟合）。

### 阶段⑥：验证 — "真实环境能跑吗"

这就涉及到你读的论文里的概念。

```
过拟合检查：
  训练准确率 98% vs 测试准确率 85% → 过拟合了！模型背答案了

部署可行性检查：
  模型 50MB → 嵌入式 Flash 只有 2MB → 需要压缩
  推理 500ms → 嵌入式要求 50ms    → 需要加速
  推理用 100MB RAM → MCU 只有 256KB → 必须优化
```

### 阶段⑦：优化压缩 — "怎么塞进芯片"

**这就是你的知识库最厚的一章**：[[model-optimization-techniques]] + [[paper-edge-ai-survey-2025]]

```
三级压缩依次递进：

第一级（无损或低损）
├── 深度可分离卷积：把普通卷积拆成空间+通道 → 参数减 7-8×
├── INT8 量化：FP32 转 INT8 → 模型减 4×，精度损 < 3%
└── 常量折叠：编译期预计算 → 无精度损失

第二级（可控损失）
├── 结构化剪枝：剪掉不重要通道 → 参数减 30-50%，精度损 < 2%
├── QAT 量化：训练时就模拟量化 → 精度损 < 1%
└── 知识蒸馏：大模型教小模型 → 小模型精度接近大模型

第三级（极致压缩）
├── 子 4-bit 量化（4/3/2-bit）：精度损失需特训
└── 二值化/三值化：乘变 XNOR → 精度损失大
```

**对应你的 3 个月精通计划**：Month 1 Week 4 就是这个。

### 阶段⑧：部署推理 — "芯片怎么用模型"

**这就是你的 TFLM 学习的终极目标。**

```
PC 上训练的模型（.h5 / .pth）
        ↓ 转换
    .tflite 文件（FlatBuffer 格式）
        ↓ 转成 C 数组
    model.cc（unsigned char 数组）
        ↓ 交叉编译
    烧录进 MCU 固件
        ↓ 上电运行
    传感器读取 → 预处理 → 推理 → 输出结果
```

**TFLM 推理 6 步（你的 Week 1 Day 1）**：

```
1. 注册算子    → 告诉 TFLM 你需要哪些运算
2. 创建解释器   → 初始化推理引擎
3. 分配 Arena   → 预分配一段连续内存
4. 设置输入    → 把传感器数据填进去
5. Invoke()    → 执行推理（这一步就是"跑模型"）
6. 读取输出    → 拿到分类结果/数值
```

## 三、嵌入式 AI vs 普通 AI 的关键差异

| 维度 | 普通 AI（PC/Cloud） | 嵌入式 AI（MCU） |
|------|-------------------|:---:|
| **训练** | 在 GPU 集群上训练 | PC/Cloud 训练好后**一次性部署** |
| **推理** | 可以随时换模型 | 模型**刻死**在 Flash 里 |
| **内存** | GB 级 | **KB 级**（ESP32 520KB, STM32 96KB） |
| **精度** | FP32 浮点 | **INT8 整数**（没有 FPU 或太慢） |
| **功耗** | 几百瓦 | **毫瓦级**（纽扣电池跑几个月） |
| **延迟** | 可接受几百 ms | 必须 **< 50ms**（实时系统） |
| **online 学习** | 可以持续更新 | **没有**（FLASH 写寿命 + RAM 不够） |
