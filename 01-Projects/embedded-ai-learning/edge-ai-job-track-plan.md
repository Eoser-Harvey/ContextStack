## 一、定位：投什么岗（吃王牌，避短板）

**目标岗**：端侧推理部署 / 推理性能优化工程师

| ✅ 投（吃你的王牌） | ❌ 避（你的短板，会露馅） |
|:--|:--|
| 端侧推理**部署**（TFLM / CMSIS-NN / C） | AI 算法 / 模型设计 |
| 推理**性能优化**（量化 / 汇编 / 硬件加速器，吃 DSP 功底） | 模型训练 / 数据标注 |
| **端侧 AI 固件**（RTOS + 推理，吃 RTOS 王牌） | 大模型 / Transformer 部署 |
| 工业时序 AI（预测性维护 / 异常检测，吃电力背景） | 纯视觉 / 纯语音（和你背景无关） |

**为什么这条线成立**：端侧推理优化的本质是「在 MCU/DSP 上把推理跑快跑省」——这正是你 DSP 汇编优化、硬件加速器、Cache 优化、内存敏感的看家本领。**你的 DSP 王牌不是端侧 AI 的门外汉，是端侧推理优化的核心竞争力。**

**薪资**：端侧推理优化岗（芯片/AI 公司）能到 50-80W，比电力电子/军工高——所以这条线**既是心仪线，又能冲 60-65K**，是「心仪 + 高薪」的最优结合。

## 三、demo 选型：工业时序异常检测（1D CNN）—— 直接衔接你的 DSP 王牌

**不选 MNIST**（太基础、和背景无关）、**不选 KWS**（语音、和背景无关），**选工业时序异常检测（1D CNN）**，理由：

1. **衔接你的王牌**：你在电能质量分析仪里做过电流/电压时序信号的 FFT 谐波分析（传统 DSP）。现在用 1D CNN 做同类时序信号的异常检测——是「DSP 信号处理 → 端侧 AI」的自然延伸，不是从零跨界。
2. **差异化赛道**：评估报告 8.7 明确说「电力故障、设备异常检测等时序工业场景，是你的差异化赛道，入门更快、简历含金量更高」。面试官听到「电力 + 端侧 AI」会眼前一亮，而不是又一个 MNIST。
3. **1D CNN 是 MCU 最优解**：推理快（Cortex-M4 上 2-5ms）、NPU 可加速、int8 量化损失 <1%，豆包和评估报告都强调「工业时序 1D CNN 全搞定，别碰 LSTM/Transformer」。

**demo 一句话**：采集设备振动/电流时序信号 → 1D CNN 异常检测模型（INT8 量化）→ TFLM 部署到 F407 → 实时输出「正常 / 异常」，测出推理延迟、内存、精度。

**面试叙事（提前想好的钩子）**：
> 「我做电能质量分析仪时用 FFT 做电流谐波分析——那是传统 DSP，对已知的谐波/间谐波有效，但对复杂、未知的异常模式识别能力有限。我想验证端侧 AI 能不能补这个短板：用 1D CNN 让模型自己学时序里的异常模式，INT8 量化后用 TFLM 部署到 Cortex-M4，推理 X ms、内存 Y KB。这让我看清了**传统 DSP 和端侧 AI 各自的地盘**——规则明确的信号用 DSP（FFT/滤波），模式复杂的识别用 AI（CNN）。」

这个叙事把你「DSP 王牌」和「端侧 AI」焊在一起，比纯 AI 候选人深一层。

## 四、8 周分阶段计划（在职现实版：每天 1h + 周末 3h，约 8-10h/周）

### Week 1-2：训练端——训出模型 + 量化 + 转 C 数组
- 数据集：用公开时序异常检测数据集（如 NASA 轴承振动、或模拟电流信号），归一化 + 滑窗切分（这一步就能回答千寻的「数据怎么标注」——时序信号用滑窗切片 + 标签规则）
- 训练：PyTorch 训 1D CNN 二分类（正常/异常），参考 `courses/week03-data-training-cnn.md`
- 量化：INT8 后训练量化（PTQ），生成 `model_int8.tflite`，转 C 数组 `model.h`
- **产出**：能跑的 `.tflite` + C 数组 + 训练/量化笔记

### Week 3-4：部署端——TFLM 集成 + 纯软件跑通
- 把 C 数组集成进 F407 工程（你卡在 90% 的地方，正好攻这个），调 TFLM 5 步 API（GetModel→Interpreter→填输入→Invoke→取输出）
- 用 CMSIS-NN 加速卷积（吃你 DSP 指令集功底）
- 串口打印推理结果，纯软件跑通（先用模拟数据）
- **产出**：F407 上能跑的推理工程 + 初步性能数据

### Week 5-6：上板闭环 + 性能实测
- 对接 ADC/传感器采集（或 DAC 回放真实信号），跑通「采集→预处理→推理→输出」完整闭环
- **实测三指标**（面试硬数据）：推理延迟（目标 <50ms）、内存占用（目标 <100KB）、精度（对比 PC 端，量化损失 <2%）
- 用你的 FreeRTOS/自研 RTOS 做「采集任务 + 推理任务 + 输出任务」三任务架构（吃 RTOS 王牌）
- **产出**：完整 demo + 实测性能数据表

### Week 7-8：理论补强 + 面试弹药
- 补 8 处答错概念（见第五节）
- 写 demo 的 STAR 话术 + 性能数据 + 「DSP vs AI」对比
- 整理成简历项目描述 + BOSS 话术
- **产出**：面试弹药库（可讲的项目 + 数据 + 概念）

## 五、理论补强清单（tech-interview-notes 里你答错的 8 处，面试高频）

| # | 概念 | 你现在的问题 |
|:--|:--|:--|
| 1 | MLP vs 1D CNN 推理负担 | 缺定量分析（要会算乘加次数：1D CNN 权值共享 vs MLP 全连接） |
| 2 | BN 折叠 vs 融合 | 「被优化了，具体为什么不知道」→ BN 参数在推理时融进 Conv 权重 |
| 3 | Dropout 翻转补偿 | 训练时丢弃、推理时乘保留概率（inverted dropout） |
| 4 | PTQ vs QAT 区别 | 答成「量化时机」→ PTQ 训后校准、QAT 训练中模拟量化 |
| 5 | 剪枝 / 蒸馏软标签 | 软标签含类间关系信息（dark knowledge） |
| 6 | CMSIS-NN / CNN / NPU 三概念 | 混淆 → CMSIS-NN 是 ARM 软件加速库、CNN 是网络结构、NPU 是硬件加速器 |
| 7 | TFLM / X-CUBE-AI / CMSIS-NN 三层 | 混淆 → TFLM 是推理框架、X-CUBE-AI 是 ST 的转换工具、CMSIS-NN 是底层算子库 |
| 8 | 量化 scale / zero_point | 核心：让推理全程只用整数乘加 + 移位、不碰浮点除法 |

补法：每条用「本质一句话 + 你的项目怎么体现」过一遍，能脱口而出。

## 七、目标公司 + 和其他两条线的关系

**目标岗/公司**（端侧推理部署/优化）：
- 芯片：寒武纪 / 地平线 / 晶晨（端侧 AI 固件、推理引擎优化）
- AI 独角兽：端侧推理部署岗
- 机器人：端侧推理（和机器人线重叠）
- 工业 AI：预测性维护（吃电力背景，差异化最强）

**三条线怎么协调**：
| 线 | 关系 |
|:--|:--|
| 芯片固件主线（必须涨） | 端侧 AI 推理优化岗很多就在芯片公司——**端侧 AI 强了，芯片主线更宽** |
| 机器人心仪线 | 机器人里的「端侧推理部署」就是这条线——**一鱼两吃** |
| 端侧 AI 主线 | 独立成线，且是「心仪 + 高薪 + 吃 DSP 王牌」三者交集，**优先级可以提到最高** |

**给你的判断**：端侧 AI 这条线，是你三条线里**唯一能同时满足「心仪 + 能吃 DSP 王牌 + 能冲 60-65K」的**。如果只能押一条，我押这条。
