# STM32动作识别端到端根因与修复报告

## 1. 结论

现有数据量足以完成当前三分类原型。长期失败的主要原因不是“数据条数不够”，而是训练链路与板端链路不一致，并且板端后处理覆盖了模型的真实输出。

本次已将 `D:\Day16_code\Day16_Software_Package_MCU` 改为部署模型B（56维时域+频域特征），并完成编译。

## 2. 已确认的根因

1. **板端清洗过程被额外修改。** Day16曾加入“静止后重置重力”和“动态加速重力跟踪”，而训练CSV来自固定 `alpha=0.02` 的重力低通。相同动作因此会产生不同的线性加速度。
2. **模型概率被人工改写。** 原代码会把某些窗口直接改为 `Idle=100%`，还会按照陀螺仪阈值交换Walk和Stairs概率。屏幕上的100%和27.4%不完全是模型的原始判断。
3. **AI初始化执行了两次。** `MX_X_CUBE_AI_Init()` 同时出现在CubeMX初始化区和用户初始化区。模型句柄不应重复创建。
4. **板端使用的Model A缺少频域信息。** Walk和Stairs都具有明显运动能量，只看模长时域统计容易混淆；步态周期、频谱质心和频带能量更适合区分两者。
5. **旧源码注释与真实CSV单位矛盾。** 训练CSV的静止 `acc_norm/1000` 约为 `0.998 g`。真实CSV是数值权威，板端必须输出g，不能再乘9.807。

## 3. 本次修复

- 部署模型B：输入 `int8[1,56]`，输出 `int8[1,3]`。
- 板端实现与Python一致的64点Hann窗RFFT和16个选定频域特征。
- 固定采样周期25 ms、窗口64点、步长16点。
- 恢复固定低通 `alpha=0.25` 和固定重力低通 `alpha=0.02`，删除自适应重力重置。
- 只保留一次 `MX_X_CUBE_AI_Init()`。
- 三个模型概率原样输出，不再改成100%，不再交换Walk和Stairs概率。
- 最终显示标签采用EMA和两窗确认；单次晃动不会立即切换状态。
- 增加编译期输入/输出维度检查。
- 增加 `clip` 计数。正常测试窗口通常为0到3；超过10视为训练分布外输入，暂不切换稳定标签。
- 增加三类固定窗口启动自检，验证Python特征、C特征、INT8输入和模型类别。

## 4. 离线连续序列验证

| 连续测试段 | 原始INT8准确率 | 两窗时序稳定后 |
|---|---:|---:|
| Idle | 100.00% | 100.00% |
| Walk | 90.78% | 95.74% |
| Stairs | 89.76% | 95.28% |
| 总体 | 92.95% | 96.75% |

对“上楼梯后切换为走路”的完整记录：

- Stairs核心段稳定后准确率：96.55%
- 已确认Walk尾段稳定后覆盖率：86.59%
- 检测到的首次稳定Walk窗口起点：291568 ms
- 人工隔离的过渡区：290768~297168 ms

Walk尾段参加过训练，因此86.59%是覆盖率，不是独立泛化准确率。

## 5. 上电后的硬判据

串口必须出现：

```text
[AI] Day16 action model (model_int8 / time_frequency) init
[AI] in=56 S8, out=3 S8, labels=idle/walk/stairs
[AI] PARITY_PASS,input_diff_gt1=0
```

如果出现 `PARITY_FAIL`，说明Python与板端输入仍未对齐，后续动作结果不能采信。

正常运行时：

```text
ACT_RAW,net=...,stable=...,lin=...,gyMax=...,fDom=...,fCtr=...,clip=...
ACT,idle=...,walk=...,stairs=...,pred=...,an=...,gn=...,n=...
```

`ACT`中的三个概率为模型原始概率；`pred`是经过两窗确认的显示标签。两者用途不同，不应再互相覆盖。
