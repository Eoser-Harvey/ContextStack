# Day11到Day16真实数据流审计报告

## 1. 审计结论

Day16当前模型输入链路应当以保存下来的 `*_clean.csv` 为数值权威，而不能直接照搬
Day11源码中的 `m/s²` 注释。

当前Day16的核心做法是正确的：

- QMI8658A加速度在进入清洗器时使用 `g`；
- 陀螺仪使用 `rad/s`；
- 清洗后整数除以1000，得到模型通道；
- 25 ms采样、64点窗口、16点步长；
- 低通系数0.25、重力跟踪系数0.02；
- 使用56维时域和频域特征模型。

但必须记录一个无法忽略的来源矛盾：当前磁盘上的Day11源码和2026年7月21日的
Release目标使用 `m/s²`，而实际保存的CSV使用 `g`。GUI没有执行9.807倍缩放，
因此这批CSV并不是由当前检查到的Day11 Release目标原样产生的。原始UART日志未保留，
无法继续追溯当时开发板上究竟烧录了哪个二进制版本。

## 2. 真实数据流

### 2.1 Day11源码描述的数据流

```text
QMI8658A寄存器原始值
  -> qmi8658_read_sensor_data
  -> 加速度 raw * 9.807 / sensitivity
  -> 陀螺仪 raw * pi / sensitivity / 180
  -> 前100个有效样本计算加速度和陀螺仪零偏
  -> qmi8658_read_xyz
  -> day11_data_collect_update
  -> float * 1000并取整
  -> 低通 alpha=0.25
  -> 重力低通 alpha=0.02
  -> 线性加速度 = 低通加速度 - 重力
  -> DAY11_RAW / DAY11_CLEAN串口文本
```

按照这段源码，静止时 `acc_norm_x1000` 应接近9807。

### 2.2 GUI实际做的事情

`day11_serial_gui_capture.py`没有转换传感器数值：

1. `parse_day11_line`只执行字符串去空格和逗号分割。
2. `CaptureWriters.write_row`只替换 `label_id` 和 `label`。
3. 其余字段作为字符串原样写入CSV。

因此，GUI不可能把串口中的9807自动变成998。

### 2.3 实际保存CSV的数值

| 类别 | Raw加速度模长中位数 | Clean `acc_norm/1000`中位数 | Clean行数 |
|---|---:|---:|---:|
| idle | 0.998433 | 0.998 | 8388 |
| walk | 0.998982 | 0.996 | 11307 |
| stairs | 0.999115 | 0.997 | 11430 |

这些数值明确表示加速度单位是 `g`，不是 `m/s²`。

### 2.4 Day11编译产物证据

`D:\Day11_code`中的Release目标生成于2026年7月21日20:50左右。
反汇编 `qmi8658.o` 可以看到：

- `qmi8658_read_sensor_data`中存在浮点乘法；
- 函数常量区包含单精度浮点数 `9.80700016`；
- 依赖文件确认对象文件来自当前检查的
  `D:\Day11_code\Software_Package\Drivers\BSP\QMI8658A\qmi8658.c`。

因此，Day11 Release对象与实际CSV之间确实存在9.807倍矛盾，不是注释错误这么简单。

## 3. V2训练真正使用的输入

训练没有使用稀疏的 `*_raw.csv`，也没有使用板端生成的 `*_window.csv`。

训练脚本只读取三个 `*_clean.csv`：

```text
lin_ax/ay/az_x1000 / 1000 -> lin_x/y/z
gx/gy/gz_x1000 / 1000     -> gyro_x/y/z
acc_norm_x1000 / 1000 - 1 -> acc_norm_centered
```

随后执行：

1. 丢弃 `valid != 1` 或 `clipped != 0` 的样本。
2. 根据时间戳线性插值到40 Hz，即25 ms。
3. 以64点、16点步长切出重叠窗口。
4. 提取时域特征和64点Hann窗频域特征。
5. 仅用训练集计算0.5%和99.5%裁剪范围、均值和标准差。
6. 生成56维模型输入。
7. 使用训练集代表性样本完成全INT8量化。

上楼梯记录的处理方式：

- `t_ms < 290768`：保留为stairs；
- `290768 <= t_ms < 297168`：作为动作切换区删除；
- `t_ms >= 297168`：根据用户确认重新标记为walk，只加入训练集。

| 重力系数 | 0.02 | 0.02 | 一致 |

| 模型通道缩放 | CSV整数除1000 | 清洗整数除1000 | 一致 |

## 5. 自检能证明什么

启动串口中的：

```text
[AI] PARITY_PASS,input_diff_gt1=0
```

能够证明：

```text
清洗后7通道
  -> C语言56维特征
  -> 裁剪和标准化
  -> INT8输入
  -> X-CUBE-AI模型输出
```

与Python一致。

它不能单独证明QMI8658A驱动和清洗器正确。传感器前半段必须再看：

```text
DAY16_SAMP,...,an=...,gn=...
```

静止平放时 `an` 应接近1000。若接近9807，说明重新生成或烧录了 `m/s²` 版本驱动，
此时所有模型结果都无效。

## 6. 最终判断

根据实际CSV和V2训练过程，Day16不应恢复为乘9.807的Day11源码版本。当前Day16使用
`g`并按CSV复现清洗和特征，是正确选择。

数据量足以验证同一块开发板、相同握持和相同采集方式下的三分类原型。当前验证集来自
同一次连续采集中的不同时间段，因此92.95%的INT8测试准确率不能等同于跨人员、跨安装
位置、跨设备的泛化准确率。若板端仍异常，下一步判断必须依据 `PARITY_PASS`、
`DAY16_SAMP`和原始三类概率，而不能再通过修改类别阈值猜测。
