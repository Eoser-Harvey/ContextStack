## 6.1 AI编程高效使用的5步法

**截图参考**：`../images/AI编程高效指南.png`

这套方法的核心是**先建立约束再释放能力**：

```
步骤1: 立范围 → 步骤2: 设问题 → 步骤3: 定目标 → 步骤4: 提示例 → 步骤5: 补要求
```

| 步骤 | 操作 | 具体做法 | 为什么重要 |
|------|------|----------|-----------|
| **1. 立范围（Scope）** | 明确本次交互的边界 | "我们只讨论订单模块的支付功能，不涉及物流" | 防止AI发散到无关领域，节省Token |
| **2. 设问题（Problem）** | 描述你要解决的具体问题 | "当前支付回调处理超时，需要优化到200ms以内" | 让AI理解"为什么要做"，而不只是"做什么" |
| **3. 定目标（Goal）** | 明确成功的标准 | "输出一个异步处理的方案，包含代码实现和时序图" | 给AI明确的交付物预期 |
| **4. 提示例（Example）** | 给参考样本 | "参照现有的refund_handler.py的风格来写" | 让AI对齐你的代码风格和模式偏好 |
| **5. 补要求（Requirements）** | 补充约束条件 | "不要引入新的依赖，错误处理要用我们统一的异常体系" | 避免AI自作主张引入不必要的东西 |

### 反面教材对比

| ❌ 低效提问方式 | ✅ 高效提问方式（5步法） |
|----------------|------------------------|
| "帮我优化一下这个接口" | "Scope: 订单模块的支付回调接口。Problem: 当前超时达2秒。Goal: 优化到200ms以内。Example: 参照refund_handler的异步模式。Requirement: 不引入新依赖。" |
| "写个登录功能" | "Scope: 用户认证模块。Problem: 当前无token刷新机制。Goal: 实现JWT双token方案。Example: 参照auth_service.py现有风格。Requirement: 用现有的crypto工具类。" |

**核心原则**：你在第一步花的准备时间越多，后面AI跑偏返工的时间就越少。

## 6.2 AI编程的新范式：7条核心原则

**截图参考**：`../images/AI编程高效指南2.png`

| # | 原则 | 核心含义 | 实操要点 |
|---|------|---------|---------|
| **1** | **Spec-Kit优先** | 先给规格说明包（Spec-Kit），再让AI动手 | Spec-Kit = 规范 + 约束 + 示例 + 模板，一次性喂给AI |
| **2** | **模板驱动生成** | 用模板约束AI的输出格式 | 先定义好输出模板（如API文档格式、代码文件结构），AI往里填内容 |
| **3** | **Hook机制拦截** | 在关键节点设置检查点（Hook） | 如：代码提交前Hook（自动检查规范）、PR创建前Hook（自动CR） |
| **4** | **增量式交互** | 小步快跑，每步确认后再继续 | 单次变更控制在50行左右，避免大段不可控输出 |
| **5** | **双向反馈闭环** | 不只是"人审AI"，也要收集AI的反馈 | AI可以说"这个设计方案可能有风险"，人要认真听 |
| **6** | **资产沉淀纪律** | 把验证有效的方法论固化下来 | 每次"好用"的交互都要问自己：能不能变成Skill？ |
| **7** | **人机协同而非替代** | 明确分工边界——AI做擅长的事，人做必须的事 | AI擅长：生成、搜索、模式匹配；人擅长：判断、决策、创新 |

### 原则之间的协作关系

```
        ┌─────────────┐
        │  Spec-Kit   │ ← 输入规范化（原则1+2）
        │  + 模板     │
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │  Hook拦截    │ ← 过程质量控制（原则3+4）
        │  + 增量交互  │
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │  双向反馈    │ ← 结果优化循环（原则5+6）
        │  + 资产沉淀  │
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │  人机协同    │ ← 底层哲学（原则7）
        └─────────────┘
```

## 6.3 最佳实践循环体系

**截图参考**：`../images/腾讯云AI编程的实践思路.png`

AI编程能力的提升不是一次性的学习，而是一个**持续的正反馈循环**：

```
     ┌─────────────────────────────────────────┐
     │                                         │
     ▼                                         │
┌──────────┐    ┌──────────┐    ┌──────────┐   │
│ 最佳实践  │ →  │ 使用深度  │ →  │ 功能迭代  │ ──┘
│ 总结提炼  │    │ 持续深入  │    │ 能力扩展  │
└──────────┘    └──────────┘    └──────────┘
     ▲                              │
     └──────────────────────────────┘
```

### 循环的三个阶段详解

#### 阶段一：最佳实践总结提炼
- 从日常使用中发现有效的模式
- 记录"什么场景用什么方法效果好"
- 形成可复制的操作SOP
- **产出**：最佳实践文档 / Skill草案

#### 阶段二：使用深度持续深入
- 有了最佳实践指导后，使用更有方向性
- 尝试将AI应用到更多场景（不只是编码，还有设计、调试、文档...）
- 发现工具的更多能力边界
- **产出**：更丰富的使用经验和场景覆盖

#### 阶段三：功能/能力迭代
- 使用深度的增加暴露出工具的能力短板
- 反馈给工具/框架的改进方向
- 新版本带来新能力，又催生新的最佳实践
- **产出**：更好的工具/框架/Skills

### 这个循环如何具体落地？

以ContextStack框架为例的落地路径：

| 循环轮次 | 最佳实践 | 使用深度 | 功能迭代 |
|---------|---------|---------|---------|
| **第1轮** | 发现"给AI项目规则后输出质量明显提升" | 开始在每次会话前准备PROJECT-RULES | 将规则加载自动化（工作台自动读取） |
| **第2轮** | 发现"好的Skill可以跨项目复用" | 建立Shared-Skills共享库 | 设计Skill的版本管理和索引机制 |
| **第3轮** | 发现"Plan模式大幅减少返工" | 所有复杂任务强制走Brainstorming流程 | Plan模式的可视化（执行计划表格化） |
| **第N轮** | ... | ... | ... |

**关键洞察**：这个循环没有终点——随着AI能力和使用经验的共同增长，天花板在不断抬高。

## 与ContextStack框架的关联

- **5步法（立范围→设问题→定目标→提示例→补要求）** 与Brainstorming Skill的Phase 1需求澄清高度同构——都是"先明确再做"
- **Spec-Kit优先原则** 正是ContextStack四层Context设计的核心理念——GLOBAL-RULES + PROJECT-RULES + 规范文档 + Memory 就是一个完整的Spec-Kit
- **模板驱动** 对应04-Templates/目录下的各类模板文件
- **Hook机制** 对应create_rule等工具实现的规则拦截机制
- **增量式交互** 对应Karpathy Guidelines的"手术式修改"原则
- **最佳实践循环** 就是ContextStack框架自身的进化方式——通过持续使用不断优化
