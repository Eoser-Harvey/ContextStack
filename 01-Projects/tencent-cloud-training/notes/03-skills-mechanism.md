## 3.1 Skills的本质：知识→技能转化

**截图参考**：`../images/AI编程的skills.png`

Skills不是简单的"提示词模板"，而是**将静态知识转化为可执行的动态技能**：

```
┌─────────────────────────────────────────────────────────┐
│                    Skills 转化漏斗                        │
├─────────────────────────────────────────────────────────┤
│  显性知识（Know-What）                                    │
│  ├── 文档（API说明、架构文档）                            │
│  ├── 规范（编码标准、Git流程）                            │
│  └── 经验（踩坑记录、最佳实践）                           │
│           ↓ 提炼 & 结构化                                 │
│  隐性知识（Know-How）                                    │
│  ├── 判断力（什么场景用什么方案）                         │
│  ├── 模式识别（这个bug见过，应该这样修）                   │
│  └── 决策逻辑（先做A再做B，因为...）                      │
│           ↓ 封装 & 可执行化                               │
│  Skills（可被AI调用的技能包）                             │
│  ├── 触发条件（何时激活）                                 │
│  ├── 执行步骤（具体怎么做）                               │
│  └── 输出规范（产出什么格式）                             │
└─────────────────────────────────────────────────────────┘
```

**核心区别**：

| 维度 | 普通Prompt | Skills |
|------|-----------|--------|
| 性质 | 一次性指令 | 可复用的技能模块 |
| 粒度 | 解决单个问题 | 封装完整方法论 |
| 迭代 | 用完即弃 | 持续优化版本化管理 |
| 共享 | 个人所有 | 团队可共享 |
| 触发 | 手动粘贴 | 自动匹配场景调用 |

## 3.2 Skills应用的两大核心机制

**截图参考**：`../images/AI编程的应用Skills的应用分析.png`

### 机制一：迭代验收（小步快跑）

```
设定小目标（~50行代码） → AI执行 → 人工快速审核 → 通过/反馈修正 → 下一个小目标
```

- 每次**只让AI做可控范围的改动**（建议50行以内）
- **每次都检查**，不等最后一起看
- 发现问题**立即纠正**，避免错误累积
- 通过的成果**立即提交**，保持进度可见

### 机制二：Prompt资产沉淀

将验证有效的交互模式固化下来：

| 类型 | 说明 | 示例 |
|------|------|------|
| **有效Prompt模板** | 反复验证过的高质量提示词 | "请按照XX规范实现YY功能，注意ZZ约束" |
| **反模式记录** | 证明无效的做法 | "不要一次让AI改超过100行" |
| **场景-Skill映射表** | 什么场景触发哪个Skill | 代码提交 → git-commit Skill |
| **验收 Checklist** | 每次交付前必查项 | 功能正确/格式符合/无回归 |

**资产沉淀的价值**：第一次用AI可能只快10%，但积累了一套Skills后，第10次同类任务可能快50%+。

## 3.3 Skills实战案例：提交代码规范化

**截图参考**：`../images/Skills应用1-提交代码.png`

以"代码提交"为例，展示Skills配置的完整5步流程：

| 步骤 | 操作 | 要点 |
|------|------|------|
| **1. 环境准备** | 确认AI工具有文件读写权限 | 配置.gitignore、权限策略 |
| **2. 克隆/准备Skill仓库** | 将Skill文件放到指定路径 | ContextStack中对应 `Skills/` 目录 |
| **3. 配置调用路径** | 让AI知道去哪里找Skill | 在规则文件中声明Skill路径 |
| **4. 验证生效** | 测试Skill是否被正确加载 | 发送触发指令，观察行为 |
| **5. 开始使用** | 在日常开发中自然触发 | 符合条件时自动或手动调用 |

**该Skill的核心内容**（以git commit为例）：
- 自动分析变更范围
- 按规范生成commit message（类型+范围+描述）
- 检查是否有敏感信息泄漏
- 确认分支策略是否符合团队规范

## 3.4 与AI对话的核心技巧：拟人化哲学

**截图参考**：`../images/和AI对话技巧1.png`

**核心理念：把AI当成一个"初中级工程师"来沟通**

这意味着：
- ✅ 他有能力，但**不能完全放心**
- ✅ 你需要**给明确的指导**，不能让他自由发挥
- ✅ 需要**定期检查**他的工作成果
- ✅ 好的**指导和反馈**会让他越来越好用

### 具体沟通技巧

| 技巧 | 做法 | 错误做法 |
|------|------|----------|
| **给角色** | "你是一个有5年经验的Python后端工程师" | 不给任何背景直接提问 |
| **给上下文** | "我们在做一个电商系统的订单模块，用的Django+PostgreSQL" | "帮我写个下单接口" |
| **给示例** | "参照现有的user_service.py的风格来实现" | 让AI自己猜风格 |
| **分步骤** | "先写接口定义，等我确认再写实现" | "帮我完成整个下单功能" |
| **及时反馈** | "这部分对了，但X地方需要改成Y" | 不说话直接让它继续 |
| **明确约束** | "不要引入新的依赖，只用标准库" | 任由AI引入各种第三方库 |

### Prompt公式

```
[角色设定] + [任务背景] + [具体要求] + [约束条件] + [输出格式]

例："作为资深网络工程师（角色），帮我看一下这个H3C交换机VLAN配置（背景），检查是否存在环路风险（要求），只使用已有命令不要新增配置（约束），输出风险点和修改建议（格式）"
```

## 与ContextStack框架的关联

- **Skills本质（知识→技能）** 正是ContextStack Skills目录的设计初衷——每个Skill文件夹 = 一个可复用技能包
- **迭代验收机制** 对应 Karpathy Coding Guidelines 的"手术式修改"原则
- **Prompt资产沉淀** 对应工作台的会话历史保存 + MEMORY索引
- **拟人化哲学** 与ContextStack的CEO协作模式完全契合——用户是Boss，AI是CEO/工程师
- **5步实战流程** 中，ContextStack已经完成了步骤1-3（环境/Skill库/路径配置），用户只需步骤4-5
