## 做对了什么（保持）

1. **找到源头而不是猜格式**：用户只给了推送截图，没有描述格式。第一反应是去仓库里搜 `刷卡循环提醒|今日需刷卡|今日资金到账`，命中原始脚本 `C:\Users\harve\CodeBuddy\automation-20260607233351\credit_cycle_reminder.py`，直接拿到权威格式（含 `template=html`、`&nbsp;&nbsp;` 缩进、🟨→💳 的真实 emoji），避免继续凭想象拼格式。
2. **用解析结果自证**：新脚本先 `--dry` 跑一遍，打印「表1 17条 / 表2 3条 / 年费0张」，与人工核对一致后才真发，格式和逻辑一次对齐。
3. **数据源与代码解耦**：脚本解析 md 表格而不是硬编码数字；年费也改为扫描 `卡片信息库.md` 的年费行自动提取日期，源文件改了脚本自然跟随。

## 踩了什么坑（避免）

1. **同一个需求改了 4 次口径，每次都是"替换"而不是"补齐"**（最大的教训）
   - 第1次：用 `卡片信息库.md` 的**账单日**匹配 → 结论"今天无卡出账"（漏报）
   - 第2次：改成 `信用卡管理方案.md` 的**还款日**匹配 → 推出交通6.0万 + 交通2 4.9万
   - 第3次（用户给截图后）：发现循环提醒的触发列是**刷卡日(D0)/到账日**，于是把还款段整个删了 → **把"今日还款提醒"丢了**
   - 第4次：用户指出还款提醒数据**也在两张表第一列**，才补回三段
   - 根因：**把"多段并存"误当成"口径替换"**。正确形态是每张表内三段并列：💳今日需还款（还款日）→ 🔔今日需刷卡（刷卡日D0）→ 💰今日资金到账（到账日），**缺一不可**。
   - 教训：改口径时先问"是替换还是新增"；任务文字里的"出账单/账单日"是模糊词，**用户的历史脚本与历史推送才是唯一权威**。
2. **数据源乱找**：为了补还款提醒，跑去用标准库解析 Excel `信用卡主控表.xlsx` 的「3-0账单日历」，被用户纠正"数据也在两张表第一列，不要乱找"。**同一需求的数据源应单一**，能在一处取到就不要引入第二个源（Excel 与 md 表还会不一致，反而埋雷）。
3. **只按文字描述搭格式**：前两版自己拼了"还款金额/刷卡日/到账日清单"的纯文本，完全不是用户想要的卡片式 HTML 排版。用户要的是"以前推送的格式"，而我一开始没去找"以前"。

## 下次怎么更快（优化）

1. 遇到"参照历史邮件/推送/报表的格式"类需求 → **第一步全局搜关键词找生成脚本**，而不是先写代码。
2. 多轮纠偏时，改口径之前先问一句"是替换还是新增"，避免三连返工。
3. 自动化任务的正解形态：**提示词只负责"调脚本 + 汇报 stdout"**，业务逻辑全部沉到脚本里。提示词里写业务规则，每天都要靠模型重新实现一遍，不稳。

## 可复用的模式

- **「截图 → 找脚本 → 复刻」闭环**：用户给格式截图时，先 `Grep` 关键文案定位生成脚本，再照抄 HTML 片段与 emoji，最后 `--dry` 自证。
- **两表独立数据的排版约定**：同源不同池的数据不要合并累加，用 `✦ ━━━ ✦` 分割线 + `🔷/🔶` 前缀分段呈现，两组边界一眼可辨。
- **脚本化自动化**：WorkBuddy 自动化提示词 = 「运行脚本 + 原样输出 stdout + 健康检查（条数断言）」，脚本支持 `--dry` 便于调试。
