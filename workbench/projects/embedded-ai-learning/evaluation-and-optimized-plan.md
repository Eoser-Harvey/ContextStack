## 一、市场调研结论：嵌入式AI岗位真实需求

### 1.1 薪资水平（2026年一线城市）

| 级别 | 经验 | 薪资范围 | 核心要求 |
|------|------|----------|----------|
| 初级 | 1-3年 | 15-25K | STM32 + 一种推理框架 |
| 中级 | 3-5年 | 25-40K | 多框架 + 量化优化 + Linux |
| 高级 | 5-8年 | 40-70K | 芯片级优化 + 系统架构 |
| 架构师 | 8年+ | 70K+ | 全栈边缘智能系统设计 |

> 关键数据：具备嵌入式+AI复合能力的人才，企业愿意溢价 **20%-30%** 招聘。

### 1.2 企业实际要求的技能栈（从岗位JD提取）

**你必须会的（硬门槛）：**
- C/C++ 精通（你已有）
- Python 熟练（需要补）
- 至少一种推理框架：TFLite Micro / ONNX Runtime / MNN / TensorRT
- 模型量化技术：INT8 / INT4 / FP16
- 模型压缩：剪枝、蒸馏、算子融合
- RTOS 或 Embedded Linux（你已有 RTOS 基础）

**差异化竞争力（高薪关键）：**
- 多框架经验：TFLite + ONNX Runtime + 至少一个国产框架（MNN/Paddle Lite）
- 硬件加速：NPU / DSP / RVV 向量指令
- 特定平台经验：Qualcomm SNPE / Rockchip RKNN / MediaTek NeuroPilot
- 完整工具链：PyTorch → ONNX → TFLite 全流程
- MLOps：模型版本管理、A/B测试、性能监控

### 1.3 行业趋势判断

| 趋势 | 对你转型的影响 |
|------|---------------|
| MCU+NPU 架构普及 | TFLM 是正确切入点，但需要扩展到 NPU SDK |
| RISC-V 国产替代加速 | 加分项，建议关注但不作为主线 |
| Transformer 向边缘迁移 | 需要了解 Attention 机制，不只是 CNN |
| 多框架并存 | **不能只学 TFLM**，至少要了解 ONNX 生态 |
| 端侧大模型兴起 | 长期趋势，当前阶段不需要深入 |

## 二、你当前计划的诊断

### 2.1 做得好的地方

- 每周结构清晰，有目标、内容、实践、考核四要素
- "常见陷阱与经验"板块非常实用，体现了工程思维

- 学习循环（计划→任务→执行→反馈→打分→完善）设计合理
- 选择了 TFLM 作为切入点，方向正确

### 2.2 需要优化的关键问题

#### 问题1：技术栈太窄——只学 TFLM 不够

你的计划几乎 100% 围绕 TFLM，但市场要求的是**多框架能力**。企业 JD 中频繁出现：
- ONNX Runtime（模型交换格式的事实标准）
- MNN（阿里开源，国产替代首选）
- TensorRT（NVIDIA 边缘设备）
- SNPE（高通平台）

**建议**：TFLM 作为主线（占 60%），但必须加入 ONNX 生态（占 30%）和至少了解一个国产框架（占 10%）。

#### 问题2：缺少深度学习理论基础

你直接从"TFLM 架构"开始，跳过了神经网络的基本原理。这会导致：
- 不理解为什么某些算子不支持量化
- 看不懂模型结构，无法做针对性优化
- 面试时被问"反向传播原理"会卡住

**建议**：在 Month 1 之前或 Week 1-2 加入 2 周的 DL 基础速成。

#### 问题3：Python 和训练侧能力缺失

你的计划侧重"部署"，但嵌入式 AI 工程师需要理解**模型是怎么训练出来的**：
- 数据预处理、增强
- PyTorch/TensorFlow 训练流程
- 损失函数、优化器选择
- 模型评估指标（mAP、F1、ROC）

**建议**：Month 1 加入 PyTorch 基础训练实践。

#### 问题4：Month 3 三个项目不现实

4 周内完成 MNIST + 语音唤醒词 + IoT 设备三个项目，即使是熟练工程师也很难。建议精简为 **1 个主线项目 + 1 个可选项目**。

#### 问题5：缺少 ONNX 中间表示

实际工作流是：**PyTorch 训练 → 导出 ONNX → 转换为 TFLite/其他格式**。你的计划跳过了 ONNX 这一环。

#### 问题6：没有硬件平台

计划中写"开发板（待定）"，但没有具体硬件就无法做真正的部署。建议尽快确定。

## 三、优化后的 3 个月学习方案

### 总体设计思路

```
传统嵌入式工程师的优势：
  C/C++ 精通 ✓ → 直接用于推理引擎集成和算子优化
  RTOS 熟悉 ✓ → 理解实时约束，做 Tickless 低功耗
  硬件调试 ✓ → JTAG/逻辑分析仪用于性能分析
  内存敏感 ✓ → 天然理解 Tensor Arena 的设计

需要补齐的能力：
  Python → 数据管线 + 模型训练
  DL 理论 → 神经网络原理 + 训练方法论
  模型压缩 → 量化/剪枝/蒸馏
```

### Month 1：基础补齐 + 第一个模型落地（Week 1-4）

#### Week 1：深度学习速成 + Python 数据管线

**目标**：理解神经网络基本原理，能用 PyTorch 训练简单模型

**理论（每天 1-2 小时）**：
- Day 1-2：感知机 → 多层神经网络 → 激活函数（ReLU/Sigmoid/Softmax）
- Day 3-4：卷积神经网络（CNN）原理：卷积核、池化、特征图
- Day 5：反向传播与梯度下降（理解即可，不需要手推公式）
- Day 6-7：损失函数（CrossEntropy/MSE）、优化器（SGD/Adam）

**实践（每天 1-2 小时）**：
- 用 PyTorch 训练 MNIST 分类器（10行核心代码）
- 用 Netron 可视化模型结构
- 用 Matplotlib 画出训练曲线（loss/accuracy）

**考核标准**：
- [ ] 能解释 CNN 的卷积、池化、全连接三层的作用
- [ ] 能独立用 PyTorch 训练一个 MNIST 模型，准确率 > 95%
- [ ] 能说出量化为什么对嵌入式重要（算力、内存、功耗三个维度）

**本周产出**：一个训练好的 MNIST 模型（.pth 文件）+ 训练笔记

#### Week 2：模型转换全流程 + TFLM 环境搭建

**目标**：掌握 PyTorch → ONNX → TFLite 转换链，完成 TFLM 编译

**理论**：
- ONNX 是什么：模型交换格式，算子标准
- TFLite 转换器原理：算子映射、图优化
- FlatBuffer 格式：为什么比 Protobuf 更适合嵌入式

**实践**：
- 将 Week 1 的 MNIST 模型：.pth → .onnx → .tflite
- 对比三个格式的文件大小
- 用 Netron 对比转换前后的模型图
- 搭建 TFLM 编译环境（Bazel/CMake）
- 编译并运行 hello_world 示例

**考核标准**：
- [ ] 完成 .pth → .onnx → .tflite 全流程转换
- [ ] TFLM 编译成功，hello_world 示例运行通过
- [ ] 能解释 FlatBuffer 相比 JSON/Protobuf 的优势

**本周产出**：完整的模型转换脚本 + TFLM 编译环境

---

#### Week 3：TFLM 架构深入 + 模型量化

**目标**：理解 TFLM 核心架构，掌握后训练量化

**理论**：
- TFLM 核心组件：MicroInterpreter、MicroAllocator、OpResolver
- Tensor Arena 内存模型：Head/Temporary/Tail 三段式
- 量化原理：对称量化 vs 非对称量化，scale + zero_point
- 后训练量化 (PTQ) vs 量化感知训练 (QAT)

**实践**：
- 对 MNIST 模型做 INT8 后训练量化
- 对比量化前后的：模型大小、推理速度、精度
- 阅读 MicroAllocator 源码（micro_allocator.h/cc）
- 用 MemoryPlanner 分析内存使用

**考核标准**：
- [ ] 能画出 TFLM 推理流程图（从 LoadModel 到 Invoke）
- [ ] 量化后模型精度损失 < 2%
- [ ] 能解释 Tensor Arena 为什么要分三段

**本周产出**：量化对比实验报告 + TFLM 架构笔记

---

#### Week 4：第一个端到端部署 —— MNIST on Device

**目标**：将量化后的 MNIST 模型部署到真实硬件

**实践**：

**考核标准**：
- [ ] 模型在开发板上成功运行

## 七、给你的个人建议

### 你的核心优势（不要低估）

1. **C/C++ 精通**：这是嵌入式 AI 工程师最硬核的竞争力。很多 AI 工程师只会 Python，遇到底层优化就卡住。你的 C/C++ 能力让你能直接看懂 TFLM 源码、写自定义算子、做指令级优化。

2. **硬件调试能力**：JTAG、逻辑分析仪、示波器——这些是纯软件工程师不具备的。当模型在设备上跑出奇怪结果时，你能从硬件层面排查。

3. **内存敏感度**：传统嵌入式开发让你天然理解"每一字节都要省"。这种思维在做模型压缩时是巨大优势。

4. **RTOS 经验**：理解实时约束、中断处理、任务调度，这对端侧 AI 的实时性保证至关重要。

### 转型风险提示

1. **不要试图成为算法专家**：你的定位是"嵌入式 AI 部署工程师"，不是"算法研究员"。数学推导了解即可，不需要精通。

2. **Python 够用就行**：不需要成为 Python 专家，能写数据管线、训练脚本、转换脚本即可。

3. **保持嵌入式本色**：不要因为学 AI 就丢掉嵌入式功底。你的价值恰恰在于"既懂嵌入式又懂 AI"的交叉地带。

### 3 个月后的进阶方向

- 学习 TVM（Apache TVM）：更底层的编译器级优化
- 深入 RISC-V 向量扩展（RVV）
- 了解端侧大模型（TinyLLaMA 等）
- 学习 MLOps 工具链（MLflow, DVC）
