# 调试方法论

> 系统化的问题定位与解决框架

## 核心原则

### 1. 先理解，后操作
- 在修改任何代码或配置前，必须完全理解当前状态
- 阅读相关文档、日志和代码注释
- 理解系统的正常行为模式

### 2. 分步验证
- 将复杂问题分解为可验证的小步骤
- 每一步都要有明确的预期结果
- 记录每一步的实际结果

### 3. 假设驱动
- 基于观察形成假设
- 设计实验验证假设
- 根据实验结果更新假设

### 4. 证据优先
- 依赖客观数据（日志、指标、抓包）
- 避免主观猜测
- 保留所有调试证据

## 调试流程

### 阶段1: 问题描述
1. **现象**: 具体发生了什么？
2. **影响**: 对系统/用户的影响是什么？
3. **范围**: 影响的广度（单点/全局）？
4. **复现**: 是否可以稳定复现？

### 阶段2: 信息收集
1. **日志**: 收集所有相关日志
2. **配置**: 检查当前配置状态
3. **状态**: 检查系统运行状态
4. **历史**: 查看变更历史

### 阶段3: 分析定位
1. **模式识别**: 寻找规律和模式
2. **根因分析**: 使用5Why法定位根本原因
3. **影响分析**: 确定影响范围和路径
4. **假设验证**: 验证可能的原因

### 阶段4: 解决方案
1. **方案设计**: 制定解决方案
2. **影响评估**: 评估方案影响
3. **实施验证**: 小范围验证
4. **全面部署**: 确认后全面实施

### 阶段5: 总结归档
1. **问题总结**: 记录问题全貌
2. **经验提炼**: 提炼可复用的经验
3. **文档更新**: 更新相关文档
4. **知识分享**: 团队内分享

## 网络设备调试专项

### 分层调试模型
```
物理层 → 数据链路层 → 网络层 → 传输层 → 应用层
   ↓         ↓          ↓        ↓        ↓
硬件连接   MAC地址    IP配置   端口状态  协议交互
链路状态   VLAN配置   路由表   Socket   应用日志
信号质量   端口模式   ARP表    TCP状态   HTTP/DNS
```

### 常见问题模式

#### 连通性问题
- **现象**: ping不通、无法访问
- **排查路径**: 物理连接 → 端口状态 → VLAN配置 → IP配置 → 路由
- **关键命令**: `ping`, `tracert`, `display interface`, `display vlan`
- **常见原因**: 端口shutdown、VLAN配置错误、IP不在同一网段、路由缺失

#### 性能问题
- **现象**: 延迟高、丢包、吞吐量低
- **排查路径**: 端口统计 → 流量分析 → 队列状态 → 带宽利用率
- **关键工具**: Wireshark抓包、端口计数器、流量监控
- **常见原因**: 带宽不足、队列拥塞、双工不匹配、MTU问题

#### 协议问题
- **现象**: 协议协商失败、邻居无法建立
- **排查路径**: 协议配置 → 协议状态 → 协议报文交互
- **关键命令**: `display` 系列命令、`debug` 系列命令
- **常见原因**: 配置不一致、认证失败、版本不匹配

### 本安设备调试注意事项
- 本安电路限制可能影响信号质量
- 发送功率受限可能导致链路不稳定
- 需要关注CRC错误和信号衰减
- 对比本安/非本安模式下的差异

## 嵌入式调试专项

### 调试层次
```
应用层 → 中间件层 → 驱动层 → 硬件层
   ↓        ↓        ↓        ↓
业务逻辑   TFLM框架  设备驱动  芯片/外设
算法实现   算子实现   中断处理  寄存器
```

### 常见问题模式

#### 内存问题
- **现象**: 程序崩溃、结果异常
- **排查工具**: 内存检测、堆栈跟踪
- **常见原因**: 内存越界、栈溢出、内存泄漏

#### 性能问题
- **现象**: 推理速度慢、响应延迟
- **排查路径**: 算子耗时分析 → 内存访问模式 → 编译器优化
- **常见原因**: 未使用硬件加速、内存对齐问题、编译器优化不足

#### 模型部署问题
- **现象**: 模型加载失败、推理结果错误
- **排查路径**: 模型转换 → 量化验证 → 输入输出对比
- **常见原因**: 模型格式不兼容、量化精度损失、输入预处理不一致

## 常用调试技术

### 日志分析
- 按时间线梳理事件
- 关注异常和错误信息
- 对比正常和异常日志

### 抓包分析
- 使用Wireshark捕获网络包
- 分析协议交互流程
- 定位通信异常点

### 二分法定位
- 缩小问题范围
- 逐步逼近问题点
- 适用于大规模代码变更

### 对比分析
- 正常环境 vs 异常环境
- 旧版本 vs 新版本
- 不同配置对比

### 嵌入式开发调试
- 调试器: J-Link, ST-Link
- 逻辑分析仪
- 示波器

### 软件调试
- IDE调试器
- 性能分析工具
- 内存检测工具
