# Systematic Debugging Skill — 使用说明

## 基本信息
- **Skill名称**：systematic-debugging
- **来源**：alexanderop 的 TRAE Skill + PUA 调试部分，适配为 ContextStack 规则
- **规则类型**：manual（手动触发）
- **作用域**：项目级（ContextStack）
- **创建日期**：2026-05-13

## 功能描述
四阶段系统化调试流程，禁止猜测式修复。同一问题修3次仍失败触发架构质疑。

## 触发方式
当用户说"调试"/"排查问题"/"修bug"/"为什么报错"时激活。

## 执行流程
1. **Phase 1: 根因调查** — 收集信息、复现问题、定位边界、排除法
2. **Phase 2: 模式分析** — 检查同类问题、最近变更、边界条件、加诊断日志
3. **Phase 3: 假设测试** — 提出假设、设计最小验证实验、确认或推翻
4. **Phase 4: 实施修复** — 最小化修复、验证修复、回归测试、根因记录

## 压力升级机制
| 修复次数 | 行动 |
|----------|------|
| 1-2次 | 正常调试流程 |
| 3次失败 | 触发架构质疑：是否根本方案就有问题？ |
| 5次失败 | 强制暂停，输出完整诊断报告请求用户指导 |

## 适用场景
- TFLM 编译错误排查
- PowerShell/Python 脚本调试
- ContextStack 工具脚本排错
- 网络设备配置问题诊断

## 反模式
| 反模式 | 正确做法 |
|--------|----------|
| "可能是X问题，我改一下" | 先确认根因再改 |
| 同时改多处来"试试" | 每次只改一处验证 |
| 反复猜测式修复 | 3次失败后质疑思路 |
| 只修表面症状 | 找到根因并修复 |
