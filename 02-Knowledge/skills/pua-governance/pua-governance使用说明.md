# PUA Governance Skill — 使用说明

## 基本信息
- **Skill名称**：pua-governance
- **来源**：tanweai 的 TRAE Skill，适配为 ContextStack 规则
- **规则类型**：manual（手动触发）
- **作用域**：项目级（ContextStack）
- **创建日期**：2026-05-13

## 功能描述
高能动性治理，用结构化压力迫使 AI 穷尽式解决问题。三种方法论按任务类型匹配，附带强制检查清单和压力升级机制。

## 触发方式
- 用户说"严格检查"/"确保质量"/"穷尽分析"/"不要敷衍"时激活
- 关键交付物（学习考核、投资分析、重要代码）完成前自动建议使用

## 三种方法论

### 1. 调试类 → 华为RCA根因分析
- 连续问5个"为什么"找到根因
- 修复针对根因而非症状
- 必须有预防措施

### 2. 新功能/迭代类 → Musk五步法
- 质疑 → 删除 → 简化 → 加速 → 自动化
- 必须按顺序执行，不可跳步

### 3. 代码审查/精简类 → Jobs减法思维
- 对每个部分问：删掉它系统还能正常工作吗？
- 能删就删，不能删再问能否用更少代码实现

## 强制检查清单（提交"完成"声明前必须通过）
- [ ] 验证证据：是否提供了可验证的完成证据？
- [ ] 边界检查：是否测试了边界情况和异常输入？
- [ ] 无遗漏：是否完成了所有子任务？
- [ ] 无回归：修改是否没有破坏已有功能？

## 压力升级机制
| 级别 | 触发条件 | 行动 |
|------|----------|------|
| L1 | 无验证证据 | 要求补充验证 |
| L2 | 同一问题修2次未解决 | 换思路/换方案 |
| L3 | 同一问题修3次未解决 | 质疑架构/暂停请求用户决策 |
| L4 | 关键交付质量不达标 | 完整重做，不接受修补 |

## 适用场景
- 嵌入式AI学习考核（确保真学懂而非表面理解）
- 投资分析验证（确保数据有据可查）
- 关键代码交付（确保质量达标）
- 调试僵局突破（3次失败后强制换思路）
