# Karpathy 编码准则 — 使用说明

## 基本信息
- **Skill名称**：karpathy-guidelines
- **来源**：Andrej Karpathy 的 LLM 编码陷阱观察
- **规则类型**：always（每次对话自动生效）
- **作用域**：项目级（ContextStack）
- **创建日期**：2026-05-13

## 功能描述
基于 Karpathy 四原则约束 AI 编码行为，防止 LLM 编码中的常见陷阱。

## 四大核心原则
1. **先思考再编码**：收到需求先输出理解和方案，不直接写代码
2. **简洁优先（YAGNI）**：只实现当前需要的功能，不做过度抽象
3. **手术式修改**：只改必须改的，不顺手重构，diff 尽可能小
4. **目标驱动执行**：每行变更必须能追溯到用户请求

## 使用方式
- **自动生效**：无需手动触发，规则已设为 always 类型
- 每次编码/文件修改操作时，AI 会自动遵守四原则

## 适用场景
- 所有编码和文件修改操作
- 特别适用于：文件整理、代码编写、需求模糊时的确认

## 反模式警告
| 反模式 | 正确做法 |
|--------|----------|
| 拿到需求直接写代码 | 先输出理解和方案 |
| 一次改多个不相关的地方 | 分次、分区域修改 |
| "顺便"重构/优化 | 只做用户要求的 |
| 添加"以防万一"的功能 | 只做当前需要的 |

## 与其他 Skill 的关系
- 与 `brainstorming` 互补：karpathy 管编码纪律，brainstorming 管设计流程
- 与 `systematic-debugging` 互补：karpathy 管"怎么做"，debugging 管"怎么修"
