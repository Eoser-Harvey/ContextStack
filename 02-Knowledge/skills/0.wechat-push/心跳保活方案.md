# WeChat Bot 心跳保活方案

> 设计日期: 2026-06-18  
> 目标: 解决 mcp-wechat-server 会话断开导致推送失败的问题

---

## 一、问题根因

微信网页版 Bot 协议的固有限制：
- Bot 必须先收到用户消息，才能向该用户发送消息（被动回复模型）
- 会话空闲一段时间后（通常2-6小时），微信服务器会断开连接
- 断开后 `send_text_message` 仍返回 `sent`，但消息实际被丢弃
- 用户发一条消息即可重新激活通道，无需重新扫码

---

## 二、心跳保活架构

```
Automation 触发 (每小时)
  │
  ├─ 1. heartbeat.check_channel_alive()
  │     ├─ "active"   → 通道存活，直接推送
  │     ├─ "unknown"  → 发送测试消息验证
  │     │    ├─ 用户回复 → mark_active() → 推送
  │     │    └─ 无回复  → mark_failure()
  │     └─ "dead"     → 记录日志，等待下次
  │
  ├─ 2. 推送完成后 → mark_active() 更新时间戳
  │
  └─ 3. 状态持久化到 channel_state.json
```

---

## 三、状态机

```
        ┌─────────────┐
        │   unknown   │  ← 初始状态 / TTL过期
        └──────┬──────┘
               │
    测试消息发送，用户回复
               │
        ┌──────▼──────┐
        │   active    │  ← 正常推送
        └──┬──────┬──┘
           │      │
    TTL过期 │      │ 连续3次推送失败
           │      │
  ┌───────▼──┐ ┌─▼──────┐
  │ unknown  │ │  dead   │ ← 需用户发消息激活
  └──────────┘ └───┬────┘
                   │
            用户发消息激活
                   │
              ┌────▼────┐
              │ active  │
              └─────────┘
```

## 五、Automation 执行流程改造

每次 x-3 automation 触发时：

```python
# 伪代码
state = heartbeat.check_channel_alive()

if state == "active":
    # 正常推送
    push_messages()
    heartbeat.mark_active()

elif state == "unknown":
    # 先发测试消息
    send_test_message("通道检测 - 请回复任意内容")
    # 尝试读取用户回复（短超时，10秒）
    reply = wait_for_reply(timeout=10)
    if reply:
        heartbeat.mark_active()
        push_messages()
    else:
        heartbeat.mark_failure()
        log("通道可能断开，已跳过本次推送")

elif state == "dead":
    log("通道已断开超过3次，等待用户手动激活")
    # 不做任何推送
```

## 六、关键参数

| 参数 | 值 | 说明 |
|------|-----|------|
| CHANNEL_TTL_HOURS | 2 | 上次活跃超过2小时需重新验证 |
| MAX_FAILURES | 3 | 连续3次验证失败标记为dead |
| 测试消息超时 | 10秒 | 等待用户回复的时间 |

## 七、局限与兜底

**本方案不能解决的问题：**
- 微信强制要求 bot 重新扫码（大约7天一次）
- 二维码过期需要手动重新生成

**兜底方案（后续实现）：**
- Server酱 HTTP 推送作为备用通道
- 当 WeChat MCP 标记为 dead 时自动切换

## 九、保活进程架构（最终方案）

```
keepalive.py (独立进程，开机自启)
  │
  ├── init_session() → Bun → mcp-wechat-server → 微信服务器
  │
  └── 循环（每30秒）:
       ├── heartbeat() → get_messages(wait=false)
       ├── 成功 → update_state() → channel_state.json
       └── 连续3次失败 → 重建Bun会话
```

**关键原理**：每30秒调用 `get_messages` 保持与微信服务器的活跃连接，防止会话超时断开。
