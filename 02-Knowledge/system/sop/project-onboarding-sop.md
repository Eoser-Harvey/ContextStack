# 项目接入SOP

> Standard Operating Procedure for onboarding new projects into the ContextStack collaboration framework.

## 目的

确保新项目能够快速、规范地接入四层协作架构，实现高效协作和知识沉淀。

## 适用范围

所有需要长期跟踪和协作的技术项目，包括但不限于：
- 产品开发项目
- 技术研究项目
- 问题调试项目
- 学习计划项目

## 接入流程

### 阶段1：项目评估（1-2小时）

#### 1.1 项目信息收集
- **项目名称**：明确、简洁的名称
- **项目类型**：开发/研究/调试/学习
- **项目目标**：主要目标和期望成果
- **时间范围**：预计开始和结束时间
- **关键人员**：项目负责人和参与人员
- **现有资源**：文档、代码、工具等

#### 1.2 架构适配评估
- **是否需要项目规则**：确定是否需要创建项目级PROJECT-RULES.md
- **工作台类型**：确定使用项目/话题/任务工作台
- **知识分类**：确定需要创建的规范文档
- **记忆管理**：确定需要记录的Memory条目

#### 1.3 风险评估
- **技术风险**：技术难点和不确定性
- **协作风险**：跨团队协作的挑战
- **工具风险**：工具兼容性和学习成本
- **时间风险**：时间安排的合理性

### 阶段2：架构配置（2-4小时）

#### 2.1 目录结构创建
```bash
# 项目工作台目录
01-Projects/{project-name}/
├── {project-name}.md              # 主工作台
├── project-plan.md                # 项目计划（可选）
└── resources/                     # 项目资源（可选）

# 如果涉及多个子话题
01-Projects/topics/{topic-name}.md   # 话题工作台

# 如果需要任务跟踪
01-Projects/tasks/{task-name}.md     # 任务工作台
```

#### 2.2 规则文件创建
**项目规则文件**（如果需要）：
```markdown
# {项目名称}协作规则

## 项目概述
- **项目名称**: 
- **技术栈**: 
- **负责人**: 
- **时间范围**: 

## 目录结构
```
项目目录/
├── src/         # 源代码
├── docs/        # 文档
├── tests/       # 测试
└── tools/       # 工具脚本
```

## 项目规范
1. 代码审查要求
2. 测试覆盖率要求
3. 文档更新要求
4. 版本管理要求

## 产品红线
1. 不能修改的核心逻辑
2. 安全相关的要求
3. 性能相关的限制

## 领域知识
- 关键技术点
- 常见问题
- 最佳实践
```

#### 2.3 工作台初始化
**项目工作台模板**：
```markdown
# {项目名称}工作台

## 项目信息
- **项目名称**: 
- **项目路径**: 
- **负责人**: 
- **创建时间**: 
- **最后更新**: 
- **当前状态**: 

## 自动上下文加载
- **全局规则**: ./GLOBAL-RULES.md
- **项目规则**: {项目路径}/PROJECT-RULES.md（如果存在）
- **相关规范**:
  - 02-Knowledge/system/methodology/debug-methodology.md（需要调试时）
  - 02-Knowledge/system/sop/project-onboarding-sop.md（需要代码审查时）
- **记忆索引**: ./MEMORY.md

## 项目目标
项目的主要目标是什么？

## 任务列表
- [ ] 任务1
- [ ] 任务2
- [ ] 任务3

## 进度跟踪
跟踪任务完成情况和状态

## 资源
文档、工具和链接

## 切换命令
- Switch to {project-name}
- Save {project-name} workbench
- Restore {project-name} workbench
- End session

## 版本控制
- 当前版本：v1.0
- 版本历史：
  - v1.0 (YYYY-MM-DD)：初始版本
```

### 阶段3：知识整理（4-8小时）

#### 3.1 现有文档整理
- **文档分类**：按类型分类现有文档
- **格式统一**：统一文档格式和风格
- **内容优化**：优化文档内容和结构
- **链接更新**：更新文档间的引用链接

#### 3.2 规范文档创建
根据项目需要创建：
- **方法论文档**：项目特有的工作方法
- **SOP文档**：标准操作流程
- **模板文档**：常用文档模板
- **调研框架**：技术调研方法

#### 3.3 工具配置
- **开发工具**：配置必要的开发环境
- **调试工具**：配置调试和分析工具
- **协作工具**：配置团队协作工具
- **监控工具**：配置项目监控工具

### 阶段4：协作启动（1-2小时）

#### 4.1 团队沟通
- **项目介绍**：介绍项目目标和计划
- **协作规则**：说明协作规则和流程
- **工具培训**：培训必要的工具使用
- **角色分工**：明确团队成员的角色

#### 4.2 工作台激活
- **工作台验证**：验证工作台功能正常
- **规则加载测试**：测试规则加载机制
- **记忆更新**：更新Memory索引
- **会话历史**：创建初始会话历史

#### 4.3 监控设置
- **进度监控**：设置进度监控机制
- **质量监控**：设置质量监控指标
- **风险监控**：设置风险监控点
- **知识沉淀**：设置知识沉淀流程

## 常见问题

### Q1：项目类型不确定如何选择工作台？
- **开发项目**：使用项目工作台，创建项目规则
- **研究话题**：使用话题工作台，按需加载规范
- **调试任务**：使用任务工作台，聚焦具体问题
- **学习计划**：使用项目工作台，跟踪学习进度

### Q2：现有项目如何迁移？
1. **评估阶段**：评估现有项目的状态和需求
2. **规划阶段**：制定迁移计划和风险控制
3. **执行阶段**：按阶段迁移，保持业务连续性
4. **验证阶段**：验证迁移效果，优化不足

### Q3：多人协作如何管理？
1. **角色分工**：明确每个人的角色和职责
2. **工作台分配**：根据需要分配不同类型的工作台
3. **同步机制**：建立定期同步和沟通机制
4. **冲突解决**：制定冲突解决流程和规则
