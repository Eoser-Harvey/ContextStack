# PROJECT-RULES.md 项目规则模板

> 用于创建项目级协作规则的模板文件

## 使用说明

1. 将此模板复制到项目根目录，重命名为 `PROJECT-RULES.md`
2. 根据项目实际情况填写各部分内容
3. 确保规则符合全局规则 (`D:\MyFile\AI\ContextStack\GLOBAL-RULES.md`)
4. 将编写好的规则文件路径更新到项目工作台的"自动上下文加载"部分

## 目录结构规范

### 标准目录结构
```
{项目根目录}/
├── src/                    # 源代码
│   ├── core/              # 核心模块
│   ├── utils/             # 工具函数
│   └── tests/             # 单元测试
├── docs/                  # 文档
│   ├── design/           # 设计文档
│   ├── api/              # API文档
│   └── user-guide/       # 用户指南
├── tests/                 # 测试文件
│   ├── unit/             # 单元测试
│   ├── integration/      # 集成测试
│   └── performance/      # 性能测试
├── tools/                 # 工具脚本
│   ├── build/            # 构建脚本
│   ├── deploy/           # 部署脚本
│   └── analysis/         # 分析工具
├── config/                # 配置文件
│   ├── dev/              # 开发环境
│   ├── test/             # 测试环境
│   └── prod/             # 生产环境
└── resources/             # 资源文件
    ├── data/             # 测试数据
    ├── images/           # 图片资源
    └── templates/        # 模板文件
```

### 文件命名规范
- **源代码文件**: 使用小写字母，单词间用下划线分隔，如 `module_name.c`
- **头文件**: 使用小写字母，单词间用下划线分隔，如 `module_name.h`
- **文档文件**: 使用中划线分隔，如 `api-reference.md`
- **配置文件**: 使用点分隔，如 `config.dev.yaml`

### 编码规范
- **缩进**: 使用4个空格，禁止使用制表符
- **行宽**: 不超过80个字符（注释不超过72个字符）
- **命名**:
  - 变量和函数: `snake_case`
  - 常量: `UPPER_SNAKE_CASE`
  - 类型: `PascalCase`
- **注释**:
  - 文件头注释包含版权和描述
  - 函数注释说明功能、参数和返回值
  - 复杂逻辑添加行内注释

## 项目规范

### 1. 代码质量要求
- 所有代码必须通过静态代码分析
- 关键函数必须有单元测试，覆盖率不低于80%
- 代码提交前必须通过代码审查
- 禁止提交调试代码和临时文件

### 2. 文档要求
- 每个模块必须有README文档
- API变更必须更新API文档
- 设计决策必须记录在决策日志中
- 用户可见的功能必须有用户文档

### 3. 版本管理
- 使用语义化版本控制 (SemVer)
- 每次提交必须有明确的提交信息
- 特性分支必须从main分支创建
- 合并请求必须有至少一个审查者

### 4. 测试要求
- 单元测试必须覆盖核心功能
- 集成测试必须覆盖模块间交互
- 性能测试必须满足性能指标
- 安全测试必须通过安全扫描

### 5. 部署要求
- 部署前必须通过所有测试
- 生产环境部署必须有回滚计划
- 配置变更必须记录和审批
- 监控和日志必须配置完整
