```
【工业协议与底层驱动】CAN/CAN FD、Modbus、IEC 61850、环网（故障收敛 ≤20ms）；
```

### 2. 高端电能质量分析仪项目（补 DSP 王牌，最致命的一条）

**❌ 改前**（功能罗列，DSP 一个字没提）：
> 主要负责 DSP 的驱动开发、RTOS 移植、计量算法实现、应用功能详细设计与实现。此项目实现了基本电参量计量、电能质量分析、实时监控等功能，以及系统的界面显示、网页显示、生成报表、数据导出等功能，还有 Modbus 和 CAN 总线工业级标准协议、IEC 61850 电网标准协议等接入功能。

**✅ 改后**（标题加 DSP 标签，正文全是 DSP 难点 + 数据）：
```
高端电能质量分析仪（DSP 信号处理，ADI SC573 双 SHARC DSP + ARM Cortex-A5）2020.08-2022.12

【DSP 信号处理与实时控制】
- DSP 算法：FFT 谐波分析（Hanning 加窗防频谱泄漏）、闪变测量（IEC 61000-4-15
  标准 IIR 滤波器组）、工频提取、插值重采样
- 性能优化：SHARC 硬件 FIR/IIR/FFT 加速器（单周期 MAC + DAG 循环缓冲）+ 汇编优化
  + ICache/DCache 优化（双核伪共享 64 字节对齐，性能提升 40%）
- 高精度采样：多通道 ADC + DMA 双缓冲 + 三级优先级调度，采样抖动 ±15us→±2us（降 90%）
- 异构架构：双 SHARC + Cortex-A5 AMP，DSP 跑 RTOS、A5 跑 Linux，
  中断驱动 + 共享内存跨核通信 ≤10ms
- 工业协议接入：Modbus、CAN、IEC 61850 电网标准
```

### 3. TSN 交换机项目（降级 + 明确角色，避免被当协议专家戳穿）

**❌ 改前**（排第 1，写满协议栈细节，会被深挖）：
> 此项目是基于 Marvell DX1516M + PHY 的 Linux 系统平台产品…完整支持了 TSN 协议集…802.1Qbv、802.1AS、802.1Qbu、802.1CB 协议集协同平台开发…

**✅ 改后**（压缩 + 写明角色是「驱动 + 集成」不是「协议栈」）：
```
新一代 TSN 时间敏感网络交换机 2025.06-至今

- 角色：PL + 底层驱动 + 集成（TSN 协议栈核心由驱动/平台团队负责）
- 负责 SyncE、CAN、RS485、PoE、PHY 底层驱动开发
- 工业协议开发：环网（故障收敛 ≤20ms）、Modbus、CAN 总线
- TSN 802.1Qbv/AS/Qbu/CB 协议集协同集成
- PL 管理软件团队，协调测试/软件平台/ODM 高质量推进项目
```

**关键**：加「角色：协议栈核心由驱动/平台团队负责」——诚实地把自己从「TSN 协议专家」降级为「做产品 + 驱动 + 集成」，面试官就不会拿协议栈细节戳你。

### 4. DSP 产品平台项目（保留，但作为「电能质量分析仪」的补充，别让它抢了正主）

**说明**：这个 3 个月的项目里有 FFT/均方根/滤波/插值/汇编/伪共享 40%/ROM 5KB，内容不错。但它只有 3 个月，是「技术储备」。**DSP 的实战深度要放在 2 年的电能质量分析仪里（见第 2 条）**，这个项目保留作为「DSP 平台化 + 性能优化」的补充即可，不用大改。

### 5. 项目排序建议

**不打乱时间倒序**（简历惯例，乱序 HR 会困惑），但用两个办法让 DSP 王牌不被埋没：
1. **个人简介置顶 DSP 王牌**（见第 1 条）——面试官先看简介就记住「DSP + 自研 RTOS」
2. **电能质量分析仪标题加「DSP 信号处理」标签**（见第 2 条）——即使排第 4，标题也亮出王牌
3. **TSN 写明角色**（见第 3 条）——即使排第 1，也不会被当协议专家戳

## 三、隐性筛选（不写弱项，只突出强项）

**原则：简历不主动写「我不擅长 X」，而是「只写强项、弱项不写」**，让强项吸引对口岗位。

| 弱项（不写 / 弱化） | 原因 |
|:--|:--|
| 端侧 AI | 学习水平，千寻已戳穿，删掉 |
| Linux BSP / 内核 / USB 驱动 | 不深，TSN 项目里弱化「Linux 平台」表述 |
| FPGA / C++ 量产 | 空白，不写 |
| TSN 协议栈 | 虚标签，写明「驱动 + 集成」角色 |

**效果**：简历只吸引「DSP 信号处理 / RTOS 底层 / 工业协议」对口的岗位，减少被拉去面 Linux/FPGA/C++ 不对口岗位的概率（根因 1 岗位错位的简历层解法）。
