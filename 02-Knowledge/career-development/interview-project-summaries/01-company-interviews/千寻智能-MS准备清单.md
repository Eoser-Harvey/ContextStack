## 四、能力匹配矩阵（策略定调：聚焦 MCU/RTOS，不补 Linux）

**用户决策（2026-08-28 定）**：只把 MCU 底层驱动 + RTOS 准备到极致，不熟悉的一律不碰（Linux/FOC/EtherCAT/IMU 都不补）。

| 判断       | 结论                                                                 |
|:-----------|:---------------------------------------------------------------------|
| 策略正确性 | ✅ 务实——半吊子补 Linux 比不补更危险；把强项做到极致是「确定性」准备    |
| 岗位刚需   | ✅ 具身智能真正缺的是「实时控制底层」人才，MCU/RTOS/TSN 是硬需求        |
| 残余风险   | ⚠️ 投的是 Linux BSP 岗，若MS官严格按 JD 考 Linux 会挂              |
| 破解       | 🎯 开场/反问主动锁强项区 + 备好「Linux 经验少，凭什么胜任」必答题     |

**千寻嵌入式分两层（你定位在下层，只打这一层）**：

| 层        | 硬件       | 跑什么         | 职责                 | 策略     |
|:----------|:-----------|:---------------|:---------------------|:---------|
| 上层域控板 | RK/NXP SoC | Linux + ROS    | 定位/算力/传感器融合 | ❌ 不碰  |
| 下层关节   | MCU        | RTOS           | 电机/实时闭环        | ✅ 极致准备 |

**匹配矩阵（聚焦版）**：

| 域               | 匹配度  | 说明                             |
|:-----------------|:-------:|:---------------------------------|
| TSN / gPTP       | ✅⭐ S级 | 全场最大差异化王牌               |
| RTOS 内核机制    | ✅       | 自研 RTOS，可深挖                 |
| MCU 底层驱动     | ✅       | 8 年驱动开发                      |
| CAN / CAN FD     | ✅       | 强项                             |
| C 语言底层       | ✅       | 但历史挂点（启动汇编/Boot跳转）需复盘 |
| 量产可靠性       | ✅       | 8 年量产工程化                    |
| Linux BSP        | ❌ 放弃  | 用户决策不补                      |

**一句话定位（最终版）**：**「8 年工业量产经验、自研 RTOS、精通 TSN 六协议的底层工程师」**。MS全程围绕「实时性 + 底层 + 量产」三根柱子打，TSN 是进攻矛头，量产是兜底信用，Linux 空白坦诚带过、一句话切换到强项。

## 五、技术MS准备（六大域，聚焦 MCU/RTOS 极致）

> 每个域都要达到「本质→实践→坑→思考」四层能脱口而出，且**有真实项目数据背书**。宁可只精 6 个域，不贪 20 个面。

### 域 1｜RTOS 内核机制（最高频，必达极致）

| 考点               | 打磨点                                       | 项目背书                 |
|:-------------------|:---------------------------------------------|:-------------------------|
| 优先级反转         | 成因 + 优先级继承/天花板协议                  | 自研 RTOS 的互斥锁实现   |
| 中断延迟/嵌套      | 关中断 vs 调度锁；临界区                      | 实测中断延迟数据         |
| 同步原语           | 信号量/互斥锁/消息队列/事件组的适用场景        | 自研 RTOS 的 IPC 设计    |
| 内存管理           | 内存池、栈溢出检测、MPU 保护                  | 自研 RTOS 的内存池优化   |
| 死锁               | 四个必要条件 + 预防                           | 实际调试过的死锁案例     |

**核心叙事**：为什么自研 RTOS（不是 FreeRTOS）？解决了什么 FreeRTOS 解决不了的问题？和 FreeRTOS/RT-Thread 对比的优劣势？

### 域 2｜MCU 启动与中断底层

| 考点           | 打磨点                                   |
|:---------------|:-----------------------------------------|
| 上电启动全流程 | 向量表→复位→时钟→初始化（你熟，但要说透）|
| NVIC 中断控制器| 优先级分组、抢占/子优先级、嵌套          |
| 时钟树/低功耗  | 时钟源切换、睡眠/停机/待机模式           |

### 域 3｜外设驱动 + DMA

| 考点        | 打磨点                                           |
|:------------|:-------------------------------------------------|
| UART/SPI/I2C/CAN | 各自时序、中断 vs DMA 收发、半双工坑           |
| DMA         | 双缓冲、缓存一致性、对齐限制、环状 vs 链式传输   |
| 驱动分层    | 硬件抽象层 HAL / 寄存器操作 / 位操作 / volatile  |

### 域 4｜C 语言底层（历史挂点，重点复盘）

| 考点          | 来源教训         |
|:--------------|:-----------------|
| 启动汇编      | 加速进化挂点     |
| Boot/App 跳转 | 加速进化挂点     |
| volatile/内存对齐/结构体/指针 | 高频     |
| 栈/堆/内存模型 | 高频             |

### 域 5｜TSN 六协议（S 级王牌，重点打磨到能讲 15 分钟）

| 协议         | 作用                     | 你要能讲出的关键点           |
|:-------------|:-------------------------|:-----------------------------|
| 802.1AS gPTP | 时间同步                 | 主从时钟、BMCA 选主、时钟偏差 |
| 802.1Qbv     | 时间感知调度             | 门控列表、保护带             |
| 802.1Qbu/br  | 帧抢占                   | 高优先级打断低优先级         |
| 802.1CB      | 冗余                     | 无缝冗余、序列号去重         |

**杀手锏话术**：「机器人域控板 + 多关节 MCU 之间，我用 gPTP 做时钟同步、Qbv 做确定性调度，保证控制指令的端到端延迟有界——这正是人形机器人实时控制最需要的确定性通信。」

### 域 6｜实时性与量产可靠性（叙事，兜底信用）

| 考点           | 打磨点                                       |
|:---------------|:---------------------------------------------|
| 实时系统确定性 | 如何证明端到端延迟有界                       |
| 偶发死机排查   | 分层定位方法论（你真实的消防/工业案例）      |
| 量产工程化     | 一致性、可靠性测试、缺陷闭环                 |

### ⭐ 必答题（策略成立的关键，务必背熟）

> **问**：「你 Linux 经验不多，这个岗是 Linux BSP，你怎么看？」
> **答**：「我的核心能力是实时系统和底层驱动，这部分在 MCU 和 Linux 上是相通的——中断、调度、内存、驱动抽象层的原理是一样的，区别只是 Linux 多了一层 platform bus + device tree 的框架。我 8 年自研 RTOS + 量产的经验，迁移到 Linux BSP 比反过来（Linux 熟但没做过实时系统）要快。而且岗位列了 TSN/gPTP，这正是我的强项——实时确定性通信在 Linux 上反而更难做，我的裸机/RTOS 底子是加分项。」

## 七、反问问题（MS时问，体现深度）

1. 实时控制/嵌入式团队现在多少人？分工是「关节控制 / 传感器 / 整机系统」怎么划的？
2. 关节电机驱动器是自研还是采购？实时控制跑在哪个 RTOS（RT-Thread / FreeRTOS / 自研）上？
3. 关节之间用 EtherCAT 还是 CAN FD？分布式时钟同步怎么保证的？
4. Spirit 模型在机器人上是云端推理还是端侧部署？端侧 AI（TFLM/NPU）在你们产品里是什么角色？
5. 具身大脑的「端侧化」是你们下一步的方向吗？（呼应你的 TFLM 差异化优势）
