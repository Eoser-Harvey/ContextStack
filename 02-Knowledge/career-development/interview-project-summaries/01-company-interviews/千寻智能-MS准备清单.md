## 五、⭐ 第一轮技术面试：结构预判 + 项目深挖押题

> 具身智能公司嵌入式岗第一轮 = 技术（约 1 小时），典型 5 段。

| 阶段 | 内容 | 时长 | 你的风险点 |
|:-----|:-----|:----:|:-----------|
| 1 自我介绍 | 2 分钟，结论先行 | 2min | 标签数据说错（见第六节） |
| 2 项目深挖 | 自研 RTOS 必被深挖 | 25min | 知识复述、数据经不起追问 |
| 3 C 语言手撕 | strcpy/链表/环形缓冲/二分 | 15min | **历史挂点**，看答案≠会写 |
| 4 RTOS/底层高频题 | 优先级反转/调度/低功耗 | 10min | 只答"是什么"，不答"为什么+坑" |
| 5 反问 | 体现深度 | 5min | 见第九节，照用 |

### 项目深挖必考 5 连问（每个都用「本质→实践→坑→思考」过一遍，录音回听）

1. **为什么自研 RTOS，不用 FreeRTOS？** FreeRTOS 解决不了你什么问题？
2. **内核资源占用具体多少？怎么算出来的？**（→ 引出第六节数据一致性，这是翻车点）
3. **优先级反转怎么解决的？你实际踩过什么坑？**（杀手级素材：关中断 1.2ms → UART FIFO 溢出丢包）
4. **任务切换延迟怎么测的？**（→ 若标签写了 <1us，必须能答测量方法）
5. **量产怎么保证可靠性？偶发死机怎么定位？**（消防/工业案例 + 分层定位方法论）

## 七、技术MS准备（六大域，聚焦 MCU/RTOS 极致）

> 每个域都要达到「本质→实践→坑→思考」四层能脱口而出，且**有真实项目数据背书**。宁可只精 6 个域，不贪 20 个面。

### 🎯 核心武器（每次回答的骨架，务必刻进脑子）

**1. 一句话技术标签（自我介绍第一句 / 每次被问项目先说这句）**：

> 「从零到一自研轻量级 RTOS，跨 ARM M4 和 DSP 双平台：内核 ROM 仅 5KB(M4)/10KB(DSP)，静态 RAM 1.3KB/2.6KB，比 FreeRTOS 创建 32 任务至少省 17KB，支持 Tickless 低功耗 + 优先级继承。」（⚠️ 任务切换延迟、量产规模两个数字见第六节核实后再填）

**2. 四步回答法（所有技术问题的统一模板，拒绝知识复述）**：

```text
问题本质（一句话点透）→ 我的实践（真实项目+数据）→ 踩过的坑（区分点）→ 我的思考（升华）
```

**3. 自研 RTOS 是最强锚点**——任何问题都往它上面引（历史经验库经验 3）：

| 被问什么   | 往哪引（真实数据）                                             |
|:-----------|:---------------------------------------------------------------|
| 编译优化   | 「内核用 Os 控 8KB，调度器 O2，浮点 O3 向量化」                  |
| 优先级反转 | 「实现优先级继承，但发现链式反转，改消息队列规避」               |
| 低功耗     | 「原生 Tickless，基于 LPTIM，待机<10uA」                         |
| Cache 问题 | 「双核伪共享致性能降 40%，64 字节对齐解决」                      |

### 域 1｜RTOS 内核机制（最高频，必达极致）

| 考点               | 打磨点                                       | 项目背书                 |
|:-------------------|:---------------------------------------------|:-------------------------|
| 优先级反转         | 成因 + 优先级继承/天花板协议                  | 自研 RTOS 的互斥锁实现   |
| 中断延迟/嵌套      | 关中断 vs 调度锁；临界区                      | 实测中断延迟数据         |
| 同步原语           | 信号量/互斥锁/消息队列/事件组的适用场景        | 自研 RTOS 的 IPC 设计    |
| 内存管理           | 内存池、栈溢出检测、MPU 保护                  | 自研 RTOS 的内存池优化   |
| 死锁               | 四个必要条件 + 预防                           | 实际调试过的死锁案例     |

**核心叙事**：为什么自研 RTOS（不是 FreeRTOS）？解决了什么 FreeRTOS 解决不了的问题？和 FreeRTOS/RT-Thread 对比的优劣势？

### 域 2｜MCU 启动与中断底层

| 考点           | 打磨点                                   |
|:---------------|:-----------------------------------------|
| 上电启动全流程 | 向量表→复位→时钟→初始化（你熟，但要说透）|
| NVIC 中断控制器| 优先级分组、抢占/子优先级、嵌套          |
| 时钟树/低功耗  | 时钟源切换、睡眠/停机/待机模式           |

### 域 3｜外设驱动 + DMA

| 考点        | 打磨点                                           |
|:------------|:-------------------------------------------------|
| UART/SPI/I2C/CAN | 各自时序、中断 vs DMA 收发、半双工坑           |
| DMA         | 双缓冲、缓存一致性、对齐限制、环状 vs 链式传输   |
| 驱动分层    | 硬件抽象层 HAL / 寄存器操作 / 位操作 / volatile  |

**🔑 实战话术（真实数据）**：
- CAN FD：「双波特率精细化位时序校准，把总线负载从 70% 降到 20%+，大幅提升多节点通信稳定性」
- ADC 采样：「三级优先级（采样5>通信3>显示1）+ DMA 双缓冲 + 环形缓冲，采样抖动从 ±15us 降到 ±2us」
- 半双工坑：「RS485 方向切换时延，用定时器精确控制发送完成→切换接收」

### 域 4｜C 语言底层（历史挂点 + 手撕代码，重点复盘）

| 考点          | 来源教训         |
|:--------------|:-----------------|
| 启动汇编      | 加速进化挂点     |
| Boot/App 跳转 | 加速进化挂点     |
| volatile/内存对齐/结构体/指针 | 高频     |
| 栈/堆/内存模型 | 高频             |

**🔑 实战话术（真实数据）**：
- GCC -O3 的坑：「延时循环被 -O3 优化掉，导致外部芯片时序不满足，最后用 `__asm__ volatile` 内存屏障解决」——这是「工程化深度」的直接证据
- volatile 三场景 + 三误解：「不等于原子性、不等于线程安全、不等于内存屏障」（历史经验库经验 5）
- const volatile：「只读硬件状态寄存器」这个组合场景要能脱口而出

> ⚠️ **标签兑现风险**：若 gPTP（主从时钟/BMCA/链路延迟）、Qbv（门控列表）、Qbu（帧抢占）、CB（序列号去重）各只能讲一句话，就把定位从「精通六协议」降级为「做过 TSN 交换机底层、熟悉确定性调度思想」。坦诚比硬撑重要——标签打得越响，深挖越狠。

### 域 6｜实时性与量产可靠性（叙事，兜底信用）

| 考点           | 打磨点                                       |
|:---------------|:---------------------------------------------|
| 实时系统确定性 | 如何证明端到端延迟有界                       |
| 偶发死机排查   | 分层定位方法论（你真实的消防/工业案例）      |
| 量产工程化     | 一致性、可靠性测试、缺陷闭环                 |

### ⭐ 必答题（策略成立的关键，务必背熟）

> **问**：「你 Linux 经验不多，这个岗是 Linux BSP，你怎么看？」
> **答**：「我的核心能力是实时系统和底层驱动，这部分在 MCU 和 Linux 上是相通的——中断、调度、内存、驱动抽象层的原理一样，区别只是 Linux 多了一层 platform bus + device tree 框架。我 8 年从零到一自研 RTOS，这种底层功底迁移到 Linux BSP 比反过来（Linux 熟但没做过实时系统）要快。而且岗位列了 TSN/gPTP，这正是我的强项——实时确定性通信在 Linux 上反而更难做，我的裸机/RTOS 底子是加分项。我要做的不是『Linux 小白』，是『带着实时系统和量产经验来做 Linux BSP』。」
