### 3.2 OTA 升级（差异化杀招，别人讲不清你能讲全）

> JD 明确点名 OTA，这是你能拉开差距的地方。完整链路要能脱口：

| 环节 | 关键点 |
|:-----|:-------|
| **分片传输** | 升级包拆固定长度分片，逐帧传输 |
| **断点续传** | 中断后从断点继续，不重头传 |
| **双分区 A/B** | 升级写备用分区，校验成功才切换，失败自动回滚，**绝不量产变砖** |
| **校验 + 签名** | CRC 校验 + 固件签名防篡改/防错包 |
| **断电回滚** | 升级标志放 **no-init RAM**（软复位不清零），断电重启能识别「升级到一半」并回滚 |
| **批量升级** | 产线一拖多节点同时升级，进度监控 + 失败重试 |

**完整流程（被深挖时展开讲）**：

**① 分片 + 序号**：固件包拆固定大小分片（如 1KB），每片带序号（0~N），"传到哪"用"第几片"精确定位。

**② 断点续传实现**：
- 进度持久化：从机每收一片写 Flash 后，把"已收分片序号"存 **no-init RAM**（软复位不清零）或 Flash 固定区——进度丢了只能重头传，所以必须持久化
- 分片校验：每片带 CRC，校验失败**只重传该片**，不重传全部
- 中断恢复：断线/断电后重连，主机**先查从机进度**（"收到第几片了"），从"最后一个成功分片的下一个"继续传

**③ A/B 双分区 + 校验签名**：升级包完整写入备用分区（B 区），CRC + 签名校验**全部成功才切换启动分区**；失败则回滚 A 区，**绝不量产变砖**。

**④ 断电回滚**：升级标志放 no-init RAM，断电重启识别"升级到一半"，自动回滚旧分区。

**完整时序**：
```
主机（上位机）                    从机（设备）
  ├─发起升级，告知大小/分片数──────→│
  │←──回复当前进度（已收第K片）──────│   ← 断点续传关键：先查进度
  ├─发第K+1片（带CRC）────────────→│
  │←─校验通过，写Flash，进度K+1─────│
  │         ⋯断线/断电中断⋯          │
  ├─重连，再查进度────────────────→│
  │←──回复"已收第K+1片"────────────│
  ├─从第K+2片续传（不重头）───────→│
  │         ⋯全部传完⋯              │
  ├─CRC+签名整体校验──────────────→│
  │←──校验通过，切换B区启动─────────│
```

**MS 话术**：
> 「OTA 我做过 CAN 总线多节点升级，核心是 A/B 双分区 + 升级标志放 no-init RAM——升级写备用分区，校验签名成功才切换；升级到一半断电，重启时靠 no-init RAM 里的标志识别『半成品』自动回滚到旧分区，保证量产设备永不砖。批量升级一拖多，失败自动重试。」

### 3.5 电机调试（加分项，基础即可，别硬撑）

> ⚠️ 诚实定位：电机精细调参不是你的日常方向，但有机器人比赛早期经验（2015 机器人大赛冠军）+ 闭环控制框架熟。答「驱动层和闭环框架熟，精细调参少」，别装专家。

| 电机 | 要能讲的基础 |
|:-----|:-------------|
| **直流电机** | PWM 调速 + 方向控制（H 桥）+ 编码器反馈 + 速度闭环 PID |
| **步进电机** | 细分驱动 + 加减速曲线（梯形/S 形）+ 失步检测 |

**原理速记（被问原理时展开，别只背表格）**：

**直流电机**：通电线圈在磁场受安培力转动，换向器保证力矩方向不变。转速 ∝ 电压，所以用 PWM 调平均电压调速；H 桥（4 个 MOSFET）控制正反转/制动。三层：PWM 调速（开环）→ H 桥换向 → 编码器 + PID 闭环。工程点：PWM >20kHz 防啸叫、H 桥死区防直通、高性能用电流环（转矩）+速度环双闭环。

**步进电机**：给一个脉冲转一个固定角度（步距角 = 360°/(齿数×相数)，常见 1.8° = 200 步/圈）。**开环定位**——脉冲数=位置，不用编码器。MCU 只发 STEP/DIR/EN 给驱动器（A4988/DRV8825/TMC2209），驱动器内部处理换相和电流细分。关键三概念：细分（正弦电流细分，提高分辨率减振动）、失步（负载大/加速快→转子跟不上→丢步）、加减速曲线（梯形/S 形防失步）。高速转矩下降原因：反电动势增大 + 绕组电感限制电流上升速度。

**两者对比（一句话收尾）**：直流电机**调电压（PWM）控制转速**，定位靠编码器闭环；步进电机**发脉冲控制位置**，开环精确走步，但高速转矩下降、会失步。

**MS 话术（诚实 + 迁移）**：
> 「直流电机的 PWM 调速、方向控制、编码器反馈闭环，这些驱动层和控制框架我很熟；步进电机的细分和加减速曲线原理清楚。精细的电机调参不是我日常主攻方向，但『PWM + 编码器 + 闭环』这套底层和我的 DSP/控制功底是相通的，上手会很快。」

### 3.7 算法性能提升（三层方法论，被问「怎么优化性能」直接答）

> MCU 岗性能优化是高频考点。按三层答，每层都结合真实项目。

**第一层｜编程设计（软件层，最基础最常用）**

| 手段 | 原理 | 我的实战 |
|:-----|:-----|:---------|
| **定点数**（整数替代浮点 + 扩大倍数） | 无 FPU 的 MCU 算浮点要软件模拟几十~上百周期；用整数放大倍数表示小数（`q = x × 2^n`），算完右移还原，精度可控 | TFLM 量化：`scale × 2^31` 存成 `scale_multiplier`，`acc × scale_multiplier >> 31` 模拟浮点除法，全程整数 |
| **移位替代乘除** | 乘/除 2^n = 左/右移 n 位（单周期）；Cortex-M0/M3 无硬件除法，M4+ 才有（2~12 周期） | 定点数的 `>> shift` 就是移位替代除法 |
| **汇编替代 C** | 关键循环用汇编，利用专用指令（单周期 MAC、循环寻址、并行搬运） | SHARC DSP 上 FFT/滤波用汇编 + 硬件加速器，效率翻倍 |
| **查表替代计算** | 复杂计算（CRC/sin/exp）预先算好存表，运行时直接查，O(1) | Modbus 的 **CRC16 查表法**；TFLM Softmax 的 exp 查表 |

**第二层｜芯片架构（访存层，最易忽略但影响大）**

| 手段 | 原理 | 我的实战 |
|:-----|:-----|:---------|
| **结构体对齐** | 未对齐 32 位访问在 ARM 外设总线 → HardFault；对齐减少跨字访问 | 非对齐访问 HardFault（嵌入式基础） |
| **提高缓存命中** | 顺序访问命中率高，跳跃访问 cache miss 频繁 | MLP 顺序读 vs CNN 滑窗跳跃（端侧 AI 项目） |
| **缓存行对齐** | 多核数据落同一 Cache 行 → 伪共享 → 互相失效 | 双核伪共享性能降 40%，**64 字节对齐解决** |

**第三层｜芯片资源（硬件加速层，白嫖的算力）**

| 手段 | 原理 | 我的实战 |
|:-----|:-----|:---------|
| **FPU 浮点加速** | 硬件浮点单元，单周期浮点运算 | — |
| **向量加速（SIMD/Helium）** | 一条指令算多个数据（如 4 个 int8） | CMSIS-NN 的 Helium SIMD（端侧 AI） |
| **DMA** | 数据搬运不占 CPU，CPU 做别的 | DMA 链式传输 **CPU 负载 90%→47%** |
| **Cache** | ICache/DCache 缓存加速 | ICache/DCache 驱动产品化 |

**MS 话术（一段话收尾）**：
> 「性能优化我按三层看：软件层用定点数替代浮点、移位替代乘除、查表替代计算——比如 Modbus 的 CRC16 用查表、TFLM 量化用 `scale×2^31` 定点数模拟除法；架构层关注结构体对齐和缓存命中，踩过双核伪共享降 40% 的坑，用 64 字节对齐解决；资源层白嫖硬件——DMA 搬运把 CPU 负载从 90% 降到 47%，SHARC 的浮点/向量加速器加汇编优化。核心思路是『先软件省算力，再架构提命中，最后硬件白嫖』。」

### 3.7.1 标准面试题：算法跑不满 CPU / 延迟很高，怎么分析优化？

> 这道题比上面「三层」更细，面试官爱追问「具体怎么排查」。按五维答，最后用 35% 实例收尾。

**五维排查框架**：

| 维度 | 排查点 |
|:-----|:-------|
| **① 算法本身** | 查复杂度；循环/分支优化（**查表法代替条件判断**）；消除冗余计算（常量提前算、合并重复操作） |
| **② 代码实现** | 循环展开、减少循环内分支；**指针直接操作减少 memcpy**；向量指令 / 编译器自动向量化 |
| **③ 内存访问** | 查缓存命中率，调数据结构 + 访问顺序提升**局部性**；内存池/静态数组代替 malloc/free 防碎片 |
| **④ 系统调度** | 任务/线程优先级，避免被低优先级抢占；**多核线程亲和性绑核**，减少上下文切换 |
| **⑤ 硬件特性** | DSP 向量指令；开 O2/O3 优化（⚠️ 注意避免优化导致的逻辑错误，如延时循环被优化掉） |

**多核绑核的深层解释（⭐ 面试官爱深挖，讲清本质）**：
> 多核下绑定线程到指定核心，本质是让线程「**独占核心 + 锁住 Cache**」——既砍掉上下文切换的算力浪费，又让算法指令和数据常驻高速缓存，同时避免多核资源争抢，最终让 CPU 算力完全释放给算法。既提升运行速度，又保证实时稳定性，是高并发、计算密集型场景的标准优化手段。

**加分话术（结合岗位，必背，35% 实例）**：
> 「我之前做工业数据处理算法就是按这个思路排查的：①原来循环里有很多分支判断，改成**查表法**后分支预测失败率大幅降低；②加上**循环展开和缓存局部性优化**，整体性能提升了 **35%**。这个思路完全可以用在算法移植到 DSP 平台的优化上。」

## 四、自我介绍（定制，1.5-2 分钟）

> 「MS 官您好，我叫韩伟，9 年工业级嵌入式开发，一直深耕 MCU 底层和实时系统。

### 7.4 高频场景题（记思路，别背答案）

1. **OTA 中途断电如何防变砖** → A/B 双分区 + 校验标记 + 自动回滚
