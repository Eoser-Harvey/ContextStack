## 三、⭐ 核心突击：控制算法三件套

> JD 明确点名 PID / 状态机 / 滤波器，是你相对薄弱的环节，但**滤波器你有真实项目背书**。三件套按「原理 → 激光场景 → 我的项目 → 追问」准备。

### 3.1 PID 控制

**原理（三句话）**：
- **P（比例）**：误差 × Kp，快速响应，但只有 P 有稳态误差
- **I（积分）**：误差累积 × Ki，消除稳态误差，但会超调/积分饱和
- **D（微分）**：误差变化率 × Kd，抑制超调、增加阻尼，但放大噪声

**组合选择（⭐ 面试高频：什么场景用什么组合）**：

| 组合 | 适用场景 | 为什么 |
|------|---------|--------|
| P（纯比例） | 允许静差、要求简单 | 最稳定，但调不到精确值 |
| **PI** | ⭐ 大多数场景（温度/液位/速度/压力） | 要消静差；D 对噪声敏感，能不用就不用 |
| PD | 快速定位、允许静差但需抑超调 | D 抑制超调，无 I 有静差 |
| PID | 要"快 + 准 + 稳"同时满足 | 三个都要，D 必须加滤波 |

**两个判断依据**：
1. **要不要消静差**：要精确到达目标 → 必须有 I；允许静差 → 可不要 I（P 或 PD）
2. **被控对象快还是慢**：慢系统（温度/液位，秒级热惯性）→ D 基本不用（预测意义小 + 放大噪声）；快系统（伺服定位）→ D 抑制超调有价值

**激光场景对照（面试直接讲）**：
| 环 | 特性 | 用什么 |
|----|------|--------|
| 功率环 | 快（µs~ms） | PI（D 谨慎） |
| 温控环 | 慢（秒级热惯性） | PI（D 不用） |
| 保护环 | 不用 PID | 阈值比较 |

**激光场景应用（必背）**：
| 场景 | 闭环链 |
|:-----|:-------|
| 激光功率闭环 | ADC 采样实际功率 → 与目标比较得误差 → PID 算占空比 → PWM/DAC 调泵浦/驱动电流 → 稳功率 |
| 温控闭环 | 温度 ADC（热敏电阻/热电偶）→ PID 算输出 → TEC/制冷片/风扇 → 稳温（激光器温控精度 ±0.1℃ 级） |

**工程落地细节（MS官深挖点，讲不出来=不会）**：
1. **积分饱和处理**：输出达到上限后积分还在累，导致退出饱和慢、超调大。解法：**积分分离**（误差大时不积分，接近目标才积）或**遇限削弱/抗饱和**（输出饱和时停止同向积分）。
2. **微分噪声放大**：D 项对噪声敏感，传感器噪声会让输出抖动。解法：**微分先行**（只对反馈量微分不对设定值微分）+ **低通滤波**（对微分项或输入先滤波）。
3. **参数整定**：我一般用**临界比例度法/经验法**先找大致范围，再结合实际负载微调；工程上更看重「超调 ≤5%、稳态误差达标、不振荡」这几个可量化指标。

**我的项目话术（诚实，结合爱博精电）**：
> 「我做过电能质量分析仪的高精度 ADC 采样和数字滤波——FFT 谐波分析、闪变测量的 IIR 滤波器组、工频提取，这是『ADC 采集 → 数字滤波去噪 → 计算』这条链。PID 闭环控制的原理我清楚（P/I/D、积分饱和、微分噪声、参数整定），但诚实说，量产项目里我没实际调过 PID 参数做闭环。激光器的功率闭环、温控，和我的高精度采样 + 滤波功底是同一套底层，PID 这块我有理论基础，上手会很快。」

### 3.2 状态机

**激光设备典型状态流（必背）**：
```
待机 → 自检 → 就绪 → 出光 → 保护(故障) → 故障复位 → 就绪
```
每个状态有明确的**进入条件 / 退出条件 / 迁移动作**，比如「保护」状态必须人工复位才能退出，「出光」状态任何异常信号（过温/过流/水冷断流）立即跳「保护」并**关光**。

**实现方式**：
- 用 `switch-case` 或**函数指针表**实现，避免 if-else 嵌套地狱
- 函数指针表的好处：扩展新状态只加一个节点，不改主流程

**我的项目话术**：
> 「我做过工业设备的多级状态机——正常运行、降级运行、故障保护三个层级，状态切换有严格互锁，防止误操作损坏硬件。激光设备的状态机本质一样，只是多了一个『出光』态和一套『异常立即关光』的安全边沿。用函数指针表实现，状态和迁移条件都显式化，好维护好扩展。」

#### 3.3.1 数字滤波器基础（必背，MS第一问）

**FIR vs IIR 对比**：

| 维度 | FIR（有限冲激响应） | IIR（无限冲激响应） |
|:-----|:--------------------|:--------------------|
| 结构 | 无反馈（纯前馈） | 有反馈（输出回送） |
| 相位 | **可严格线性相位**（系数对称） | 非线性相位（需补偿） |
| 稳定性 | **永远稳定**（无极点） | 可能不稳定（极点跑到单位圆外） |
| 同指标阶数 | 高（系数多） | **低（效率高）** |
| 实现 | 卷积（乘累加 `y[n]=Σ b_k·x[n-k]`） | 差分方程（`y[n]=Σ b_k·x[n-k] + Σ a_j·y[n-j]`） |
| 典型用途 | 抗混叠、工频提取、需要线性相位的场景 | 闪变仪滤波器组、低阶平滑、控制环路补偿 |

**一句话选型原则**：要线性相位/保波形形状 → FIR；要低阶/省算力/省资源 → IIR。

**常见滤波器类型（按用途）**：
| 类型 | 用途 |
|:-----|:-----|
| 低通 | 去高频噪声、平滑采样（最常用） |
| 高通 | 去直流漂移、去趋势 |
| 带通 | 提取特定频段（工频 50Hz 提取） |
| 带阻/陷波 | 抑制特定干扰（工频 50Hz 陷波） |

#### 3.3.2 我的真实项目：电能质量分析仪的 DSP 信号处理（MS金矿）

> 爱博精电高端电能质量分析仪，平台 ADI SC573（双 SHARC DSP + ARM Cortex-A5 异构）。这块是「工业级高精度信号处理」的完整实战，**直接对口激光的功率/温度采样处理**。

| 我做过的 DSP 模块 | 原理 | 对应激光场景 |
|:------------------|:-----|:-------------|
| **FFT 谐波分析** | 加窗（Hanning 等）→ FFT → 各次谐波幅值/相位，防频谱泄漏 | 功率/电流信号的频域特征分析 |
| **闪变测量**（IEC 61000-4-15） | 平方解调 → **IIR 带通/加权滤波器组** → 统计 | 传感器信号的频段加权提取 |
| **工频提取** | 带通/陷波滤波器提取 50Hz 基波 | 提取信号基频成分 |
| **均方根（RMS）** | 有效值计算 | 功率有效值、信号强度 |
| **插值重采样** | 非整周期采样修正、频率精确估计 | 采样率对齐、精确频率 |
| **SHARC 硬件 FIR/IIR/FFT 加速器** | 单周期完成一次 FIR tap 乘加 | 高性能滤波的硬件加速思路 |
| **汇编优化 + Cache 优化** | 汇编指令级优化 + ICache/DCache 命中率优化 | 实时性压榨 |

#### 3.3.3 激光场景的滤波器应用（把上面的功底落到激光）

**1. 功率采样滤波**：
- ADC 采样激光功率 → 噪声去除 → 喂给 PID
- 常用：**滑动平均 + 中值滤波**组合（先剔尖峰异常，再做平滑），或一阶 RC 低通
- 关键：滤波不能太滞后，否则功率闭环响应变慢

**2. 温度采样滤波**：
- 温控精度要求高（±0.1℃），传感器噪声必须滤干净
- 常用：中值滤波去脉冲干扰 + 低通平滑；激光器温漂慢，滤波可以重一些

**3. 保护信号处理**：
- 过流/过功率/过温检测，**滤波要快**（保护不能滞后，否则器件烧了才反应过来）
- 与 PID 输入滤波相反：保护链路宁可在噪声容忍范围内「偏快」也要「及时」

**高频追问 & 答法**：
| 追问 | 答法 |
|:-----|:-----|
| 为什么选中值滤波不选均值？ | 中值对脉冲尖峰鲁棒（单点干扰不拉偏），均值会被尖峰带偏；但中值保边缘差，所以「中值去尖峰 + 滑动平均平滑」组合最常用 |
| FIR 和 IIR 你项目里分别用在哪？ | 谐波用 FFT（本质是 FIR 滤波器组的频域实现）；闪变仪用 IIR 滤波器组（标准规定，阶数低效率高）；工频提取用 FIR（要线性相位保波形） |
| 采样率怎么定？ | 奈奎斯特（≥2 倍最高频率）+ 实际留余量；电能质量要测到 50 次谐波（2.5kHz），采样率至少 5kHz+，实际更高 |
| 硬件加速器原理？ | SHARC 有 FIR/IIR/FFT 专用加速单元，单周期完成一次乘加（FIR tap），比纯 CPU 循环快数倍；我配合汇编 + Cache 优化把整个 DSP 流水线效率拉满 |

### 🔴 第一梯队：JD 直接点名，必问

**Q1｜PID 三个参数 P/I/D 各起什么作用？**

> **P（比例）**：误差 × Kp，快速响应，但只有 P 有稳态误差（静差）。
> **I（积分）**：误差累积 × Ki，消除稳态误差，但会超调、积分饱和。
> **D（微分）**：误差变化率 × Kd，抑制超调、增加阻尼，但放大噪声。

**追问 1：积分饱和怎么处理？**
> 积分分离（误差大时不积分，接近目标才积）或遇限削弱（输出饱和时停止同向积分）。

**追问 2：微分噪声怎么解决？**
> 微分先行（只对反馈量微分不对设定值）+ 低通滤波（对微分项或输入先滤波）。

**追问 3：参数怎么整定？**
> 临界比例度法/经验法先找大致范围，再结合实际负载微调，看「超调 ≤5%、稳态误差达标、不振荡」。

---

**Q2｜激光设备的状态机怎么设计？用什么实现？**

> 状态流：`待机 → 自检 → 就绪 → 出光 → 保护 → 故障复位 → 就绪`。
> 每个状态有明确进入/退出条件和迁移动作。关键两条：出光态任何异常（过温/过流/水冷断流）**立即跳保护并关光**；保护态必须人工复位才能退出。
> 实现用**函数指针表**（switch-case 也行），扩展新状态只加一个节点不改主流程。我之前做过工业设备多级状态机（正常/降级/故障保护三层 + 严格互锁），激光设备本质一样，只多了「出光」态和「异常立即关光」的安全边沿。

---

**Q3｜FIR 和 IIR 的区别？分别用在哪？**

> FIR 有限冲激响应，无反馈，**可严格线性相位、永远稳定**，但阶数高；IIR 无限冲激响应，有反馈，**阶数低效率高**，但相位非线性、可能不稳定。
> 选型：**要保波形用 FIR**（工频提取），**要省算力/匹配模拟原型用 IIR**（闪变仪 Butterworth 滤波器组、控制环路补偿）。

**追问：激光功率采样滤波怎么做？**
> 中值滤波去尖峰 + 滑动平均平滑，或一阶 RC 低通。关键：滤波不能太滞后，否则功率闭环响应变慢。

---

**Q4｜你没做过激光，怎么理解激光设备的嵌入式控制？**

> 激光设备控制 = **功率闭环 + 温控 + 保护**三件事：
> - 功率闭环要**快**（kHz 级，ADC 采样→滤波→PID→PWM/DAC）
> - 温控要**准**（±0.1℃，PID 控 TEC/制冷片）
> - 保护要**可靠**（过温/过流/过功率/水冷断流，微秒级立即关光）
> 这和我做电力仪表的「高精度采样 + 实时闭环 + 可靠性保护」是一套东西，被控对象从电压电流换成激光功率和温度，底层能力直接迁移。

---

**Q4.1｜激光功率闭环具体怎么实现？（从 ADC 到 PWM 的完整链路，⭐ 必背）**

> ADC 采样光功率（光电二极管/积分球）→ 数字滤波（中值去尖峰 + 滑动平均）→ 与目标功率比较得误差 → PID 算输出 → PWM/DAC 调泵浦电流 → 激光出光功率变化 → 再采样，形成闭环。关键：功率闭环 kHz 级响应，**滤波不能太滞后**（否则闭环响应变慢）。

**Q4.2｜温控 PID 和功率 PID 有什么区别？（⭐ 体现懂被控对象）**

> 被控对象特性不同：功率环快（µs~ms 级，纯电子），温控环慢（秒级，热惯性大）。所以功率环快速响应、微分要谨慎（噪声敏感）；温控环主要用 PI（积分消静差），**D 项基本不用**（热系统惯性大、噪声敏感、微分会放大噪声）。温控 ±0.1℃ 精度靠高精度 ADC + 重滤波 + 慢而稳的 PI。

**Q4.3｜保护逻辑的微秒级响应怎么保证？（⭐ 体现安全认知）**

> 保护不能走软件轮询（太慢），三层保证：①**硬件比较器直接触发**（过流/过温硬件阈值电路，最快）；②**保护中断优先级最高**（不能被其他任务阻塞）；③**软件保护兜底**（ADC 采样 + 阈值判断 + 立即关光）。原则：宁可误报（多一层冗余）不可漏报（器件烧毁）。

### 🟡 第二梯队：RTOS/驱动，你的强项，讲出数据

**Q5｜RTOS 优先级反转怎么解决？**

> 优先级继承/天花板协议。我自研 RTOS 的 Mutex 当时没做完整继承（轻量取舍），靠编码规范规避（锁内禁阻塞、消息队列代替共享内存）；FreeRTOS 的 Mutex 默认做了继承。
> 踩过的坑：关中断 1.2ms 导致 UART FIFO 溢出偶发丢包，把不依赖原子保护的逻辑移出临界区后降到 0.2ms。

---

**Q6｜ADC 采样怎么保证实时性和精度？**

> 三级优先级（采样最高）+ DMA 双缓冲 + 环形缓冲，采样抖动从 ±15us 降到 ±2us；DMA 链式传输替代 CPU 轮询，CPU 负载 90%→47%。

---

**Q7｜DMA 和 Cache 一致性怎么处理？**

> DMA 前后做 Cache Flush/Invalidate。双核伪共享踩过坑——两个变量落同一 Cache 行，性能降 40%，用 64 字节对齐解决。

### 🟢 第三梯队：结合项目深挖，展现 DSP 王牌

**Q8｜你电能质量分析仪的 DSP 算法怎么优化的？**

> 三层：①算法层用 FFT（蝶形 O(NlogN)）+ Hanning 窗防频谱泄漏；②硬件层用 SHARC 的 FIR/IIR/FFT 加速器（单周期 MAC + DAG 循环缓冲 + bit-reverse 寻址）；③代码层汇编 + Cache 优化。三层叠加把整个 DSP 流水线效率拉满。

---

**Q9｜DSP 和 ARM 双核怎么通信的？**

> ADI SC573 双 SHARC + ARM Cortex-A5 异构，中断驱动 + 共享内存双核通信，跨核通信 ≤10ms。DSP 跑 RTOS 做实时采集和 FFT，A5 跑 Linux 做上层协议和界面。

---

**Q10｜你做过最难的性能/稳定性问题是什么？（开放题）**

> 双核伪共享——两个核的数据落同一 Cache 行互相失效，性能降 40%，最后用 64 字节对齐解决。这个问题的难点在于「不是代码逻辑错，是 Cache 架构层的隐性性能损耗」，靠逐层排除（先排除算法、再排除代码、最后定位到 Cache）才找到。

### 🔴 补充题组 A：CAN / CAN FD（你的王牌，前面漏了，必补）

**Q11｜CAN 和 CAN FD 的区别？什么时候选 CAN FD？**

> CAN 数据场最大 8 字节，CAN FD 最大 64 字节 + 双波特率（仲裁段低速保兼容、数据段高速 2/5/8Mbps）。大数据量（传感器、升级包）选 CAN FD。我的实战：双波特率位时序校准，总线负载 72%→21%。

**Q12｜CAN 总线负载率怎么算？负载高有什么问题、怎么优化？**

> 负载率 = 实际传输位数 / 总线带宽（含帧开销 + 位填充）。负载高 → 延迟、丢帧、低优先级饥饿。优化：精简报文、降频、ID 优先级规划、上 CAN FD。

**Q13｜CAN 总线丢包怎么排查？**

> 先看 TEC/REC 错误计数：一直涨 = 真丢包（总线/硬件问题），干净 = 软件丢包（缓冲区溢出）。硬件层查终端电阻、差分波形、地线干扰；软件层查接收 FIFO 溢出、任务调度延迟、缓冲区大小、优先级。

**Q14｜CAN 错误状态机三级？**

> 错误主动（TEC<128）→ 错误被动（≥128）→ 总线关闭（>255 自动脱离）。恢复：软件定时复位控制器、清零计数、主动上报。

### 🔴 补充题组 B：RTOS 深挖（主场）

**Q15｜信号量、互斥锁、消息队列区别？**

> 互斥锁：保护共享资源、有所有权、支持优先级继承、**不能在中断用**；信号量：计数/同步、中断可释放、无所有权；消息队列：传数据（不是单纯同步）、支持数据拷贝。

**Q16｜中断上下文能不能调阻塞 API？**

> 不能。中断没有任务栈、不能休眠阻塞，只能调非阻塞 API（FromISR 版本，如 `xSemaphoreGiveFromISR`）。

**Q17｜HardFault 排查步骤？**

> 栈回溯抓 PC → CFSR 判 fault 类型（UsageFault/BusFault/MemManage）→ `.map`/`addr2line` 反查源码行。常见原因：数组越界、空指针、栈溢出、中断冲突、非对齐访问。

**Q18｜栈溢出什么现象、怎么检测？**

> 现象：随机死机、变量被莫名篡改。检测：栈水印（watermark）/ `uxTaskGetStackHighWaterMark()` 监控剩余栈空间。

### 🟢 补充题组 D：工程场景（拉开差距）

**Q21｜设备偶发随机死机，没有必现规律，怎么排查？**
