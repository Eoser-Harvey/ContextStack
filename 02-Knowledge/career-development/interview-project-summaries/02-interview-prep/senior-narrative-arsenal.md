## 〇、四层叙事框架（所有答案的骨架，先背）

```
① 本质（一句话点出问题核心，展现高度）
② 实践（真实项目 + 具体数据，证明你做过）
③ 坑（踩过的坑 + 解法，区别普通工程师和资深的关键）
④ 思考（更好的方法 / 如果再做一次，升华）
```

**判断标准**：答完如果只有「是什么」，就是 3 年水平；答完有「坑 + 数据 + 取舍」，才是 8 年水平。

## 一、挂题 1：GCC 优化等级？（原答：只讲 O0~O3 是什么）

### ❌ 3 年答法
> GCC 有 O0、O1、O2、Os、O3 五个优化等级，O0 不优化方便调试，O3 优化最激进……

### ✅ 8 年答法（四层）

**① 本质**：GCC 优化等级本质是**速度、体积、调试性三者的权衡**——没有「越高越好」，只有「按模块精确控制」。

**② 实践**：我在自研 RTOS 上做了**分模块编译**：
- 内核用 **-Os**（Flash 宝贵，控制在 5~8KB 以内）
- 调度器是性能热点，用 **-O2**（每次上下文切换都经过，要快）
- DSP 浮点运算用 **-O3**（开向量化，榨性能）

**③ 坑**：-O3 踩过时序坑——一个精确延时循环 `for(i=0;i<1000;i++) __NOP();`，-O3 的循环展开 + 死代码消除**把整个循环优化掉了**，延时变成 0，外部芯片时序直接崩。后来用 `__asm__ volatile("" ::: "memory")` 内存屏障强制阻止编译器重排才解决。

**④ 思考**：这个教训让我理解——**优化等级不是全局设一个值，是按模块的热点/体积/时序敏感度逐个定的**。时序敏感的代码（GPIO 精确翻转、外设握手）要么 -O0/-O1，要么显式加内存屏障，不能交给 -O3 自由发挥。

## 二、挂题 2：优先级反转怎么避免？（原答：只讲继承/天花板两种方法）

### ❌ 3 年答法
> 优先级反转有高优先级等低优先级资源被中优先级抢占的问题，解法是优先级继承和优先级天花板……

### ✅ 8 年答法（四层）

**① 本质**：优先级反转的本质是**高优先级任务被「不相关」的中优先级任务无限阻塞**——1997 年火星探路者就是因为这个看门狗复位，NASA 损失几百万美元。

**② 实践**：我在自研 RTOS 里真实踩过。系统是电力仪表，三个任务共享一个互斥锁保护的测量结构体：
- 高优先级**测量计算任务**（Prio 5）：DMA 采样完唤醒，算有效值/功率，更新共享结构体
- 中优先级**通信任务**（Prio 3）：Modbus 打包应答，约 80ms 纯计算，**期间没有任何阻塞调用**
- 低优先级 **LCD 刷新任务**（Prio 1）

**触发链**：LCD 先拿锁 → 计算任务被 DMA 唤醒抢 CPU，要拿锁发现被 LCD 持有，挂起 → 通信任务恰好被唤醒，优先级比 LCD 高且 80ms 纯计算不释放 CPU → LCD 拿不到 CPU 去解锁 → 计算任务永久挂起，测量结果不更新，触发安全复位（50Hz 系统 80ms = 丢 4 帧数据）。

**③ 坑**：注意，这不是教科书那种标准三任务反转——**通信任务全程没有阻塞点**，标准的优先级继承都救不了（因为 LCD 连被提升优先级运行的机会都没有，CPU 一直被通信任务占着）。我排查了很久才定位到。

**④ 思考（更好的方法）**：修复分两层——短期编码规范禁止「锁内调任何可能阻塞的函数」；长期**从架构上用消息队列替代共享内存**（不共享数据就不需要锁，不需要锁就不存在反转）。另外如实说：我当时的 Mutex 是**普通互斥锁，没做优先级继承**（为内核精简的取舍），标准解法是继承（FreeRTOS 的 `xSemaphoreCreateMutex` 默认就有）——**主动讲「没做 + 知道怎么做」，比假装做了更可信**。

## 三、挂题 3：使用 Cache 会带来什么问题？（原答只有概念，需补全四层）

### ❌ 3 年答法
> Cache 会带来数据一致性问题、伪共享、时序问题……

### ✅ 8 年答法（四层）

**① 本质**：Cache 用**局部性原理**弥合 CPU 和主存的速度差，但它引入了**多副本一致性**问题——同一份数据可能同时存在 Cache、主存、DMA 缓冲区里，几个副本不一致就出错。Cache 的所有问题本质都是「一致性管理」。

**② 实践**：我在电能质量分析仪（ADI SC573 双 SHARC DSP + ARM A5）上把 ICache/DCache 驱动做成了产品化，DMA 做高速采样，踩过两类典型坑。

**③ 坑（两个，都是真实数据）**：

- **坑 1：双核伪共享（false sharing）**——两个核的变量恰好落在**同一条 Cache 行**（64 字节），一个核写自己那份，会把另一个核的整个 Cache 行置失效，两个核互相失效 → **性能直接降 40%**。解法是**关键数据 64 字节对齐**，让不同核的变量落在不同的 Cache 行。
- **坑 2：DMA 与 Cache 不一致**——DMA 绕过 CPU 直接写主存，但 CPU 从 Cache 读，读到的是 Cache 里的**旧数据**；反过来 CPU 写完数据在 Cache 里，DMA 去读主存拿到旧值。解法：DMA 读数据前 **Cache flush**（把脏数据写回主存），DMA 写完后 **Cache invalidate**（作废缓存行强制重读）。

**④ 思考**：Cache 问题不是「会不会用 Cache」，是**搞清「数据在哪些副本里、什么时候必须同步」**。伪共享是多核的坑（对齐解决），DMA 一致性是外设直写的坑（flush/invalidate 解决）——两类坑机制不同，但根子都是「多副本」。这也是「把性能问题定位到 Cache/硬件层」的能力，不是调库能解决的。

## 四、方案 3：项目介绍「先讲值钱的」（青鸟/思朗的死法纠正）

### 反面教材（你真实挂过的）

| 公司 | 死法 |
|:--|:--|
| 青鸟 | 先讲整体框架 → MS 官说「没看到细节」 → 开始补细节 → 没讲完被挂断 |
| 思朗 | 先讲最基础的 → 对方最想听的（算法工程化落地）没先讲 |

**病根**：把「我做了什么」当主线，而不是把「我解决过什么难的问题」当主线。

### ✅ 原则（三句话）

1. **第一句直接抛「最难的技术问题 + 我解决了 + 数据」**
2. **不铺垫整体框架**，先立一个「技术高点」，让 MS 官追问
3. **主动埋钩子**：「我在这块踩过一个很经典的坑，要不要展开？」

### 自我介绍重写（30 秒版，先讲值钱的）

> 「我是韩伟，9 年嵌入式。**最能打的是两件事**：一是从零自研过一个 RTOS 内核——5KB，跑在百万台量产设备上，调度/内存/中断源码级；二是 DSP 信号处理——电能质量分析仪的 FFT 谐波分析、闪变测量，用 SHARC 硬件加速器 + 汇编优化把实时性做到极致。最近在新华三做工业交换机底层。
>
> 我举个具体例子：在自研 RTOS 里我踩过一个**优先级反转的坑**，一个 80ms 纯计算的通信任务把 LCD 任务饿死，高优先级测量任务永久挂起触发了安全复位——要不要展开讲我怎么定位和规避的？」

**为什么这样开头**：第一句就把最值钱的（自研 RTOS + DSP）立住，然后用一个具体的坑当钩子，引导 MS 官往你的强项追问——而不是等他漫无目的地问。

### 项目介绍开头重写（按岗位给钩子）

| 投的岗位 | 项目介绍第一句（钩子） |
|:--|:--|
| RTOS/底层岗 | 「我自研过一个 RTOS 内核，最深的坑是优先级反转——不是教科书那种，是一个不阻塞的通信任务把低优先级任务饿死的变体。」 |
| DSP/信号处理岗 | 「我做电能质量分析仪，最难的是双核伪共享把性能打降 40%，我用 64 字节对齐 + Cache 管理解决。」 |
| MCU 驱动岗 | 「我把一个 CPU 占用 90% 的轮询采样改成 DMA 链式传输，CPU 负载降到 47%，采样抖动从 ±15us 压到 ±2us。」 |

**每个钩子都带一个「难点 + 数据」**，让 MS 官有的可追。

## 五、自检清单（每次开口前 3 秒过一遍）

| 检查项 | 达标标准 |
|:--|:--|
| 我有没有先给「本质一句话」？ | 先立高度，再展开 |
| 我有没有讲「真实项目 + 数据」？ | 不是背书，是讲我做过的 |
| 我有没有讲「坑 + 解法」？ | 这是资深和普通分水岭 |
| 我有没有埋「钩子」？ | 主动引导 MS 官往强项问 |
| 我第一句是不是「值钱的」？ | 不是「整体框架」「最基础的」 |

**一句话记住**：先讲最难的问题 + 我解决了 + 数据，再讲坑，最后讲思考——别从「是什么」开始背。
