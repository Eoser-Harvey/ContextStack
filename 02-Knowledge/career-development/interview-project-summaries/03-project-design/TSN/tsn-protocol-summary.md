# TSN 时间敏感网络协议总结

> 本文档是 TSN 专题的唯一权威总结（2026-09-01 合并整合）。原 `TSN-protocol-analysis.md`（话题工作台）、`tsn-protocol使用说明.md`（skill 说明）已合并至此并删除，`tech-interview-notes.md §3.2` 的协议清单也并入此处。

## 一、TSN 是什么

**一句话**：TSN（Time-Sensitive Networking，时间敏感网络）是 IEEE 802.1 工作组定义的一组以太网扩展标准，把「尽力而为」的标准以太网升级为「**确定性传输**」——保证低延迟、低抖动、有界的端到端时延。

**为什么需要 TSN**：标准以太网是共享竞争、无时间保证的。而工业控制、机器人关节控制、汽车自动驾驶、音视频流等场景，要求数据「在确定的时间窗口内必达」。TSN 就是给以太网加上「时间观念」。

**TSN 三根支柱**：
1. **时间同步**（802.1AS）——先让全网设备时钟对齐
2. **确定性调度**（Qbv/Qbu/Qci/Qav）——保证关键流量按时送达
3. **可靠性**（802.1CB）——冗余路径无缝切换

## 二、核心协议集

| 协议       | 名称                 | 作用                       | 我的实践 |
|:-----------|:---------------------|:---------------------------|:---------|
| 802.1AS    | 时间同步（gPTP）     | 全网时钟对齐到纳秒级       | ✅ 落地   |
| 802.1Qbv   | 时间感知整形（TAS）  | 基于时间窗的确定性调度     | ✅ 落地   |
| 802.1Qci   | 单条流过滤和监控     | 流量过滤、速率限制         | ✅ 落地   |
| 802.1Qbu   | 帧抢占               | 高优先级帧打断低优先级帧   | ✅ 落地   |
| 802.1CB    | 帧复制与消除         | 双路径冗余、无缝切换       | ✅ 落地   |
| 802.1Qcc   | 集中配置             | 管理面（CUC/CNC）          | 了解（未开发） |

⭐️注：802.1Qbu 高优先级帧插入传输完成后，低优先级帧继续传输；
    802.1CB 帧复制 路径多样性 帧消除，入口打标记终点消除

### 各协议与「丢包/确定性」的关系（⭐️实战视角）

- **802.1Qbv 门控列表**：门控列表配置错误 → 帧在错误时间窗发送 → 丢失或延迟。丢包排查的高风险点。
- **802.1Qci 过滤规则**：过滤规则过严 → 合法帧被误丢弃，SMAC DMAC VLAN等判断是否TSN流量,监管和阻断两种方式。
监控报文的入方向；
- **802.1AS 时间同步**：同步偏差 → 破坏门控列表的有效性（时间窗对不齐）。

> 排查结论（2026-04 实战）：门控列表配置是 TSN 丢包的头号风险点，其次才是硬件信号质量（本安电路降低发送功率 → CRC 错误）。

### Qci Meter 令牌桶原理（⭐️ 监管限速的核心）

Qci 的 Meter 用**令牌桶（Token Bucket）**算法实现流量监管（限速 / 阻断）。

**令牌桶类比**：一个水桶，系统匀速往里加令牌；数据要放行就从桶里取令牌；桶空则丢包。

| 参数 | 含义 | 决定什么 |
|------|------|---------|
| 令牌生成速率 | 每秒加几个令牌 | 长期平均速率上限 |
| 桶容量 | 最多存多少令牌 | 允许的突发量 |
| 包大小 | 每个包扣几个令牌 | 按字节/包计费 |

**为什么能限速**：令牌匀速生成 → 长期平均速率被卡死；桶能攒令牌 → 允许短时突发；持续超速 → 令牌耗尽 → 丢包。

**Qci 场景**：给日志流配 10Mbps 令牌桶，正常时令牌够用；日志风暴飙到 100Mbps，令牌秒光丢包 → 异常流被限死，控制流（关节指令）带宽不受挤占。这就是「限速 / 阻断」两种控制方式的底层原理。

**令牌桶 vs 漏桶（高频追问）**：

| | 令牌桶 | 漏桶 |
|---|--------|------|
| 允许突发 | ✅ 可攒令牌允许突发 | ❌ 严格匀速 |
| 输出速率 | 突发时瞬时超平均 | 恒定速率 |

> Qci 选令牌桶不选漏桶：控制流需要允许一定突发（批量指令下发），但限制长期平均速率——令牌桶正好"管平均、放突发"。

## 三、时钟同步技术栈（TSN 的基础）

> 当前产品同时支持三类同步技术，**时钟同步是 TSN 的基础**。

| 技术  | 标准          | 层次       | 作用                              |
|:------|:--------------|:-----------|:----------------------------------|
| SyncE | ITU-T G.826x  | 物理层     | 频率同步（从物理链路提取时钟）    |
| PTP   | IEEE 1588     | 报文/应用层| 高精度时间同步（纳秒级）          |
| gPTP  | IEEE 802.1AS  | TSN 协议集 | TSN 时间同步（PTP 的 profile）    |

**为什么「时钟同步是 TSN 的基础」**：
- Qbv 时间感知调度、Qbu 帧抢占、802.1CB 冗余，都依赖全网设备时钟对齐到同一时间基准
- 没有 gPTP 精确同步，各设备的「时间窗」对不齐，确定性调度无从谈起
- 因此 gPTP（802.1AS）是 TSN 协议栈的根基——**先有同步，再有确定性**

**SyncE vs PTP 的区别（⭐️高频⭐️）**：

| 维度     | SyncE                  | PTP / gPTP              |
|:---------|:-----------------------|:------------------------|
| 同步对象 | 频率（frequency）      | 时间 + 相位（time/phase）|
| 层次     | 物理层                 | 报文层                  |
| 实现     | 从以太网线路恢复时钟   | 报文交换计算偏差         |
| 依赖     | 需要物理层芯片支持     | 只需支持 IEEE 1588 报文 |
注：SyncE要求树状组网； 目前设计是500ppm=0.05%；
    两个设备之间通过ESMC报文物理层交互，需要指定主从设备；
    单个设备多个端口也需要指定优先级；
    硬件上需要高精度锁相环PLL；

SyncE 时钟源类型：BITS时钟(H3C不支持)、线路时钟、PTP时钟、本地时钟；
      选源：分为手动、自动(取决于 SSM级别、优先级、接口编号小的优先级高)
      选出最优时钟后，设备会将本地时钟SSM级别传递给下游设备继续进行选源传递；

⭐️⭐️⭐️⭐️⭐️
典型问题：时钟环路导致设备精度越来越差，触发条件设备循环同步自己发出去的时钟；
    如果使用SSM级别，收到上游时钟设备的同步时钟后，需要将SSM级别设备为DNU，避免上游设备收到后再次同步；
    组网应是树状或链状，避免成环；

### SyncE 频率传递机制（⭐️ 码流 vs 业务帧，面试必讲）

SyncE 的频率是怎么传过去的？**核心：频率信息蕴含在物理层串行码流的比特跳变边沿里，随码流一起发给下游，跟以太网业务数据包无关。**

**两个概念分清**：

| | 串行码流（PHY L1） | 以太网业务帧（MAC L2） |
|---|---|---|
| OSI 层 | 物理层，网线/光纤真实信号 | 数据链路层，数据包/帧 |
| 连续性 | 链路 UP 就持续输出；无业务时发 **IDLE 空闲码** | 突发、间断，有业务才发 |
| 内容 | 业务符号 + IDLE 空闲 K 控制字符（如 K28.5） | MAC 头 + 载荷 + CRC |
| SyncE 作用 | CDR 从跳变边沿恢复**频率本身** | ESMC 报文只传 QL 质量等级，不带时钟 |

**关键机制（背）**：
1. 发送端：主时钟（BITS/PRC）经 PLL 锁定 PHY 发送时钟，码流以精确符号速率输出
2. 无业务时：PHY 持续发 **IDLE 空闲码**（8B/10B 的 K28.5 等），维持码流连续、持续产生 0↔1 跳变边沿
3. 接收端：**CDR（时钟数据恢复电路）只检测比特跳变边沿，恢复出发送端频率**——完全不解析帧头/MAC/IP/载荷，不知道"数据包"是什么
4. 恢复的频率送 DPLL 锁相环再生，驱动本设备向下游继续输出码流

**⚠️ 核心误区纠正**：很多人误以为 SyncE 靠 ESMC 报文传时钟——**错**。ESMC 是 L2 业务报文，只传 SSM-QL 时钟质量等级（用于选源、防环路）；**频率是 L1 码流边沿自带的，和报文无关**。哪怕 ESMC 全丢光，只要链路 UP，CDR 照样恢复频率，只是没法选源。

**高频追问**：
- **Q：业务完全断流（0 数据包），SyncE 还能同步频率吗？** → 能。链路 UP，PHY 持续发 IDLE 码，CDR 从 IDLE 码流恢复频率；只是收不到 ESMC，无法选源。
- **Q：链路拥塞/业务大量丢包，会破坏 SyncE 吗？** → 不会。频率恢复在 L1 物理层，只看跳变边沿，不受 L2 排队/拥塞/丢包影响；只有 ESMC 丢包影响选源。
- **Q：为什么 PTP 不一样？** → PTP 时间戳封装在 L2 业务 MAC 帧载荷里，拥塞/抖动直接破坏时间精度；SyncE 频率藏在 L1 码流，不依赖业务包。

**一句话面试话术**：
> "串行码流是物理层 PHY 在网线/光纤上传输的连续比特流（L1），链路 UP 就持续输出，没业务时发 IDLE 空闲码维持跳变边沿；以太网业务帧是 L2 的 MAC 数据包，突发间断。SyncE 的频率信息蕴含在 L1 码流的比特跳变边沿里，接收端 CDR 直接恢复频率，不需要解析业务包——即使 0 业务流量，靠 IDLE 码也能恢复时钟。ESMC 报文只传 QL 质量等级，不传频率本身。"

### PTP 底层驱动（PHY/MAC 硬件时间戳）

PTP 要纳秒级精度，必须**硬件时间戳**——在报文离开/到达物理介质的那一刻打戳（软件打戳误差微秒~毫秒级，不满足纳秒要求）。

**两个打戳位置**：

| 位置 | 打戳点 | 精度 | 典型芯片 |
|------|--------|------|---------|
| PHY 层 | 报文离开 PHY 进网线的瞬间 | 最高（最贴物理介质） | TI DP83640、Marvell 88E1512 |
| MAC 层 | 报文经过 MAC 的 MII 接口 | 略低（差 MII+PHY 延迟） | STM32 ETH、多数 SoC MAC |

**MAC 驱动做啥**：
1. 使能时间戳单元（TSU），打开时间戳捕获
2. 初始化 PTP 硬件时钟（纳秒计数器，秒+纳秒）
3. 提供时钟调整接口：步进调整 `adjtime` / 频率调整 `adjfreq`（PPM 微调）
4. 捕获时间戳：发送写 **Tx 描述符**、接收写 **Rx 描述符**
5. 描述符时间戳读回 + 关联到对应报文

**PHY 驱动做啥**：
1. 使能 PHY 1588 功能 + 本地时钟
2. 通过 MDIO/MDC 管理接口读时间戳、配时钟
3. 延迟补偿：入口延迟(ingress) + 出口延迟(egress) + MII 接口延迟
4. PHY 本地时钟与主时钟对齐（SyncE 时尤其重要）

> 简单说：MAC 驱动管「时钟 + 打戳 + 描述符」，PHY 驱动管「更精确打戳点 + MDIO 读回 + 延迟补偿」。

**时间戳关联报文（核心难点）**：硬件时间戳异步返回，软件要匹配到正确报文——Tx 按描述符索引/序号，Rx 按接收顺序 + PTP `sequenceId`。

**一步法 vs 两步法（高频追问）**：

| | 一步法 one-step | 两步法 two-step |
|---|----------------|----------------|
| 机制 | 硬件实时把时间戳塞进报文 | 记下时间戳，Follow_Up 补发 |
| 硬件要求 | 需支持传输中插入时间戳 | 低，描述符带时间戳即可 |
| 实现 | 难 | 易，大多数硬件支持 |

> 绝大多数嵌入式走两步法：硬件只做描述符打戳，协议栈用 Follow_Up 补发时间戳，实现最简可靠。

### PTP BMCA 选主算法（⭐️ 如何确定最优时钟）

BMCA（Best Master Clock Algorithm）是 PTP 里**分布式选主时钟**的核心算法——全网设备交换 Announce 报文，自动选出唯一 Grandmaster。

**比较字段序列（按顺序比，值小者胜）**：

| 顺序 | 字段 | 含义 | 说明 |
|------|------|------|------|
| 1 | priority1 | 用户可配静态优先级（0~255） | 手动指定谁当主，默认 128 |
| 2 | clockClass | 时钟等级 | 6=锁定 GPS/原子钟，7=holdover，255=从时钟 |
| 3 | clockAccuracy | 时钟精度 | 越精确越好 |
| 4 | offsetScaledLogVariance | 偏移方差（稳定性） | 越小越稳定，65535=未知 |
| 5 | priority2 | 用户可配第二优先级 | 默认 128 |
| 6 | clockIdentity | 8 字节唯一 ID（EUI-64） | 最后兜底，保证不并列 |

**一句话记顺序**：`priority1 → clockClass → clockAccuracy → 方差 → priority2 → clockIdentity`。

**算法流程（分布式，无需中央控制器）**：
1. 每台设备初始认为"自己是主时钟"
2. 周期性广播 Announce 报文（带质量字段）
3. 收到 Announce → 数据集比较
4. 自己更好 → 继续 Master；对方更好 → 降 Slave 同步过去
5. 状态机管理：Master / Slave / Passive / Listening

**gPTP（802.1AS）简化版**：

| | 完整 PTP（1588） | gPTP（802.1AS） |
|---|-----------------|-----------------|
| 比较字段 | 6 个字段全比 | 只比 priority + clockIdentity |
| 原因 | 跨广域网、时钟源复杂 | 二层局域网，主时钟通常预先指定 |

**H3C 项目话术**：
> "BMCA 通过 Announce 报文交换时钟质量字段，按 priority1 → clockClass → clockAccuracy → 方差 → priority2 → clockIdentity 顺序比较，值小者当选 Grandmaster。gPTP 用简化版，只比 priority 和 clockIdentity。部署时手动把接 GPS/BITS 的设备 priority1 设小，强制它当主，其余自动同步。"

**可能被追问**：

| 追问 | 答法 |
|------|------|
| 怎么强制某台当主？ | priority1 设最小（如 0） |
| 全字段相同会并列吗？ | 不会，最后比 clockIdentity（MAC）分胜负 |
| holdover 是什么？ | 主时钟失去 GPS 后进入保持模式（clockClass=7），本地晶振维持，精度渐降 |
| 有中心控制器吗？ | 没有，纯分布式独立比较收敛 |


## 七、问题排查

### 问题 1：时间同步失败

症状：设备时钟偏差 >1μs、PTP 未同步。排查顺序：物理连接（网线/指示灯/CRC 错误）→ PTP 配置（域/优先级/启用）→ 网络（防火墙/组播/VLAN）→ 时钟源（Grandmaster/多主竞争/稳定性）。

### 问题 2：流量延迟过大

症状：端到端延迟超标、抖动大。排查：门控配置（周期/门状态/偏移）→ 网络负载（非 TSN 流量/链路利用率/广播风暴）→ 设备性能（处理能力/缓冲溢出）。

### 问题 3：帧丢失或重复

症状：收到重复帧、丢失关键帧。排查：帧复制配置（是否启用/路径/消除算法）→ 拓扑（环形完整/链路故障/路径对称）→ 序列号（生成/检测算法/溢出）。

## 九、⭐️⭐️⭐️ MS话术（TSN 如何讲）

> 「TSN 本质是给标准以太网加上『时间观念』，三根支柱：802.1AS 时间同步、Qbv/Qbu 确定性调度、802.1CB 可靠性。我在 H3C 带队把 5 个协议（gPTP/Qbv/Qci/Qbu/1CB）完整落地，环网故障收敛做到 ≤20ms。关键难点是门控列表的配置和时间同步的精度——时间窗对不齐，确定性调度就是空谈，所以 gPTP 是 TSN 的根基。」

**被追问「时钟同步怎么保证精度」时的回答链**：
SyncE（物理层频率同步）→ PTP/gPTP（报文层时间相位同步）→ 两者配合才能做到高精度。TSN 用 gPTP（802.1AS），它是 PTP 针对二层桥接网络的 profile。

## 四、协议层次

```text
应用层
    ↓
TSN 配置管理（YANG 模型、NETCONF）
    ↓
TSN 控制面（CUC 集中用户配置、CNC 集中网络配置）
    ↓
TSN 数据面（交换机、终端设备）
    ↓
物理层（以太网）
```

## 五、配置方法（H3C 风格示例）

### 交换机配置

```bash
configure terminal

# 启用 TSN 功能
tsn enable

# 配置时间同步（gPTP）
ptp profile 802.1as
ptp domain 0
ptp priority1 128
ptp priority2 128
ptp clock-source external

# 配置时间感知整形（Qbv）
interface GigabitEthernet1/0/1
tsn qbv enable
tsn qbv schedule 1
tsn qbv gate-states 1 1 1 1 1 1 1 1
tsn qbv gate-durations 1000000
```

### 终端设备配置（Linux PTP）

```bash
ptp4l -i eth0 -m -s -2        # 802.1AS 模式
```

### 流量分类（规划阶段）

| 类别 | 优先级 | 典型场景       |
|:-----|:-------|:---------------|
| A 类 | 最高   | 运动控制、安全信号 |
| B 类 | 中等   | 过程数据、视频流   |
| C 类 | 低     | 文件传输、配置数据 |

## 六、调试方法

### 1. 时间同步调试

```bash
pmc -u -b 0 "GET CURRENT_DATA_SET"    # 查看当前时钟状态
pmc -u -b 0 "GET PARENT_DATA_SET"     # 查看父时钟
ptp4l -m -i eth0                       # 实时打印同步状态
timedatectl status
```

**常见问题**：时钟不同步（查连通性/PTP 配置/时钟源）、精度差（查负载/交换机配置/时钟稳定性）、主时钟切换（查优先级/Announce）。

### 2. 流量整形调试

```bash
show tsn qbv interface GigabitEthernet1/0/1   # 查门控状态
show tsn qbv schedule 1
```

### 3. 抓包分析（Wireshark 过滤器）

```
ptp                        # gPTP 协议
ptp.messageType == 0       # Sync 消息
vlan.id == 100             # TSN 流量的 VLAN 标签
```

**关键字段**：`sequenceId`（帧复制消除用）、`gateState`（门控状态）、`timeSync`（时间同步）。
