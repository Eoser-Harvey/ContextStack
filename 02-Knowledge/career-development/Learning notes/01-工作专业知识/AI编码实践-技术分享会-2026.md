## 一、AI编码项目经验分享（史峰诚）

### 1.1 项目实践

| 维度 | 内容 |
|------|------|
| **AI参与度** | 项目代码几乎全部由 AI 生成，仅在极小改动时手动修改 |
| **测试表现** | 系统测试阶段基础功能问题较少，主要问题集中在**多功能混合时的设计矛盾** |
| **核心教训** | AI 擅长独立功能，但在功能间交互/设计层面容易出错 |

### 1.2 踩坑记录

| 问题 | 现象 | 根因 | 解决 |
|------|------|------|------|
| **DCP设置理解错误** | 最初认为 CNP 管 CNP、CNM 管 CCM8/16字节 DSCP；实测发现 CNP 既管发送的 CNP 又管 CCM8字节，CNM 专管 CCM106字节 | AI 对协议规范的边界理解不精确 | 实测验证后纠正理解，将修正后的知识反馈给 AI |
| **复杂逻辑辅助** | AI 生成了逻辑关系表并生成代码，初始代码不正确 | 复杂逻辑需要多轮迭代 | 通过多次调整最终完成 |
| **VS Code AI插件局限** | 不识别 Word 文档、表格、图片 | 插件能力边界 | 将资料转化为纯文字描述再喂给 AI |
| **编码格式乱码** | GB2312 与 UTF-8 不兼容导致乱码 | IDE 编码不一致 | 统一使用 UTF-8 |

### 1.3 经验提炼

```
✅ 好的实践：
  - 提供详细的参考代码和示例函数
  - 功能点描述准确 → AI生成质量高
  - 复杂旧代码改动采用分步指导，避免大规模改动风险

❌ 避免：
  - 直接喂 Word/表格/图片
  - GB2312 与 UTF-8 混用
  - 一次性描述过于复杂的逻辑
```

## 三、AI编码过程复盘与优化建议（闫波）

### 3.1 建议流程

```
SOW文档 → AI生成代码 → 实测验证 → 反向更新SOW → 重新生成验证
  ↑_______________________________________________↓
             形成闭环，文档与代码始终保持一致
```

### 3.2 关键成功因素

| 因素 | 说明 |
|------|------|
| **详细参考代码** | 提供示例函数和参考实现，AI 理解更准确 |
| **准确的功能描述** | 功能点描述越精确，生成代码质量越高 |
| **分步指导** | 复杂旧代码改动时，不要让 AI 一次改太多，分步逐步修改 |
| **接口命名明确** | 平台命令行与驱动侧对接时，必须明确指定函数与命令字的对应关系 |

### 3.3 优化方向

| 优先级 | 方向 | 说明 |
|:---:|------|------|
| 🔴 | SOW 加约束条件 | 要求 AI 在不明确时**主动提问**，减少幻觉生成 |
| 🔴 | 加强代码注释 | 代码注释质量直接影响 AI 的理解准确性 |
| 🟡 | 全流程自动化 | 探索从 SOW → 代码 → 验证 → 文档更新的完整闭环 |

### 4.2 开发踩坑与解决

| 问题 | 解决 |
|------|------|

### 4.3 当前状态与后续规划

| 状态 | 说明 |
|------|------|

| **后续目标** | 实现**硬件接口说明书直接生成定制代码**，完成全流程自动化 |

## 五、Skill开发方法总结

### 5.1 对话迭代法 vs 大型模板法

| 方法 | 方式 | 效果 |
|------|------|:---:|
| **对话迭代法** | 与 AI 反复对话，逐步修正生成错误，最终总结成稳定 Skill | ✅ **更有效** |
| **大型模板法** | 提供庞大的初始模板让 AI 填充 | ❌ 效果差 |

> **核心经验**：小步快跑，每次对话解决一个问题，积累到稳定后固化 Skill。

### 5.2 BS平台AI编码前景

```
当前：生成产品框架（目录结构+编译脚本+基础代码）
  ↓
后续：硬件接口说明书 → 直接生成定制代码 → 全流程自动化
```

## 七、核心提炼：AI编码实践十诫

```
① 喂文字不喂文件  → 图片/表格/Word 转为纯文本描述
② 分步不贪大      → 复杂逻辑分多轮迭代，每轮只改一个点
③ 提供参考代码    → 示例函数和参考实现是最有效的 prompt
④ 描述精确        → 功能点描述越精确，AI 生成越准确
⑤ 改动后验证      → 每次 AI 修改后必须重新读取确认
⑥ 编码统一        → 全项目统一 UTF-8，杜绝乱码
⑦ 文档代码同步    → 代码确定后反向更新 SOW/需求文档
⑧ 不明确主动问    → SOW 中加约束：AI 不确定时提问，禁止猜测
⑨ 注释驱动理解    → 代码注释质量 = AI 理解质量
⑩ 对话迭代固化    → 反复对话→稳定→总结成 Skill，不用大型模板
