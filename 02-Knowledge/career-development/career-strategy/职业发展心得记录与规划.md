### 记录 1 — 2024年9月25日：H3C工业交换机部门体会

**背景**：新华三工作期间对团队氛围和成长环境的反思。

**核心感受**：
- 组内没有成长氛围，培养没有，只是单纯的干活、做项目
- 直接领导基本没有管理，只是安排他领导下发的任务
- 不是我理想中的团队——应该是有交流、有团队氛围、积极发展的状态，我目前的团队比较沉闷
- 加班特别严重，而且是一直处理简单问题，不出业绩

**反思**：团队环境对个人成长的制约是真实的。当一个团队只关注"干活"而缺乏"成长"，长期来看对个人发展极为不利。这不是个人的问题，而是组织土壤的问题。

### 记录 2 — 2023年3月15日：离职谈话策略

**背景**：准备离开爱博精电，与组长吴工谈话计划。

**核心心得**：学会成熟离职——不说缺点，说自己的问题。

**话术准备**：
1. 主要是个人家庭原因，想和对象距离近一些
2. 公司相对稳健，我野心比较大，随着年龄的增长、认知的变化，我想寻求改变，给自己更大的期待
3. 目前正在找，已经MS了几家了（大公司、创业公司），不说具体的下家

**爱博精电时期的核心失落**（22年复盘）：
- 22年业绩预期：做了许多，结果我和其他人一样，很失落
- 未来规划失落：看不到成长方向
- 工资年底失落：都是大锅饭
- 生活需要我家庭的责任
- 去年承诺，今年就不提了，失落。那我肉眼可见的未来，一样。心里不踏实

**23年的迷茫**：
- 这一年的规划是什么？
- 以后的规划，对未来看不到希望，自己成长的方向、追逐的目标是什么？
- 22年是否有业绩？23年从哪里发力？
- 把杂事情梳理清楚了，如果我专精发展，杂事情必须去掉

**反思**：这一段记录非常真实地反映了一个技术人员在传统工业公司遇到的职业天花板——大锅饭、看不到成长方向、承诺不兑现。这是很多人职业转折的触发点。

### 记录 4 — 2022年12月19日：与爱博精电刘总聊天

**谈话要点**：
1. 了解公司发展方向，不只是工作、挣个工资，而是当做事业去干。对公司负责，对自己负责。自己的努力能和公司的努力方向一致，事半功倍。
2. 你对技术方向、行业发展前景趋势的看法？
3. 公司的稳定客户源是什么？
4. 计划多少比例投入研发？

**反思**：这是在主动寻求与公司的战略对齐——试图理解公司方向，找到个人努力与公司发展的共振点。但最终没有找到，导致了后来的离职。

### 记录 5 — 2021年4月30日：组内建设思考

**互相打分机制**：
1. 需要有具体事例支撑
2. 比重不宜过大

**内推奖励机制**：
1. 刚入职奖励30%
2. 一年后，表现良好，给予100%奖励

**管理心得**：
> 每天最首当其冲的工作，不是决定某件事该怎么处理，而是决定哪些事要尽快处理、哪些事暂不处理了。

**反思**：已经开始思考管理机制设计——考核、激励、优先级管理。这句"优先级管理"的心得非常经典，是管理者的核心能力。

### 记录 6 — 2021年2月6日：工作反思

**自我管理**：
1. 我的脾气需要压制，不能随随便便、喜形于色了！
2. 不用直接说下属的问题，用词委婉一点，当然应该有的态度还是要有的！
3. 多和领导沟通，表达自己的想法、思路，让领导看到你的成长、你的向上态度！

**反思**：三个自我管理要点——情绪控制、沟通方式、向上管理。这是从纯技术向技术+管理转型的关键软技能。

### 记录 7：爱博发展问题总结

**目前存在的问题**：
- 钱方面：项目奖一年几乎没有发。年终奖不到一万。两年涨一次工资，涨一次才4/5千。
- 人员方面：我们这几个中级很累，但是没有输出，收获很少。

**要和公司说明的诉求**：
- 工资：至少30K
- 社保、公积金需要按照工资全额交（以后每年按照工资走）
- 年终奖体系也要变高
- 无特殊情况，明年至少涨工资的10%
- 车牌
- 两居的房子

**反思**：这是对爱博精电薪酬体系的全面不满。从薪资到社保到年终奖，全面落后于市场水平。这些诉求最终没有实现，直接导致了离职决策。

### 记录 8 — 2024年7月17日：关于"不管"的管理哲学

**背景**：观察同事老薛的管理风格后的感悟。

**核心观点**：
> "不管"是做老板和领导的其中一门大学问。如何做好"甩手掌柜"，既要规则，也要艺术。

**深度思考**：
- 涉及到哪些不管，哪些管（范围：哪些人，哪些事，哪种程度）
- 如果要管，管到什么程度（团队关键人和游戏规则/流程，项目里程碑/节点等）
- 这又涉及到团队架构、决策机制、沟通和反馈机制、风控措施和责任承担机制等
- 确实是个系统工程

**反思**：从"事必躬亲"到"学会放手"是管理者的重要跃迁。这个思考已经触及了管理的核心——不是不管，而是管对的事情、管对的程度。

## 四、国内嵌入式工程师职业发展路径参考

### 4.1 典型发展路径

国内嵌入式领域发展好的工程师，通常走以下几条路径：

#### 路径A：技术专家线（深耕到底）

```
初级嵌入式工程师（1-3年）
  → 高级嵌入式工程师（3-5年）
    → 资深/主任工程师（5-8年）
      → 技术专家/架构师（8-12年）
        → 首席科学家/技术VP（12年+）
```

**特征**：持续深耕某一技术方向（如RTOS内核、DSP算法、芯片驱动），成为该领域不可替代的专家。

**代表人群**：华为2012实验室专家、地平线芯片驱动架构师、大疆飞控系统专家。

**适合你的点**：你的自研RTOS + TSN全协议栈 + DSP深度优化，天然适合走技术专家线。

#### 路径B：技术管理线（技术+管理复合）

```
嵌入式工程师（1-3年）
  → 技术骨干/Tech Lead（3-5年）
    → PL/项目经理（5-8年）
      → 研发经理/部门经理（8-12年）
        → 技术总监/CTO（12年+）
```

**特征**：技术扎实的前提下，逐步承担管理职责，最终负责整个研发团队或技术方向。

**代表人群**：小米IoT嵌入式负责人、字节硬件团队Lead、各类硬件创业公司CTO。

**适合你的点**：你已有PL管理经验（5人团队、培养3名骨干），这条路也走得通。

#### 路径C：行业专家线（行业深耕+技术）

```
嵌入式工程师 → 行业领域专家 → 行业解决方案架构师 → 行业技术VP
```

**特征**：不是泛嵌入式，而是深耕某一垂直行业（如汽车电子、工业控制、医疗设备），成为行业+技术双料专家。

**适合你的点**：工业嵌入式（电力仪表+TSN交换机）是你已有的行业积累。

#### 路径D：创业/合伙人线

```
技术积累（5-8年） → 加入创业公司做技术合伙人/CTO → 独立创业
```

**特征**：在技术成熟后，以技术合伙人身份加入早期创业公司，分享公司成长红利。

**适合你的点**：你表达过"野心比较大"——这条路值得考虑。

### 4.2 你的最佳路径分析

基于你的实际情况（~9年经验、自研RTOS、TSN、DSP、PL管理），**推荐路径**：

```
当前阶段：技术+管理复合（PL级）
  ↓
下一步（1-2年）：技术专家定位 + 管理加分
  ↓
中期（3-5年）：嵌入式架构师 / 研发经理
  ↓
长期（5-10年）：技术总监 / 行业专家 / 创业CTO
```

**核心判断**：
- 你的**S级能力**（自研RTOS、TSN、DSP）在国内嵌入式领域属于稀缺能力
- 你的**PL经验**是加分项，不是主菜——主菜永远是技术深度
- **端侧AI**是未来5年的增量方向，与你的底层驱动能力天然互补

## 五、个人发展定位

### 5.1 一句话定位

> **"国内稀缺的嵌入式底层技术专家——自研RTOS + TSN全协议栈 + DSP深度优化，PL交付能力加持，端侧AI前瞻布局"**

### 5.2 能力三层模型

```
         ┌─────────────────┐
         │   端侧AI/TFLM    │  ← 前瞻层（未来竞争力）
         │  AI编程提效      │
         ├─────────────────┤
         │  PL管理/IPD流程  │  ← 差异化层（区别于纯技术）
         │  工业协议全家桶   │
         ├─────────────────┤
         │  自研RTOS内核     │
         │  TSN全协议栈     │  ← 核心层（吃饭的家伙）

         │  AMP异构架构     │
```

### 5.3 发展原则

1. **核心层持续深耕**：RTOS/TSN/DSP/驱动是你的立身之本，不能丢
2. **差异化层适度维护**：PL经验保持，但不要成为主标签
3. **前瞻层持续投入**：端侧AI要保持学习，每周至少投入2-3小时
4. **不追求广度**：不碰消费电子、不碰Web/云、不碰自己不擅长的领域

### 记录 9 — 2026年08月03日：战略决策——做极致顶点，不分散补短板

**背景**：AI 助教分析了 2026 嵌入式AI 市场数据（猎头薪资/技术趋势/职业岗位），对标我的真实技能矩阵后，明确了我与"Linux BSP+AI双栈"热门路线的差距（Linux BSP 只会应用层、AUTOSAR 完全不会）。

**核心决策**：

> **不做"Linux BSP+AI双栈"的香饽饽，做"自研RTOS+TSN+端侧AI落地"这个细分里不可替代的顶点。**
>
> 能自己写RTOS、能调DSP、能部署TFLM、能解决Python↔C跨语言一致性问题的人，全国可能不到三位数——这个交叉点的稀缺性比补 Linux BSP 更高。

**为什么不做 Linux BSP/AUTOSAR（现阶段）**：
- Linux BSP：转型成本中等，但会分散精力，1-2个月后才能看到收益
- AUTOSAR：完全陌生领域，学习曲线陡峭，且只在车载方向有用——与我的工控/可穿戴主线偏离
- 目前已有的"RTOS底层+TSN+端侧AI"三叠组合，市场溢价30-50%，资深60-80W——天花板已经够高

**为什么"极致化当前技术栈"是对的**：
- 2026 可穿戴/工业AI两条赛道都是 MCU+RTOS 主场，不需要 Linux BSP
- 我的动作识别项目只需要产品化（四分类+实测性能+低功耗）就能成为MS核弹
- 端侧AI部署的"部署契约+Parity自检+5根因修复"是工程深度壁垒，比多会一个 Linux 驱动更稀缺

**Linux BSP 怎么补（后续慢慢来）**：
- 方向：用户空间驱动 + 设备树 + 简单字符驱动（不需要内核深度）
- 时机：当前主线（嵌入式AI课程+MS准备）完成后，每周投入2-3小时
- 目标：不是成为 Linux 内核专家，是能看懂 BSP 代码、能调设备树、能写简单驱动——够MS用即可

**行动清单（基于此决策更新）**：
- [ ] 嵌入式AI课程 Week3-4 完成（CNN训练+MNIST实战）
- [ ] 动作识别项目 P0 实测三数（推理延迟/内存/功耗）+ NPU 跑通或量化决策分析
- [ ] 动作识别项目产品化叙事（四分类扩展+低功耗方案+OOD检测）
- [ ] MS弹药库完成（RTOS全考点+启动流程+优先级反转+Tickless+项目11钩子+三连案例）
- [ ] 投递方向聚焦：可穿戴/工业AI/机器人嵌入式（不碰车载/纯Linux BSP岗位）

**反思**：这次决策的核心方法论——**"不做什么"比"做什么"更重要**。看到 Linux BSP 热门就想补，是 FOMO（害怕错过）；把自己的稀缺组合做到极端顶点，是长期主义。我的市场价值不在"会的多"，在"会的交叉点无人替代"。</ins>
