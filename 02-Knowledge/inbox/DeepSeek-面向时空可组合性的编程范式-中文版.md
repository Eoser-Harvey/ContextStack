## 摘要

现代软件——从插件系统到自演化智能体运行框架——日益需要动态组合，但相应的形式化基础仍不成熟。本文识别出该问题彼此正交的两个维度：时间可组合性，即移除组件时能够彻底撤销该组件产生的副作用；空间可组合性，即能够声明组件间依赖，并以反应式方式对其进行管理。

本文通过将经典的效应（effect）与协效应（coeffect）概念提升为运行时机制来处理这两个维度。具体而言，我们形式化了可逆效应：每一次上下文变换都携带一个逆变换，并由运行时对其进行追踪。我们还形式化了反应式协效应：上下文每次发生变化时，系统都会依据组件的协效应规约向该组件发出通知。

我们把效应上下文与协效应上下文统一为单一的上下文类型，由此构成一种编程范式。在此基础上，我们将上述机制组合进"组件"这一概念，并给出一套动态组合演算；其元理论把单个组件的时空可组合性推广到由多个交错执行组件构成的整个系统。

我们在 Cordis 中实现了这些思想。Cordis 是一个面向时空可组合性的元框架：其核心库提供效应追踪与协效应解析；其声明式组件加载器则提供配置协调与热模块替换能力。

## 1. 引言

组合——用更简单的部分组装复杂的系统——是软件工程的基本原则 [1]。传统上，组合是静态的：函数调用、模块导入和类继承在编译时解析，并在整个执行过程中保持固定。然而，现代软件越来越需要动态组合，其中组件在运行时上加载、卸载和重新配置。插件架构 [2] 和自演化智能体运行框架都要求系统能够安全地动态添加和删除功能，但当前的实践遵循粗粒度机制 [3]，仅通过重新启动、丢弃运行时状态来重新配置。尽管动态组合的实际重要性日益增长，但与静态组合可用的丰富形式化框架相比，其理论基础仍然不发达。

### 1.1. 可组合性的维度

为了描述动态组合的要求，我们在组合充分研究的代数方面之外确定了两个正交维度：

- **时间可组合性**解决了时间维度问题：移除组件后，必须完全且安全地撤消组件对共享环境所做的修改。这需要跟踪组件执行的每个资源分配、事件注册和状态变更，并保证它们的有序回收在移除时有效。
- **空间可组合性**解决空间维度：组件必须能够以结构化且可验证的方式声明、发现和解决它们之间的依赖关系。这需要管理依赖拓扑并协调组件生命周期以响应依赖项更改。

在静态设置中，时间可组合性减少为词法作用域（例如 RAII [4]、bracket 模式 [5]），空间可组合性减少为模块导入解析 [6]。在动态设置中，组件到达和离开运行时时，两个维度都变得更加困难：时间可组合性必须处理长期存在且有状态的效应，其范围不是受词法边界约束；空间可组合性必须处理执行期间出现、消失或更改身份的依赖项。

### 1.2. 动机示例

#### 1.2.1. 插件系统

插件系统是动态组合的典型实例。我们使用最广泛使用的可扩展 IDE 之一 Visual Studio Code (VSCode) 作为代表性示例。

**时间维度限制。** VSCode 在名为扩展宿主的共享进程中运行所有扩展。尽管可以动态安装扩展，但该主机不提供在运行时卸载单个扩展代码的机制。一旦执行了扩展的激活功能，禁用或卸载它需要重新启动整个主机，从而影响所有加载的扩展。纯声明性扩展（例如主题、键绑定和片段）不包含任何代码并可以自由删除。然而，在安装数量排名前 100 的扩展中，有 87 个包含可执行代码，因此在删除后需要重新启动。尽管 VSCode 提供了 deactivate 钩子，但它仅在主机进程终止期间充当正常关闭回调，因此无法启用实时删除。此外，该钩子将效应清理与效应创建（激活中）分开，违反了关注点局部性并使完整清理难以验证。

**空间维度限制。** VSCode 确实提供了 extensionDependencies 来声明扩展之间的依赖关系，但它的用途很少：在按安装数量排名前 100 的扩展中，只有 7 个在非内置扩展上声明了 extensionDependencies。这种稀缺性反映了扩展 API 的形状，它公开了固定的表层扩展点，例如命令、视图和语言功能。扩展通过这些点为主机做出贡献，而不是相互依赖，因此扩展之间的依赖关系很少出现。此外，VSCode 的扩展间交互机制不提供结构化契约：它通过 vscode.extensions.getExtension(...).exports 向其他人公开扩展的功能，但返回的值是无类型的（默认为任何类型），因此依赖方不能依赖于已检查的接口。简而言之，VSCode 将扩展引向一组固定的主机提供的扩展点，并且没有为它们提供相互依赖的安全、结构化的方式。

这两个限制并不是 VSCode 独有的。它们通常在插件系统中重复出现 [2, 7]，仅程度不同。

#### 1.2.2. 自演化智能体运行框架

现代 AI 智能体依赖于运行时智能体运行框架 [8-10]。这些系统可以组成不同的工具集 [11] 和执行环境，管理权限和沙箱，维护会话状态和持久性，提供上下文管理和内存系统 [12]，编排子智能体和多智能体工作流 [13]，并向用户和自动化公开接口。未来的运行框架可以在持续服务请求的同时生成并部署对其自己的组件的修改。模型合成的可复用工具为组件级自修改 [14] 提供了一种范围更窄的先导形式。每个此类修改本身就是动态组合的一个实例。

由于这些修改是连续发生的，并且在有限或没有人为监督的情况下，动态可组合性变得不可或缺。如果没有时间可组合性，则每次自我修改都会迫使系统整体重启，从而丢弃所有进程本地累积状态；在这样的频率下，累积不可用时间变得实质性，并且进行中的任务反复被破坏；更糟糕的是，有缺陷的自修改可以使执行恢复所需的进程失效。如果没有空间可组合性，每个模块必须自行检测并适应其所依赖的模块的变化（当它们出现、消失或改变身份时），并且只能通过临时手段来做到这一点；更糟糕的是，朴素的代码替换策略可能会默默地破坏依赖项或引入仅在重新加载时出现的循环依赖项。

#### 1.2.3. 粗粒度解决方法

动态可组合性受到有限正式关注的原因之一是操作系统和容器编排器已经提供了粗粒度替代品。操作系统在进程的粒度上产生时间可组合性；容器编排器 [3] 在服务粒度上产生空间可组合性。实际上，大多数软件通过遵循这些粗粒度机制来容忍细粒度可组合性的缺乏：通过重新启动进程来处理行为不当的模块，并且由容器编排器来管理服务依赖性。

然而，这种解决方法会带来巨大的成本。在时间维度上，每次重新启动都会丢弃所有进程本地累积状态（例如缓存、连接、部分计算），并且重建需要几秒到几分钟的时间 [15]；在此期间保持可用性需要冗余副本，从而产生资源开销，以弥补 recover 无法使用单个组件的情况。在空间维度上、容器级编排无法表达共享地址空间的组件之间的依赖关系，并且会引入可能是本地函数调用的交互的网络开销。这两种机制都在进程和容器的边界上运行，但现代系统越来越在更精细的层面上组合。该粒度失配需要一个组合抽象来管理效应和与组件本身相同级别的依赖项。

### 1.3. 贡献

动态可组合性的两个维度分别涉及计算如何修改以及它们如何依赖于环境。这两个方向是效应系统 [16, 17] 和协效应系统 [18, 19] 形式化的：效应提供形式化词汇用于推理对环境的修改，并提供协效应用于推理对环境的要求。然而，现有形式体系将推理限制为词法固定作用域上的编译时分析，并且不扩展到组件到达和离开运行时的动态场景。通过将效应提升为可逆的运行时模型，将协效应提升为反应式依赖解析机制，我们获得了动态可组合性的统一形式化基础，即语言无关，适用于任何需要动态组合的软件架构。我们做出以下贡献：

1. 我们形式化可逆效应（第3.1节）：每个上下文变换都带有运行时跟踪的显式逆，并且跟踪和恢复都保留组合，因此在组件删除时恢复上下文。这样就建立了局部时间可组合性。
2. 我们形式化反应式协效应（第 3.2 节）：组件将其所需的协效应声明为规约，并且上下文的每次更改都会针对规约通知组件作为激活、停用或中性。这样就建立了局部空间可组合性。
3. 我们将效应上下文和协效应上下文统一为单一上下文类型（第3.3节），其中协效应上的观察等价为效应提供独立性，构成时空可组合性的编程范式。
4. 我们给出了动态组合（第4节）的演算，它将两种机制结合到组件的概念中，并为其生命周期配备了操作语义。其元理论承载时空可组合性，从单个组件到交错执行的组件的整个系统。
5. 我们在 Cordis（第 5 节）中实现了这些想法，Cordis 是时空可组合性的元框架，它提供了一个核心库，通过效应追踪和协效应解析实现形式化模型，以及通过配置协调和热模块替换实现声明式组件加载器。

## 2. 预备知识

本节简要概述了效应系统与协效应系统——我们工作的两个理论支柱。我们假设熟悉基本类型论和范畴论；这里的目标是修复符号并引入第 3 节将作为运行时机制进行操作的关键抽象。

### 2.1. 效应

在简单类型的 lambda 演算 (STLC) [20, 21] 中，输入判断式 Γ ⊢ t: T 表明项 t 在上下文 Γ 下具有类型 T。效应系统细化类型以描述计算可能产生的副作用，产生以下形式的判断：

Γ ⊢ t : T | 效应

在这里，结果类型用效应代数的元素进行注释，该元素描述计算可能产生哪个副作用，从而实现有关状态计算的组合推理。这种方法起源于 Lucassen 和 Gifford [22]，他们引入了一种区分类型、效应和区域的类型系统，以发现并行程序中的调度约束。

**Monadic 效应。** Moggi [16] 首先通过 monad 明确地建模了计算效应；Wadler [23] 在 Haskell 中推广了该方法。类别 c 上的单子 (T, η, μ) 将有效的计算封装为 T(A) 类型的值，其中 η: A → T(A) 提升纯值，μ: T(T(A)) → T(A) 对嵌套计算进行排序。经典实例包括 Maybe monad（用于偏爱）、State monad（用于可变状态）和 IO monad（用于外部交互）。

**代数效应。** Plotkin 和 Power [17, 24] 表明代数运算决定 monad，建立了一个框架，其中效应接口与其实现解耦。效应签名 Σ 声明一组操作（例如，get: () → S，put: S → () 表示状态）；程序自由调用操作，无需遵守特定的解释。Plotkin 和 Pretnar [25] 随后引入了效应处理程序，它通过提供延续语义来解释操作：

使用 { op(v, κ) ↦ ... } 处理 e

处理程序接收操作参数 v 和分隔延续 κ，它可以调用零次、一次或多次，从而在统一框架内启用异常、协程和非确定性 [26]。Koka [27, 28]、Eff [29] 和 OCaml 5 [30] 等语言采用了代数效应，并进行了不同的设计权衡。

### 2.2. 协效应

与效应一样，协效应系统 [18, 31] 丰富了上下文而不是类型，产生了形式的判断：

Γ | 协效应 ⊢ t : T

这里，上下文用协效应代数的元素进行注释，描述计算需要从其环境中获得什么，例如要访问的资源、持有的权限、或依赖的服务。效应模拟了程序对世界的影响，而协效应则模拟了世界对程序的限制。

**Comonadic 协效应。** 使用 comonads 构建上下文依赖方计算的想法首先由 Uustalu 和 Vene 提出 [32]，他们提出对称（半）monoidal comonads 作为效应 Moggi 的 monadic 框架的对偶，捕捉数据流和属性评估等概念。佩特里克等人 [18] 在此基础上提出协效应作为上下文依赖的统一静态分析。comonad (D, ε, δ) 捕获上下文依赖方计算：ε: D(A) → A 从上下文中提取当前值，并且 δ: D(A) → D(D(A)) 复制上下文以进行嵌套访问。环境 comonad D(X) = E × X 模型对固定环境 E 的依赖；Stream comonad D(X) = N → X 模型对时间数据的依赖。

**分级协效应。** 对于更细粒度的跟踪，分级协效应系统使用预先排序的半环 S = (S, ≤, +, ×, 0, 1) 作为协效应代数 [33]，这一学科后来由 Gaboardi 等人与分级效应统一 [19]。S 的元素注释每个变量绑定以量化其使用情况：0 表示未使用，1 表示线性使用，n 表示有界使用，∞ 表示无限制使用。半环运算顺序（×）和并行（+）组成协效应，在统一的代数框架 [37] 内实现精确的资源跟踪、敏感性分析 [34] 和信息流控制 [35, 36]。

### 2.3. 与动态可组合性的关系

效应系统与协效应系统沿着两个互补的方向组织有关计算的推理：效应描述计算如何修改其环境，而协效应描述计算如何依赖于其环境。这两个方向对应于第 1 节中确定的动态可组合性的两个维度：

- **时间可组合性**要求组件对共享环境的修改在卸载时可恢复。相关的效应是有状态的，可以持久地改变该环境；撤销这样的变换需要它承认逆。
- **空间可组合性**要求响应式地声明和管理组件间依赖。这些依赖关系正是协效应捕获的东西，管理它们相当于根据环境提供的内容解决每个依赖关系。

然而，经典的效应系统与协效应系统是静态仪器：效应在词法固定作用域内跟踪并由编译时处理程序释放；协效应注释根据执行前确定的上下文进行验证。相比之下，动态组合要求这些保证适用于到达和离开运行时的组件，以应对不断发展的上下文。没有固定的词法范围可以界定部署后加载的插件；没有编译时上下文可以预见运行时配置中出现的依赖关系。

这引发了视角的转变：我们不是用更多注释来扩展静态类型系统，而是具体化了效应和协效应的概念结构，以便运行时可以直接对它们进行操作，动态地建立这些系统静态提供的保证。

## 3. 可逆效应和反应式协效应

本节将第2节中介绍的效应和协效应的概念提升到运行时机制，构建动态组合的理论。中心思想是将携带效应和协效应的类型上下文转换为上下文类型，即运行时可操作类型，将上下文具体化为一等实体。对于效应类型，我们将其建模为与逆元配对的上下文变换，实现局部时间可组合性。对于协效应上下文，我们将其建模为携带依赖信息的类型，实现局部空间可组合性。协效应上的观察等价可为效应提供独立性。承载效应和协效应的统一上下文本身构成了编程范式。

### 3.1. 可逆效应

时间可组合性能够在运行时处加载和卸载组件，以便在卸载时，共享环境恢复到组合之前的状态。这要求组件对环境所做的每次修改都是可跟踪和可恢复的。因此，我们将效应建模为类型 Γ → Γ × (Γ → Γ) 的函数：应用于当前上下文，它会生成修改后的上下文以及显式逆函数。提供该逆值可以使效应恢复，而将其返回到运行时则可以使效应可跟踪。我们称这种效应为可逆的：通过在执行过程中跟踪和组合这些逆过程，完整的环境恢复成为结构性保证。

#### 3.1.1. 效应上下文

给定任何非纯函数 f: X → Y，我们将其转换为纯形式 f: Γ × X → Γ × Y，其中 Γ 是上下文，所有可能的副作用都可以表示为 Γ 上的变换。对于任何固定输入 x: X，诱导映射 γ ↦ pr₁(f(γ, x)) 捕获 f 的副作用，与返回值无关。因此 Γ 上的效应存在于变换 Γ → Γ 下的组合。的幺半群中，其中每个幺半群公理都可以直接读取为效应的属性：

- **闭包**：两个效应的连续组合又是一个效应
- **关联性**：复合效应与它的括号方式无关
- **恒等式**：id，Γ 上的恒等函数，充当组合的单位元

为了对可撤销的效应进行建模，我们将每个变换 f 与另一个撤销 f 的变换 g 配对，并将 g 称为 f 的左逆，在整个论文中缩写为逆。撤销是单方面的：逆元所坚持的是 g ∘ f，而不是 f ∘ g。成对的变换带有它们自己的乘法。

## 8. 结论

本文识别了动态组合的两个正交维度——时间可组合性和空间可组合性，并通过将效应和协效应提升为运行时机制来形式化地处理这两个维度。可逆效应保证了组件卸载时的环境恢复；反应式协效应保证了依赖关系的动态管理。统一上下文类型构成了一种编程范式，动态组合演算的元理论将时空可组合性从单个组件推广到整个系统。Cordis 实现验证了这些思想的可行性。
