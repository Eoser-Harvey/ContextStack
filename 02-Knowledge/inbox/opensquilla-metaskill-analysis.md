## 1. 核心概念：MetaSkill 是什么

### 一句话定义

MetaSkill 是一份**「元 markdown」**，它不定义具体业务逻辑，只定义：
- 如何检索可用的原子 Skill
- 如何筛选合适的 Skill
- 如何按依赖关系组合它们

### 关键设计原则

| 原则 | 说明 |
|------|------|
| **无硬编码业务逻辑** | MetaSkill 里只有步骤声明、依赖关系、输入输出映射 |
| **原子 Skill 下沉** | 真正的「怎么做」全部下沉到原子 Skill |
| **自发现** | 社区有新 Skill 出现时，自动纳入可选范围 |
| **自替换** | 更好的 Skill 出现时，自动评估替换 |

### 解决的问题：「组合灾难」

> 当 Skill 数量从几十个涨到几百个甚至上千个时，你知道哪几个能组合起来解决当前问题吗？

- 传统方式：人工翻文档、试组合、调参数
- MetaSkill 方式：自然语言描述目标，Agent 自动检索→筛选→组合→执行

## 2. 实际案例：公众号转小红书

### 用户输入

> 帮我把这篇公众号文章转成小红书图文，风格要种草感强一点。

### OpenSquilla 的自动编排

```
用户输入
    ↓
OpenSquilla 检索可用 Skill
    ↓
发现三个原子 Skill：
  1. wechat-article-extractor（解析公众号文章）
  2. xiaohongshu-text-skill（生成小红书文案）
  3. xiaohongshu-cover-generator（生成小红书封面图）
    ↓
自动构建 DAG 工作流：
  解析 → 改写 → 出图
    ↓
40 秒完成全流程
```

### 产出质量

- 标题带 emoji
- 文案分段短、有网感
- 封面图风格符合小红书审美
- **工作流不是提前写好的，是现场组出来的**

## 3. MetaSkill 协议的设计

### 元 Skill 的结构

MetaSkill 只包含：
1. **步骤声明** — 需要哪些步骤
2. **依赖关系** — 步骤之间的先后/并行关系
3. **输入输出映射** — 步骤间的数据流转

不包含：
- 具体怎么解析公众号
- 具体怎么改写文案
- 具体怎么生成封面

### 带来的核心优势

| 优势 | 说明 |
|------|------|
| **动态适配** | 新 Skill 出现自动纳入，无需修改工作流 |
| **自动替换** | 更好的 Skill 自动评估替换 |
| **降低心智负担** | 用户无需记住每个 Skill 的能力边界 |
| **自然语言驱动** | 一句话描述目标即可 |

## 4. 与传统工作流的对比

| 维度 | 传统工作流 | MetaSkill |
|------|-----------|-----------|
| **编排方式** | 硬编码脚本 / 人工拖拽节点图 | 自然语言描述 + Agent 自动组合 |
| **Skill 更新** | 脚本可能失效，需人工修改 | 自动发现新 Skill，自动评估替换 |
| **依赖管理** | 写在人脑子里或硬编码 | Agent 自动判断输入输出匹配 |
| **扩展性** | 新增 Skill 需改流程 | 新增 Skill 自动纳入可选池 |
| **专家依赖** | 需要知道先调 A 再调 B | 不需要记住 Skill 边界 |

## 5. OpenSquilla 的产品演进

| 版本 | 核心能力 |
|------|---------|
| **1.0** | 智能路由 — 简单任务用便宜模型，复杂任务用好模型，缓存命中直接复用 |
| **3.0** | MetaSkill — 工作流编排也自动化，Agent 自组织技能 |

### 智能路由示例

- DeepSeek-v4-flash：简单任务
- DeepSeek-v4-pro：复杂任务（自动移交）

### 产品主线

> **Agent 的下一轮效率红利，可能不来自模型升级，而来自 Harness 层优化。**
>
> 把优化前置到 Skill 组合层，比让 Agent 在线反复 trial-and-error 有效得多。

## 6. 对 ContextStack 的借鉴价值

### 6.1 直接可借鉴的模式

| MetaSkill 设计 | ContextStack 应用场景 | 优先级 |
|---------------|----------------------|--------|
| **Skill 自发现** | 自动发现框架内可用的 Skill，无需手动维护清单 | 高 |
| **动态工作流编排** | 根据任务自动组合 Skill，而非预设固定流程 | 高 |
| **输入输出映射** | Skill 间的数据流转标准化 | 中 |
| **智能路由** | 简单任务用轻量模型，复杂任务用好模型 | 中 |
| **缓存复用** | 相同输入直接复用结果，降低 token 成本 | 中 |

### 6.2 与现有项目的结合

**wechat-radar 项目**：
- 当前：固定流程抓取→解析→生成日报
- 可改进：用 MetaSkill 思路，自动发现「更好的抓取器」「更好的摘要生成器」

**family-investment 项目**：
- 当前：手动整理投资数据
- 可改进：自动发现数据获取 Skill → 分析 Skill → 报告生成 Skill

### 6.3 对框架设计的启发

ContextStack 目前的 Skill 管理是**静态的**（手动放入 skills/ 目录）。

可借鉴 MetaSkill 的**动态发现**机制：
1. Skill 注册表 — 每个 Skill 声明自己的能力、输入、输出
2. 任务解析器 — 将自然语言任务拆解为子任务
3. Skill 匹配器 — 自动匹配可用的 Skill 组合
4. 执行引擎 — 按 DAG 执行并处理依赖

## 7. 与 ARS 的对比

| 维度 | ARS (学术研究) | OpenSquilla (技能编排) |
|------|---------------|----------------------|
| **核心问题** | 如何保证 AI 辅助学术工作的质量 | 如何让 Agent 自动发现和组合技能 |
| **解决方式** | 完整性门 + 引用验证 + 反讨好 | MetaSkill 协议 + 智能路由 |
| **Agent 数量** | 32+ 专用 Agent | 动态组合，数量不固定 |
| **工作流** | 10 阶段固定管线 | 动态编排，现场组合 |
| **人机协作** | Human-in-the-loop，检查点确认 | 一句话驱动，全自动执行 |
| **适用场景** | 高质量、需验证的学术产出 | 快速、自动化的任务执行 |

### 互补性

- **ARS** 解决的是「质量」问题 — 如何保证产出正确
- **OpenSquilla** 解决的是「效率」问题 — 如何快速组合技能完成任务

两者结合 = **高质量 + 高效率**：用 MetaSkill 快速组合工作流，用 ARS 的完整性门保证产出质量。

## 8. 核心判断

### 关键洞察

1. **「让 Agent 学会自己造工具，比给 Agent 造更多工具，重要得多」**

2. **Agent 的下一轮效率红利来自 Harness 层优化，不是模型升级**

3. **MetaSkill 的本质是「组织技能的协议」，不是另一个工作流引擎**

4. **动态发现 + 自动替换 = 真正的「自进化」**

### 一句话总结

> OpenSquilla 的 MetaSkill 让 Agent 从「被编排」走向「自组织」——不是提前写好流程图，而是让 Agent 像人一样：遇到新问题 → 检索能力 → 组织方案 → 执行交付。这对 ContextStack 最大的启发是：**Skill 管理应该从静态目录走向动态发现**。
