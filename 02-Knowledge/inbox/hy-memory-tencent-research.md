## 项目概述

**Hy-Memory** 是腾讯混元推出的**长期记忆框架**，专为 OpenClaw 等长期协作型 Agent 设计，定位为 Agent 的"第二大脑"。

### 核心定位
> "把用户的长期偏好、事实、画像和意图沉淀成一份可共享的记忆资产。"

---

## 核心架构：六层记忆 × 双路径

### 六层记忆结构（L1-L6）

| 层级 | 名称 | 说明 | 写入时机 |
|------|------|------|---------|
| **L1** | 原始痕迹 | 保留对话、行为和上下文 | System1 实时 |
| **L2** | 原子事实 | 零散表达抽成可检索、可更新、可合并的事实片段 | System1 实时 |
| **L3** | 身份画像 | 稳定的长期偏好、特质和人设画像 | System1 实时 |
| **L4** | 会话摘要 | 压缩长会话为精华 | System1 实时 |
| **L5** | 心智模型 | 从行为里抽出认知框架 | System2 异步 |
| **L6** | 前瞻意图 | 异步沉淀的下一步意图预测 | System2 异步 |

### 双路径处理

| 路径 | 速度 | 职责 | 触碰层 |
|------|------|------|--------|
| **System1** 在线快路径 | ms 级 | 实时写入 L1-L4 | 原始痕迹→事实→画像→摘要 |
| **System2** 后台慢整理 | 秒到分钟级 | 异步沉淀 L5-L6 | 心智模型→前瞻意图 |

## 核心创新：记忆演化链

### 问题：普通记忆系统越用越乱
- 同类事实反复堆叠
- 新旧偏好并存
- 向量搜索召不回中间环节

### 解决方案：supersedes 演化链
- 写入时用 `supersedes` 指针把记忆串成因果链
- 命中链上任意一条，整条"态度演变"自动跟出
- 旧记忆被抽取、合并、更新、沉淀，越用越接近"干净的用户理解"

### 记忆演化5步
```
L1 原始对话 → L2 事实抽取 → L2 合并去重 → L5 冲突处理 → L3 画像沉淀
```

**关键**: 同一段记忆被反复重写，而不是无限往后堆。

## 评测成绩

| 评测 | Hy-Memory | mem0 | Graphiti | 某云平台 |
|------|-----------|------|----------|---------|
| **LongMemEval** (6题型) | **85.20%** ✅ | 47.00% | 68.32% | 未测 |
| **PersonaMem** (7题型) | **76.91%** ✅ | 65.82% | 64.86% | 52.09% |
| **题型逐项** | **13/13 全胜** | — | — | — |
| **写入速度** | **12.3 s/k tokens** ✅ | 15.6 | 97.8 | 5.36 |
| **记忆条数** | **82.3条** ✅ (最精炼) | 309.8 | 362.3 | 51.4 |
| **信息密度** | **130.5 token/条** ✅ | 52 | 89.2 | ~104 |

### 核心优势
- **少**: 用 1/4 的记忆量达成更高准确率
- **精**: 单条信息密度是 mem0 的 2.5 倍
- **快**: 写入速度是 Graphiti 的 8 倍

|------|------|------|---------|

## ContextStack 可借鉴点

### 1. 六层记忆结构 → Memory 层分级设计
- **Hy-Memory**: L1原始→L2事实→L3画像→L4摘要→L5心智→L6意图
- **ContextStack 现状**: Memory 只有 User/Feedback/Project/Reference 四类
- **借鉴**: 把 Memory 分为原始记录层 + 提炼事实层 + 稳定画像层

### 2. 记忆演化链 → 经验去重与合并
- **Hy-Memory**: supersedes 指针串成因果链，旧记忆被重写而非堆积
- **ContextStack 现状**: Feedback 记录只增不减
- **借鉴**: 定期合并同类 Feedback，保留最新结论

### 3. 双路径处理 → 同步写入 + 异步整理
- **Hy-Memory**: System1 实时写入 + System2 后台整理
- **ContextStack 现状**: 只有同步处理
- **借鉴**: 对话中快速记录，对话后异步整理沉淀

### 4. 冲突处理 → 偏好更新机制
- **Hy-Memory**: 新旧偏好冲突时，旧的淡化，新的固化
- **ContextStack 现状**: 无冲突处理
- **借鉴**: 用户纠正时，标记旧结论为"已过期"

### 5. 会话摘要 → L4 自动压缩
- **Hy-Memory**: 每次会话自动生成摘要
- **ContextStack 现状**: 刚设计的 session 经验沉淀（类似 L4）
- **借鉴**: 已在 P0 落地，方向正确
