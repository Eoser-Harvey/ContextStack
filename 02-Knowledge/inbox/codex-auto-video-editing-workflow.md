## 一、背景与核心逻辑

### 1.1 问题定义

**传统混剪痛点**：手动在剪映逐帧对照参考视频 → 找素材 → 卡时间 → 配字幕，一条视频 **2-3小时**，日均上限约6条。

**自动化方案**：参考视频 + 自有素材库 → Codex自动镜头识别 → 素材匹配 → 配音生成 → 剪映草稿输出，**单条几分钟**，日均30条，效率提升 **≥5倍**。

### 1.2 核心理念："抄爆款"不等同于搬运

| 概念 | 含义 |
|------|------|
| 抄爆款 | 沿用已验证的视频结构（节奏、景别切换、文字密度），用自己的素材替换 |
| 搬运 | 直接复制他人内容（侵权+平台限流） |
| 关键差异 | 结构可复用，内容必须原创 |

### 1.3 适用与不适用场景

| ✅ 适用 | ❌ 不适用 |
|---------|----------|
| 电商带货混剪 | 高度原创精品创作 |
| 营销推广视频 | 精细镜头语言需求 |
| 混剪Vlog | 复杂转场与情绪表达 |
| 多段素材拼接类 | 强叙事/强情感线 |

## 二、环境与准备

### 2.1 工具链

| 工具 | 角色 | 备注 |
|------|------|------|
| **Codex** | AI自动化平台，流程引擎 | 需先阅读作者入门文章 |
| **FFmpeg** | 视频拆分/合成/格式转换 | 必须安装 |
| **Python 3.8+** | 脚本语言 | 流程代码载体 |

| **VoxCPM** | 配音备选 | 免费开源声音克隆 |
| **剪映专业版** | 最终编辑/微调 | 打开生成的草稿 |

> 💡 一条 Codex 提示词即可检查全部环境：让 Codex 逐项检测并安装缺失项。

### 2.2 项目目录结构

```
项目文件夹/
├── assets/          ← 素材库（按外观/功能/场景 或 AI生成/实拍 分类）
├── work/            ← 工作区，按日期建子目录（如 2026-07-28/）
│   ├── 参考视频.mp4
│   ├── recipe.json          ← 步骤1产出
│   ├── fragment_plan.json   ← 步骤2产出
│   ├── matches.json         ← 步骤2产出
│   └── 最终草稿/
└── AGENTS.md        ← 项目配置文件（Codex依赖此文件理解需求）
```

### 2.3 AGENTS.md —— 关键配置文件

## 三、四步工作流

### 步骤1：拆解参考视频

| 项目 | 说明 |
|------|------|
| 输入 | 参考视频 → `work/日期/` |
| 操作 | 发送拆解提示词给 Codex |
| 产出 | `recipe.json`（镜头序列、时间戳、景别、OCR/ASR文案） + 小视频片段 + 关键帧截图 |
| 验证 | 检查镜头切分是否合理（多数自动识别可用） |

`recipe.json` 是整个后续流程的唯一事实源（Single Source of Truth）。

### 步骤2：筛选和匹配素材（最关键环节）

**传统痛点**：手动遍历素材库——逐镜头翻找、遗忘更优备选、极易漏配。

**自动化匹配原理**：
1. Codex 读取 recipe.json 每个镜头的关键帧
2. 遍历 assets/ 提取素材关键帧
3. 计算颜色、亮度、构图等视觉特征相似度
4. 返回匹配得分排序 + 推荐

**匹配约束规则（避坑实战）**：

| 规则 | 目的 |
|------|------|
| 禁止连续使用同一素材 | 避免机械重复感 |
| 强制景别变化 | 远景→近景→特写交替 |
| 置信度阈值 | 低于阈值自动标记"缺素材"，宁缺毋滥 |
| 复制而非移动素材 | 保护原始素材库完整性 |

**产出文件**：
- `fragment_plan.json`：每个镜头的需求描述（场景/动作/景别/避用素材）
- `matches.json`：匹配结果（素材路径/置信度/是否降级匹配）

> ⚠️ **黄金原则**：宁可标记"缺素材"留人工补充，也不硬凑无关素材。一旦素材质量崩塌，视频观感直线下降。

### 步骤3：生成配音

| 步骤 | 说明 |
|------|------|
| 1 | 检查步骤1 OCR/ASR 提取的文案准确性 |
| 2 | 发送配音提示词给 Codex |
| 3 | Codex 读取每个语音文件实际时长，自动调整镜头长度（5秒配音→5秒镜头，全覆盖3秒参考镜头） |
| 4 | 人工试听确认自然度和语速 |

> 音画对齐是自动化实现：Codex 根据实际音频时长反推视频节奏，而非死板复制参考视频时间戳。

### 步骤4：生成剪映草稿（最复杂）

**难点**：剪映草稿格式严格——素材绝对路径、时间轴嵌套、元数据ID、根索引ID 必须完全准确且不重复。

**关键坑点与对策**：

| 坑 | 对策 |
|----|------|
| ID 冲突 | 确保内容ID / 元数据ID / 根索引ID 三者一致且不与已有草稿重复 |
| 素材路径失效 | 使用绝对路径，且素材在生成前不能移动 |
| 首次生成慢 | 正常现象（约十几分钟），后续可封装 Skill 加速 |

**验收清单**（生成后在剪映中逐项检查）：
1. 草稿能否正常打开？
2. 素材是否全部显示无缺失？
3. 时间轴时长、顺序是否与参考一致？
4. 字幕是否遮挡关键画面内容？
5. 配音与画面是否同步？

## 四、效率总结与进阶

| 阶段 | 耗时 |
|------|------|
| 完整流程（首次） | 20-30分钟/条 |
| 素材库已备好 | 可低至 5分钟/条 |
| 传统手动 | 2-3小时/条 |
| **提效比** | **12-36倍** |

> 💡 流程跑通后，对 Codex 说"帮我把工作流封装成 Skill"，后续调用 Skill 即可，无需重复复杂步骤。

作者两个多月内迭代了至少 10 个版本。
